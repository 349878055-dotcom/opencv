# 眼眉/耳指令集 · 定义说明书

> **本文件是整个系统的唯一固定件。**
> **客户提示词可以千变万化（东方不败喝酒、贵宾犬被打），但本指令集的 12 通道协议永远不变。**

---

## 一、指令集是什么

**12 个标准化通道 × 150 帧（5 秒@30fps）的时间序列。**

每个通道值域 `[0.0, 1.0]`，描述一个独立的物理运动维度。

| 通道 | 人类语义 | 动物语义 |
|------|---------|---------|
| pupil_x | 视线左右 | 瞳孔注视方向 |
| pupil_y | 视线上下 | 瞳孔注视方向 |
| blink | 眼睑开合 | 眼睑开合 |
| **eyebrow** | **眉压** | **耳位（耷拉/竖立）** |
| pupil_scale | 瞳孔缩放 | 瞳孔缩放（情绪浓度） |
| iris_scale | 虹膜覆盖度 | 同人 |
| cornea_bulge | 角膜鼓起 | 眼神有神度 |
| squint | 眯眼眶压 | 同人 |
| **brow_raise** | **挑眉** | **耳尖微动/眉脊** |
| lid_upper | 上眼睑 | 上眼睑 |
| lid_lower | 下眼睑 | 下眼睑 |
| eye_gloss | 眼湿润高光 | 泪眼汪汪程度 |

此 12 通道协议**对所有人/猫/狗固定不变**。物种差异在 **PAD 权重、compile 规则、S5 人格/品种 base/scale**，**不改 E(t) 四段时间轴**。

---

## 二、OpenCV 输出什么

指令集经过渲染管线，输出 **工程底膜帧序列**：

```
12 通道 × 150 帧
       │
       ▼ 物种渲染器（AffineRenderer / CatAffineRenderer / DogAffineRenderer）
       │
       ▼
150 张 PNG，每张 690×361，RGB 三色分离：
  R = 眼眶轮廓（闭合路径）
  G = 眉脊线 / 耳廓线（物种自适应）
  B = 虹膜 + 瞳孔（实心区域）
```

OpenCV 不"画人脸"，OpenCV 画的是 **三色几何控制图**：
- 红色 = 眼眶该在的位置
- 绿色 = 耳朵/眉毛该在的位置
- 蓝色 = 瞳孔该在的位置

这些图喂给扩散引擎后，扩散引擎在**对应的像素位置**生成真实画面。

## 三、指令集永远固定，视频却千变万化

### 固定的：12 通道协议 + 编译管线

无论客户提什么需求，**12 通道名与 150 帧长度**不变；编译顺序为：

```text
情绪 JSON → E(t) → pulse(12×150) → styled(12×150) → 02 烘焙 → OpenCV 底膜
              ↑仅滑杆              ↑PAD+物种      ↑人格/品种(S5)
```

代码入口：[`run_species_delivery()`](../../gaze_engine/delivery_pipeline.py) · [`style_compose.py`](../../gaze_engine/_shared/style_compose.py)

⚠️ **人格/品种不改 E(t)**。同情绪 JSON，换人格只变 styled，不变主钟。

### 变化的：客户提示词 + 参考图

| 场景 | 参考图 | 客户提示词 | 指令集 |
|------|:-----:|-----------|:------:|
| 东方不败喝酒 | 林青霞照片 | "古装、喝酒、眼神迷离" | 同一套 |
| 贵宾犬委屈 | 狗照片 | "被打、耳朵耷拉、眼泪" | 同一套 |
| 猫被吓到 | 猫照片 | "飞机耳、瞳孔炸开" | 同一套 |

**指令集之于视频 = 乐谱之于演奏：**

```
乐谱（指令集）固定          演奏者（Wan）可变
    ↓                            ↓
同一首《小星星》          钢琴版 / 吉他版 / 交响版
同一套委屈指令集          东方不败演 / 贵宾犬演 / 布偶猫演
```

### 指令集在镜头中的应用

指令集的 12 通道节奏**贯穿全片，不依赖景别**：

```
帧 0   17   32         86          149
│      │    │          │            │
▶扫视   ▶压眉 ▶盯住    ▶轻眨释放    ▶收尾
│      │    │          │            │
├特写   ├中景 ├切碗    ├全景低头    ├特写结束
│瞳孔   │耳耷 │空镜     │全身蜷缩    │闭眼
```

- 帧 17 是特写 → 底膜直接驱动眼球扫视
- 帧 32 切到中景 → 底膜不可见，但**节奏不变**，头颈跟随
- 帧 55 切到碗的空镜 → 无面部，但**剪接点对齐脉冲拐点**
- 帧 86 全景低头 → 无面部，但蜷缩动作对齐 blink 的释放感

**没有面部的镜头，节奏依然在工作。**

## 四、节奏说明书（Rhythm Specification）

## 4.1 节奏说明书是什么

**节奏说明书** 是 12 通道指令集面向扩散引擎（Wan）的**人类可读解读版**。

```
指令集（机器数字）→ 节奏说明书（语义解读）→ 扩散引擎（视频生成）
    12×150 浮点数       每通道一句"节拍：xxx"       Wan
```

**它不改变指令集的任何数值，只为每个通道的脉冲曲线配上自然语言说明。**

## 4.2 节奏说明书长什么样

```
## 各通道脉冲
- **blink**（眼睑开合）: t0=0.0, t45=0.3, t83=0.0, t110=1.0, t149=0.0
  - 节拍：眼睑脉冲；唇颊放松/微收节奏
- **eyebrow**（耳位）: t0=0.7, t30=0.3, t55=0.1, t100=0.0, t149=0.2
  - 节拍：耳位下垂程度；对应狗耳朵耷拉节奏
```

每个通道一行 `t=xxx v=xxx` 关键帧，加一行 `→ 节拍：` 说明这个通道的脉冲对画面意味着什么。

## 4.3 为什么需要节奏说明书

扩散引擎（Wan）不看 JSON 数字，它读 **自然语言 Prompt**。

- 数字 `eyebrow: t0=0.7, t30=0.3` 对 Wan 没有意义
- 加上 `→ 节拍：耳位下垂程度；对应狗耳朵耷拉节奏` 之后，Wan 才明白：**哦，这个值从 0.7 降到 0.3 意味着耳朵在 30 帧内从竖立变耷拉**

## 4.4 节奏说明书由谁生成

由 `gaze_engine/_shared/export_diffusion_metronome.py` 自动生成。

输入：`02_烘焙_真人律.json`（12 通道 × 150 帧烘焙定稿）
输出：`05_扩散节拍表.txt`（完整的节奏说明书文本）

每个通道的节拍说明来自 `channel_contract.py` 中的 `DIFFUSION_HINTS` 字典，物种自适应。

## 五、一句话总结

> **12 通道指令集是固定协议 → OpenCV 输出工程底膜 → 扩散引擎结合客户提示词与参考图 → 生成千变万化的视频。**
>
> **镜头可以切到任何角度、任何景别、甚至没有脸——但指令集的节奏一秒都不停。**
>
> **节奏说明书是连接机器数字与人类语义的桥梁，让 Wan 理解每个通道的脉冲意味着什么。**
