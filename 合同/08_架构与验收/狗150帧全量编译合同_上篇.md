## 一、概述（What）

### 1.1 最终产物是什么

门户勾选 **狗情绪** + **狗品种** 后，动态层要落盘的是：

```text
02_烘焙.channel_tracks[ch].keyframes[t].v
  ch ∈ 12 通道，t ∈ 0…149
  → 共 12 × 150 = 1800 个 float（每帧 clamp 在 [0,1]）
```

### 1.2 中间要经过几条「150 帧」

| 代号 | 名字 | 形状 | 谁决定 |
|------|------|------|--------|
| **E(t)** | 能量主钟 | **150 × 1** | 仅狗情绪滑杆 |
| **pulse** | 纯情绪 12 轨 | **12 × 150** | 情绪 + PAD + 狗编译规则 |
| **styled** | 叠品种后 12 轨 | **12 × 150** | pulse + 品种 base/scale |
| **final** | 先验/质检后 | **12 × 150** | styled + prior + QC |

**品种不参与 E(t)**；PAD **不参与 E(t)**，只参与 pulse 的通道分配。

### 1.3 12 通道名单（固定顺序）

`pupil_x` · `pupil_y` · `blink` · `eyebrow` · `pupil_scale` · `iris_scale` ·  
`cornea_bulge` · `squint` · `brow_raise` · `lid_upper` · `lid_lower` · `eye_gloss`

代码真源：[`gaze_engine/dog/envelope_compile.py`](../../gaze_engine/dog/envelope_compile.py) → `DOG_CHANNELS`

## 二、理论依据（Theory）

### 2.1 为什么要分 E(t) → pulse → styled

```
① 一条主钟 E(t) 保证「起—盯—收」时间轴全品种一致
② PAD 把「这种戏」映射到 12 通道比例（10 种情绪各一组常数）
③ 品种只在 pulse 上乘加偏置，改脸不改戏的节奏
```

### 2.2 帧轴与四段（全项目统一 150 帧 @ 30fps ≈ 5s）

由 `_timing(macro)` 从滑杆推出关键帧号（**因情绪而异**，不是死 25/90）：

| 符号 | 含义 |
|------|------|
| `t_peak` | 蓄力结束 / 启动顶点 |
| `t_settle` | 启动段结束 |
| `t_hold0` | 保持段开始 |
| `t_hold1` | 保持段结束 / 缓和开始 |
| `t=149` | 最后一帧，E(t) 应收至 0 或合同允差 |

四段语义：**蓄力 → 启动 → 保持 → 缓和**（见 [`全量帧指令集规范.md`](../04_通道与先验/全量帧指令集规范.md)）。

### 2.3 S4 vs S5 对照（核心易混点）

**S4 pulse** = 「这条情绪怎么演」 · **S5 styled** = 「这只狗什么脸」

```text
                    S4 pulse（情绪层）              S5 styled（品种层）
                    ─────────────────              ───────────────────
输入                E(t) + PAD + 编译规则          pulse + style.json
时间轴              跟 E(t) 走                     跟 pulse 走（每帧线性叠）
品种                ❌ 不参与                      ✅ base_offset + scale_factor
典型公式            pulse = E×scale×gain           styled = base + scale×pulse
表演力来源          blink锚点、tremble、湿眼…      半阖基线、动态幅度缩放
改错了会怎样        戏不像、木偶、死眼              脸不像品种、clip 顶死
```

#### 对照图（同一帧 t 的数值关系）

```text
         S2                S3              S4                    S5
      E[t]（1个数）    scale[ch]（12个）   pulse[ch,t]         styled[ch,t]
         │                 │                  │                      │
         │    ×────────────┘                  │                      │
         └──────────────→ E×scale×gain ──────→│                      │
                                              │   base[ch]           │
                                              │ + sf[ch]×pulse ─────→│
                                              │                      ↓
                                         （无品种）              （门户最终动态）
```

#### 数值例子（示意，非定稿）

假设 `t=50`，`E[50]=0.36`，`scale[blink]=0.48`，贵宾 `base=0.55, sf=0.25`：

```text
pulse[blink,50]  = clamp(0.36 × 0.48 × gain) ≈ 0.17   ← 情绪驱动的眨动
styled[blink,50] = clamp(0.55 + 0.25 × 0.17) ≈ 0.59   ← 叠加「天生半阖」
```

若只调 S5 把 `base[blink]` 从 0.55 提到 0.85：**脸更阖，但 blink 节奏不变**。  
若只调 S2 把 `power` 提高：**E(t) 峰值变大，全通道 pulse 同步变猛，节奏仍由 E(t) 统一**。

## 三、为什么这样做（Why）

| 决策 | 理由 |
|------|------|
| 先算 1 条 E(t) 再展开 12 轨 | 避免 12 轨各自编时间轴导致不同步 |
| PAD 在 JSON `pad` 块、与滑杆分离 | 客户只调 6+3 滑杆；通道性格由定稿情绪定义 |
| styled 在 prior 之前 | 品种是「脸」，prior 是「叙事补偿（如回头）」叠在最外 |
| S4 特殊分支独立于 E×scale | 眨眼/湿眼/ripple 是表演力关键，纯乘法做不出 |

## 四、怎么实现（How）— 逐步编译

> 以下用 **t** 表示帧号 0…149，**ch** 表示通道名。

### S0 · 读入（门户勾选）

| 输入 | 路径 |
|------|------|
| 狗情绪 | `预设资产/情绪包/dog/{情绪名}.json` → `SliderPacket`（含 `pad`） |
| 狗品种 | `预设资产/风格包/dog/{breed_id}/style.json` → `base_offset`, `scale_factor` |
| 帧数 | `frame_count = 150`（常量 `FRAME_COUNT_DEFAULT`） |

**出参**：内存中的 `packet`，`breed_id`。

---

### S1 · 查 PAD（每种情绪一组常数）

```text
(P, A, D) = resolve_pad(packet)   // 优先 JSON pad 块，回退 emotion_pad 表
```

- 值域各 **[-1, 1]**
- **与品种无关**；狗 10 情绪 → **10 组**
- 客户微调滑杆 **不改变** PAD

代码：[`emotion_pad.py`](../../gaze_engine/_shared/emotion_pad.py) · [`dog_pipeline.run_dog_pipeline`](../../gaze_engine/dog/dog_pipeline.py) 步骤 1

**出参**：三个 float，**不是 150 帧**。

---

### S2 · 算 E(t)（150 帧 × 1）

**只读** `packet.macro` + `packet.hold_seg`，**不读** PAD、**不读** 品种。

```text
peak   = f(push, power)
plateau = peak × f(grip)
E[0…t_peak]     = 蓄力上升 → peak
E[t_peak…t_settle] = 启动 → plateau
E[t_hold0…t_hold1] = plateau × hold_texture(shape)
E[t_hold1+1…149]   = 缓和 → 0（或慢收留尾）
```

代码：[`build_energy_envelope()`](../../gaze_engine/_shared/envelope_compile.py)

**出参**：`envelope[t]`，**150 个数**。

---

### S3 · PAD 分配 → 每通道 scale（12 个常数）

```text
scale[ch] = DOG_BASE_SCALE[ch] + P×Wp + A×Wa + D×Wd
scale[ch] = max(0, scale[ch])
```

代码：[`compute_pad_scale()`](../../gaze_engine/_shared/envelope_compile.py) + [`pad_weights.py`](../../gaze_engine/dog/pad_weights.py)

**出参**：12 个 float。

---

### S4 · 情绪 pulse（12 × 150）⭐ 表演力主战场

对 **每一帧 t**、**每一通道 ch**，由 E(t) 与 scale[ch] 生成 **pulse**（品种尚未参与）。

#### 4.1 通用形

```text
pulse[ch, t] = clamp01( E[t] × scale[ch] × gain[ch] )
```

#### 4.2 特殊通道

| 通道 | 计算要点 |
|------|----------|
| `pupil_x` | `sign(push) × E[t] × scale[pupil_x]` |
| `pupil_y` | `(y_bias×E + sign×0.08×E) × scale[pupil_y]` |
| `blink` | **独立 blink 序列**（多锚点峰值），不是纯 E×scale |
| 带 `_DOG_CHANNEL_LAG` 的通道 | 用 `E[t-lag]` 而非 E[t] |

#### 4.3 保持段叠加

| 规则 | 条件 | 作用 |
|------|------|------|
| `_apply_tremble_hold_coupling` | hold.shape=tremble | ripple → squint、pupil_y 等 |
| `_apply_moist_sad_baseline` | 情绪名含委屈/可怜/渴望 | 保持段 squint/lid/gloss 抬高 |
| `micro_jitter` | 全段 | 生物微颤 |
| `inject_ear_into_channels` | JSON 有 `ear` | eyebrow / brow_raise |

代码：[`channels_from_envelope()`](../../gaze_engine/dog/envelope_compile.py)

**出参**：`pulse[ch][t]`，**12 × 150**。

> **微调重点**：S4 内各函数的 **锚点帧号、峰值系数、ripple 幅度、jitter hz** —— 这是「表演力最强」的主要施工区。

---

### S5 · 叠狗品种 → styled（12 × 150）✅ 已接入

```text
styled[ch, t] = clamp01( base_offset[ch] + scale_factor[ch] × pulse[ch, t] )
```

- **不改变** E(t)、**不改变** PAD
- `base_offset` 高 → 天生更阖/更湿；`scale_factor` 大 → 动态更夸张（易 clip）

代码：[`apply_breed_style()`](../../gaze_engine/dog/breeds.py)

**出参**：`styled[ch][t]`，**12 × 150**。

> **微调重点**：各品种 `style.json` 的 base/scale —— 改「脸」，不改「戏眼何时出现」。

---

### S6 · 叙事先验

在 **styled** 上叠加，如「回头」→ `pupil_x` 扫视。

代码：[`apply_dog_prior()`](../../gaze_engine/dog/prior.py)

---

### S7 · 质检 + 写入 02

```text
fix_dog_pulse_quality(channels)   // blink 下限、通道重合抽检
→ keyframes[t].v  × 1800
→ 02_烘焙 JSON
```

代码：[`dog_pipeline._make_dog_baked()`](../../gaze_engine/dog/dog_pipeline.py)

---

### 4.9 数据流总图

```text
S0  情绪 JSON（macro+hold+pad+ear）+ 品种 style.json
      ↓
S1  (P,A,D)  ← JSON pad 块
      ↓
S2  E[t]           150×1
      ↓
S3  scale[ch]      12×1
      ↓
S4  pulse[ch,t]    12×150   ← 表演力：blink/tremble/湿眼/jitter
      ↓
S5  styled[ch,t]   12×150   ← 品种 base+scale（已接入）
      ↓
S6  prior          叙事补偿
      ↓
S7  QC → 02 channel_tracks（1800 v）
```

## 五、检查点（Checkpoints）

### 5.1 结构合格（P0 · 管线通不通）

| 步骤 | 检查什么 | 方法 | 合格 |
|------|----------|------|------|
| S2 | E(t) 长度 | len(envelope) | **150** |
| S2 | 收束 | E[149] | ≈ **0** |
| S3 | scale | 12 通道 | ≥ 0 |
| S4 | pulse 形状 | dict keys | = `DOG_CHANNELS`，每 len **150** |
| S5 | styled 公式 | 单元测试 | = clamp(base+scale×pulse) |
| S7 | 02 稠密 | validate_baked_delivery | **1800** keyframes |

### 5.2 表演力清单（P1 · 像不像在演）

| 检查项 | 看什么 | 合格读感 |
|--------|--------|----------|
| **节奏** | E(t) @ t_peak, t_hold0~t_hold1 | 5 秒内能读出「起—盯—收」 |
| **盯住纹理** | hold.shape | flat=钉死 / pulse=呼吸 / tremble=细颤 / decay=下泄 |
| **眨眼** | blink 轨 | 全片 ≥2 次可见峰，委屈类更频 |
| **通道分化** | 任意帧 12 通道 | **不能** 12 轨数值几乎相同 |
| **情绪辨识度** | 同组两情绪 02 diff | peak 或 PAD 或 hold.shape 至少一项显著不同 |
| **品种气质** | 同情绪两品种 styled | E(t) 相同，blink/squint baseline 可辨 |

### 5.3 防出戏清单（P1 · 违不违自然）

| 风险 | 症状 | 查哪层 | 处理 |
|------|------|--------|------|
| **死眼** | 5s 无 blink | S4/S7 | 补 blink 锚点或 QC |
| **橡皮脸** | 12 通道同步拉伸 | S4 lag/gain | 加大 `_DOG_CHANNEL_LAG` 差异 |
| **顶死 clip** | 多通道长期 =1.0 | S5 base/scale | 降 base 或 scale_factor |
| **矛盾滑杆** | 急但无力、狠却飘 | L1 禁区 | `slider_bounds.py` G 条 |
| **品种改节奏** | 换品种 E(t) 变了 | S5 越界 | 查是否误改 macro（应只改 style） |
| **平顶开脉冲** | flat 却 ripple 很大 | S2 hold | G5/G6 规则 |

```text
       步骤1 resolve_pad
       步骤2 build_energy_envelope + channels_from_envelope   ← S2+S3+S4
       步骤3 inject_ear_into_channels                        ← S4 耳位

```

### 7.2 `run_dog_pipeline` 逐步对照

```python
# gaze_engine/dog/dog_pipeline.py · run_dog_pipeline()

# S1

# S7

baked = _make_dog_baked(pkt, channels, ...)
```
