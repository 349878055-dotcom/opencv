## 一、概述（What）

### 管线位置

```
上游：NL → SliderPacket（物种无关的数据单元）
  │
  ▼
┌─ _shared/（公共层：物种无关） ──────────────────────┐
│  数据类定义 · 能量曲线 E(t) · 校验 · I/O · LLM      │
│  输出：校验后的 SliderPacket + E(t)                  │
└────────────────────────────────────────────────────┘
  │
  ▼  （按 species 字段路由）
  ├── human/  ──→ 人类通道映射 + 九大人格 + 先验 + 质检
  ├── cat/     ──→ 猫通道映射 + 12情绪 + 品种风格 + 耳位 + 三眼睑
  └── dog/     ──→ 狗通道映射 + 10情绪 + 品种风格 + 耳位 + 眉脊
  │
  ▼
下游：02_烘焙.json → 扩散引擎 / 节拍表
```

### 管辖范围

本合同管辖：
- 什么代码可以放在 `_shared/`（公共层）
- 什么代码必须放在 `human/` `cat/` `dog/`（物种层）
- `_shared/` 与各物种包的调用依赖规则
- 数据传递的接口协议

### 边界（非管辖）

❌ 不定义具体物种的通道映射逻辑
❌ 不定义各物种的渲染算法
❌ 不定义预设情绪的具体数值
❌ 不定义 LLM prompt 的推理逻辑
❌ 不定义客户资产库的业务逻辑

## 二、理论依据（Theory）

### 理论依据链

```
① 不同物种的眼部解剖结构不同
   → 人类：眉毛独立运动系统，瞳孔虹膜分明，眼睑开合自由度大
   → 猫：耳位代替眉毛情绪表达，三眼睑（瞬膜），扫视更频繁
   → 狗：耳位替代部分眉毛功能，但保留眉脊，瞳孔变化幅度小
   → 结论：通道映射公式必须物种独立

② 但能量曲线 E(t) 是通用的
   → 无论什么物种，情绪的起/蓄/盯/收 是相同的物理节奏
   → Push/Power/Speed/Steady/Grip/Outro 六维滑杆是通用控制面
   → 结论：E(t) = f(macro) 可以在公共层

③ 数据类（DTO）和校验函数不携带物种信息
   → SliderPacket: { emotion, macro, hold_seg, species } 无物种假设
   → EarParams: { left_angle, right_angle } 通用参数
   → 结论：数据定义可以在公共层

④ 人格（persona）是人类的戏剧表演概念
   → "天选者_大祭司"、"魅惑者_部落巫医" 是人类角色标签
   → 猫/狗使用的是"品种风格"（breed style）作为风格化偏置
   → 品种风格 = base_offset + scale_factor，叠加在 **pulse** 之上（S5），**不改变 E(t)**
   → 人类人格与猫狗品种 **同公式、同层**；见 [`风格化偏向.md`](../05_风格化/风格化偏向.md)

⑤ 节奏说明书的提示词文案物种相关
   → 人类描述："眉压↑颧骨额肌紧张度"
   → 猫描述："brow_raise 映射耳尖微颤"
   → 狗描述："狗有眉毛肌，眉脊微动辅助表达"
   → 结论：文案数据必须物种独立，算法骨架可共用
```

## 三、为什么这样做（Why）

### 关键决策

| 决策 | 备选方案 | 选择理由 |
|------|---------|---------|
| **公共层只放物种无关代码** | 把所有人格/节奏数据放共享层 | 避免超大文件耦合；新增物种时无需修改共享层 |
| **`envelope_compile.py`（能量曲线）留在 `_shared/`** | 各物种各自复制一份 | 能量曲线是纯数学，无物种假设，重复代码无意义 |
| **`persona_compiler.py` 移到 `human/`** | 继续放共享层但用 species 分支 | "九大人格"是人类特有概念；猫狗用 breed style，不需要人格编译 |
| **`rhythm_compiler.py` 算法留共享层，文案下放** | 整个放共享层或用 species 分支 | 算法逻辑（帧收集、时间轴合并）是普适的；文案是物种特异的 |

### 历史教训

⚠️ **教训 1**：`export_diffusion_metronome.py` 和 `rhythm_compiler.py` 共存于 `_shared/`，功能高度重叠但后者是前者的进化版，导致调用方混乱。
→ 规则：同一功能的旧版必须标记废弃，调用方统一迁移到新版。

⚠️ **教训 2**：`persona_matrix.json` 混合了人类人格（9类）和猫狗品种风格（breed_personas），数据归属不清晰。
→ 规则：JSON 数据文件必须与使用它的代码放在同一目录，不允许"数据在共享层、消费代码在物种层"的跨目录引用。

⚠️ **教训 3**：`cat/breeds.py` 和 `dog/breeds.py` 通过 `get_persona(id)` 调用 `_shared/persona_compiler.py` 读取品种数据。
→ 规则：各物种的品种配置数据应读自己目录下的文件，不能依赖共享层的人格编译器。

### 4.2 输入/输出规格

#### 公共层输入

| 输入 | 格式 | 来源 |
|------|------|------|
| SliderPacket | `emotion: str, macro: MacroSliders, hold_seg: HoldSegment, species: str` | 前端 UI / NL → LLM |
| EarParams | `left_angle: float, right_angle: float` | 前端 UI（仅宠物版） |
| PAD 权重表 | `dict[str, tuple[float, float, float]]` | 各物种 `pad_weights.py` 传入 |
| 通道基础 scale | `dict[str, float]` | 各物种 `envelope_compile.py` 传入 |

#### 公共层输出

| 输出 | 格式 | 消费方 |
|------|------|--------|
| 校验后的 SliderPacket | `SliderPacket`（clamped） | 各物种 `envelope_compile.channels_from_packet()` |
| E(t) 能量曲线 | `List[float]` 长度 150 | 各物种 `envelope_compile` 的通道映射 |
| PAD 投影系数 | `float` | 各物种通道公式 `base + P×Wp + A×Wa + D×Wd` |

#### 物种层输入

| 输入 | 格式 | 来源 |
|------|------|------|
| SliderPacket | `SliderPacket` | `_shared/` 校验后 |
| E(t) 曲线 | `List[float]` | `_shared/envelope_compile.build_energy_envelope()` |
| 预设数据 | `dict`（情绪预设） | 各物种自己的 `presets.py` |
| 品种偏移 | `dict`（base_offset + scale_factor） | 各物种自己的品种配置 |

#### 物种层输出

| 输出 | 格式 | 消费方 |
|------|------|--------|
| 12 通道 × 150 帧 | `dict[str, List[float]]` | `delivery_pipeline.py` → 后续烘焙/导出 |
| 02_烘焙.json | JSON 文件 | 扩散引擎 / 节拍表导出 |
| 05_扩散节拍表.txt | 文本 | Wan 扩散引擎 |

### 4.3 核心公式与算法归属

| 公式/算法 | 归属 | 原因 |
|-----------|------|------|
| E(t) = f(push, power, speed, steady, grip, outro) | `_shared/envelope_compile.py` | 纯数学，物种无关 |
| PAD 投影: scale = base + P×Wp + A×Wa + D×Wd | `_shared/envelope_compile.py` | 通用公式，权重参数由物种传入 |
| final[t] = clamp(base_offset + pulse[t] × scale_factor) | `human/persona_compiler.py` | 人格偏置是人类特有概念 |
| channel[t] = scale[ch] × envelope[t] | 各物种 `envelope_compile.py` | 映射公式物种独立 |
| 二阶欠阻尼扫视 | `human/human_prior.py` | 人类真人化物理特征 |
| 三眼睑 + 耳耦合 | `cat/prior.py` | 猫特有解剖 |
| 耳耦合 + 眉脊保留 | `dog/prior.py` | 狗特有解剖 |
| 关键帧收集 + 时间轴合并 | `_shared/rhythm_compiler.py` | 算法逻辑通用 |
| 扩散提示词文案 | 各物种自持 | 文案语义物种特异 |

### 4.4 调用依赖规则

```
✅ 允许的调用方向：

  _shared/  →  物种包 (human/cat/dog)
     │               │
     │   共享层提供：数学公式、数据类、I/O、LLM 工具
     │
     └───────────────┘
     物种包之间不允许互相调用

❌ 禁止的调用方向：

  物种包  →  _shared/  （可调，但仅限公共函数，禁止读写共享层数据文件）
  物种包A →  物种包B   （完全禁止）
  
  例外：delivery_pipeline.py 是调度层，按 species 字段路由到各物种包
```
