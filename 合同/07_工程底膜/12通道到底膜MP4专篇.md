## 二、理论依据（Theory）

### 2.1 为什么需要「数值 → 像素」翻译

Wan 类视频扩散模型的 **Control / conditioning 接口接受图像或视频**，不接受 JSON 浮点数组。这是上游架构的硬约束，不是本项目的设计偏好。

因此管线必须在出厂前增加一道 **视觉封装**：

```text
数值真值（12×150 float）  ──驱动──▶  像素真值（150 帧 RGB PNG/MP4）
```

### 2.2 两条正交轴在本环节的汇合

低膜方案与 12 通道动画在本环节之前**完全分离**，只在渲染时相乘：

| 轴 | 管什么 | 存哪里 | 本环节角色 |
|----|--------|--------|-----------|
| **几何轴** | 眼距、眼位、眼大小、品种耳形 | `预设资产/底膜包/` + 客户 `物种底膜模板.json` | 决定 **画在哪里**（渲染常量 LEFT_CX、EYE_W…） |
| **动画轴** | 5 秒内各通道怎么动 | `02_烘焙.channel_tracks` | 决定 **画成什么形状**（每帧 12 个 float） |

合成公式（概念）：

```text
frame[t] = Render( template_constants, channels[t] )
```

- `template_constants` = `template_to_renderer_constants(species, effective_template, breed_id)`
- `channels[t]` = 从 `channel_tracks` 提取的第 t 帧 12 维向量

**改几何不动动画，改动画不动几何** — 与 [`03_12通道映射与编译链.md`](../03_情绪坐标/03_12通道映射与编译链.md) §2.1 一致。

### 2.3 RGB 三色 = 三个解剖系统的像素编码

| 色彩通道 | 解剖系统 | 12 通道中主要驱动者 |
|----------|----------|---------------------|
| **R** 红 | 眼眶（上下眼睑闭合环） | `blink`, `squint`, `lid_upper`, `lid_lower` |
| **G** 绿 | 眉毛（3 点折线） | `eyebrow`, `brow_raise` |
| **B** 蓝 | 虹膜实心 + 瞳孔环 | `pupil_x/y`, `pupil_scale`, `iris_scale`, `cornea_bulge` |

猫/狗额外绘制 **耳位**（仍走 G 或专用耳通道常量），详见各物种 `affine_renderer.py`。

### 2.4 从「滑杆」到「像素」的完整理论链

客户操作的 **6 macro + hold_seg** 并不直接进入渲染器。中间经过编译链（详见兄弟合同）：

```text
① SliderPacket（6 macro + hold_seg + emotion/PAD）
        ↓ finalize_packet（L1 禁区）
② E(t) 能量曲线（1×150）
        ↓ channels_from_envelope × PAD
③ pulse[12×150]
        ↓ apply_{species}_prior + fix_pulse_quality
④ Dense′[12×150]
        ↓ dense_to_baked_sparse / _make_species_baked
⑤ 02_烘焙.channel_tracks（出厂 JSON）
        ↓ _channels_from_baked
⑥ channels dict（渲染输入）
        ↓ affine_renderer.render_frame（×150）
⑦ 03_工程底模.mp4
```

**本专篇只管 ⑤→⑦**；①→⑤ 见 [`03_12通道映射与编译链.md`](../03_情绪坐标/03_12通道映射与编译链.md)。

### 2.5 12 通道 → 几何参数的映射原理

渲染器把 `[0, 1]` 归一化通道值映射为 **像素位移或缩放**。核心原则：

1. **眼睑** — 标准抛物线法，只改 peak，不改曲线族  
   `y = cy − peak × (1 − (2t−1)²)`  
   `peak = UPPER_PEAK − blink×BLINK_DROP − lid_upper×LID_UPPER_DROP`

2. **眉毛** — 3 点折线整体抬/压（走 `deform()`，不走抛物线拟合）

3. **瞳孔** — 圆心偏移 + 半径缩放；`blink ≥ 0.95` 时跳过瞳孔环绘制

4. **eye_gloss** — **不参与几何**；湿润感由 04 节拍表语义描述，交给扩散模型「脑补」

| 通道 | 几何作用 | 典型映射（人类常量） |
|------|----------|---------------------|
| `pupil_x` | 瞳孔/虹膜水平偏移 | `cx + px × PUPIL_X_RANGE × pupil_s` |
| `pupil_y` | 瞳孔/虹膜垂直偏移 | `cy + py × PUPIL_Y_RANGE × pupil_s` |
| `blink` | 上眼睑 peak 下降 | `UPPER_PEAK − blink × 40` |
| `squint` | 下眼睑 peak 上升 | `LOWER_BOT − squint × 25` |
| `lid_upper` | 上睑额外下压 | `− lid_upper × 15` |
| `lid_lower` | 下睑额外上抬 | `− lid_lower × 10` |
| `eyebrow` | 眉整体下压 | `cy + brow_offset`（deform） |
| `brow_raise` | 眉上抬 | 与 eyebrow 合成 brow_offset |
| `pupil_scale` | 瞳孔半径 | `PUPIL_R_BASE × (1 + p_scale × 0.5)` |
| `iris_scale` | 虹膜半径 | `IRIS_R_BASE × (1 + i_scale × 0.3)` |
| `cornea_bulge` | 虹膜额外放大 | `× (1 + cornea × 0.15)` |
| `eye_gloss` | — | 不绘制 |

完整常量表见 [`工程底膜驱动规范.md`](工程底膜驱动规范.md) §4.5–§4.6。

## 三、为什么这样做（Why）

### 3.1 关键决策一览

| 决策 | 备选 | 选择 | 理由 |
|------|------|------|------|
| 渲染触发点 | 编译链内嵌 / 门户按需 | **门户 export 时渲染** | 02 可反复存盘；MP4 重算成本高，按需生成 |
| 渲染输入 | 重跑 delivery / 读 baked | **读 `channel_tracks` 真源** | 与落盘 02 一致，避免双真值 |
| 几何来源 | 烘焙 JSON 内嵌 / 客户模板 | **`get_effective_template()` 实时读** | 标定后可重渲染旧 02，无需重编译通道 |
| 视频编码 | OpenCV VideoWriter / ffmpeg | **ffmpeg H.264 CRF 18** | 与 Wan 侧习惯一致；yuv420p 兼容 |
| 三物种 | 一套 renderer 参数化 | **三个 AffineRenderer 子类** | 猫竖瞳/狗垂耳等结构差异大 |

### 3.2 历史教训

| 问题 | 根因 | 规则 |
|------|------|------|
| 眼角跑偏 | deform 线性衰减 ≠ 底图抛物线 | 💥 眼睑只走标准抛物线公式 |
| 帧间闪烁 | LINE_AA + micro_jitter | 💥 工程底膜必须 LINE_8 硬边缘 |
| 狗项目用了人类 MP4 | 旧管线未写 `membrane_meta.species` | 门户 `_analyze_membrane_status()` 强制校验 |
| 标定后 MP4 眼位不对 | 渲染未读客户模板 | `_render_opencv_video` 必须 `get_effective_template()` |

### 3.3 扩散引擎为什么要 MP4 + Prompt 双路

| 输入 | 类型 | 管什么 |
|------|------|--------|
| `03_工程底模.mp4` | **像素 conditioning** | 眼眶/眉/瞳孔的精确时空轨迹 |
| `04_Prompt.txt` + wan± | **语义 conditioning** | 演什么情绪、什么品种、什么叙事 |
| `start_image.jpg` | **外观锚点** | 客户参考照，锁脸型 |

三者打包在 `输出/扩散引擎包/manifest.json`，`ready_for_diffusion=true` 当 03 + 04 齐备。

**MP4 渲染完之后的组装细则**见 **[`扩散输出流程专篇.md`](../08_输出与扩散/扩散输出流程专篇.md)**。  
**「导演指令 / 每帧语义」是什么、怎么从 02 编译**见 **[`扩散输出流程专篇.md`](../08_输出与扩散/扩散输出流程专篇.md)** — 本专篇只管 02→03 像素封装。

## 四、怎么实现（How）

### 4.1 端到端数据流

```text
┌─ 上游（已完成）────────────────────────────────────────┐
│  SliderPacket → run_species_delivery()                  │
│    → 02_烘焙_真人律.json（channel_tracks: 12×150）       │
│  客户标定 → 物种底膜模板.json → effective_template       │
└────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─ 本环节：视觉封装 ─────────────────────────────────────┐
│  _channels_from_baked(baked)                            │
│    → channels: dict[str, list[float]]                   │
│  template_to_renderer_constants(species, template, breed)│
│    → constants: LEFT_CX, EYE_W, BLINK_DROP, …           │
│  for t in 0..149:                                       │
│    renderer.render_frame({k: channels[k][t]})           │
│    → PNG f_{t:04d}.png (690×361 RGB)                    │
│  ffmpeg → 03_工程底模.mp4                               │
│  写 03_工程底模.meta.json（species, renderer, frame_count）│
└────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─ 下游：扩散输出 ───────────────────────────────────────┐
│  DiffusionPromptAssembler → 04_Prompt.txt               │
│  build_diffusion_bundle() → 扩散引擎包/                  │
│    ├── 03_工程底模.mp4                                   │
│    ├── 04_Prompt.txt                                    │
│    ├── wan_positive.txt / wan_negative.txt              │
│    ├── start_image.jpg                                  │
│    └── manifest.json                                    │
└────────────────────────────────────────────────────────┘
```

### 4.2 核心函数调用链

```python
# 1. 提取渲染通道（真源 = baked.channel_tracks）
channels = _channels_from_baked(baked, _species_channel_keys(species))

# 2. 合成几何常量（真源 = 客户 effective_template + breed）
template = get_effective_template(customer_id)
constants = template_to_renderer_constants(species, template, breed_id=breed)

# 3. 构造渲染器
renderer = AffineRenderer(constants)  # 或 Cat/Dog 版本

# 4. 逐帧绘制 + ffmpeg
for t in range(frame_count):
    fd = {k: channels[k][t] for k in keys}
    img = renderer.render_frame(fd)   # (361, 690, 3) uint8
    cv2.imwrite(f"f_{t:04d}.png", img)
# ffmpeg → control_video.mp4 → 复制为 03_工程底模.mp4
```

## 五、检查点（Checkpoints）

| 编号 | 检查项 | 方法 | 合格标准 | 优先级 |
|------|--------|------|----------|--------|
| R01 | 02 含 channel_tracks | 读 JSON | 12 轨 × 150 点，无 NaN | **P0** |
| R02 | MP4 帧数 | `ffprobe` | = 150 | **P0** |
| R03 | MP4 分辨率 | `ffprobe` | 690 × 361（偶数对齐后） | **P0** |
| R04 | meta.species 与项目一致 | 读 `03_工程底模.meta.json` | 与 `project.species` 相同 | **P0** |
| R05 | 渲染读客户模板 | 标定前后各 render 一次 | 眼距/眼位变化，通道 JSON 不变 | **P1** |
| R06 | channels=0 ≈ 模板中性帧 | 对比首帧与 `底膜预览.png` | 几何一致 | **P0** |
| R07 | 扩散包就绪 | `manifest.ready_for_diffusion` | true（03 + 04 存在） | **P0** |
