## 一、概述（What）

### 1.1 本文件管什么

本文定义 **工程底膜的几何模板从哪来、怎么选、怎么标定、何时注入渲染**，以及 **与 S5 风格层的边界**。

工程底膜 = **扩散引擎消费的 RGB 线条骨架**（见 [`工程底膜合同.md`](工程底膜合同.md)）。  
底膜模板 = **驱动该骨架的静态几何参数**（眼距、眼位、耳形控制点等），**不包含** 150 帧动态曲线。

### 1.2 管辖范围

✅ 三层底膜选择策略：物种 → 品种 → 客户配准  
✅ 预设资产与客户资产的存放边界  
✅ 头像标定流程：上传照 → 自动检测 / 手动锚点 → 存盘 → 渲染 MP4  
✅ 人 / 猫 / 狗 分工差异  
✅ 与 S5 `style`（改通道曲线）的正交边界  
✅ **禁止客户侧「美图秀秀式」美颜**（见 §3.4、§5 P0）

### 1.3 边界（非管辖）

❌ RGB 三色协议、0-noise、抛物线驱动公式 → [`工程底膜合同.md`](工程底膜合同.md)  
❌ `affine_renderer` 内部算法 → [`工程底膜驱动规范.md`](工程底膜驱动规范.md)  
❌ macro / PAD / E(t) / styled 曲线编译 → `01`～`05`、`09` 目录  
❌ 扩散 Prompt 文案 → [`07_输出与扩散/`](../08_输出与扩散/)

### 1.4 一句话定义

> **底膜标定 = 用参考照把工程骨架配准到「这只脸的真实解剖比例」；不是让客户把眼睛调大、把脸修瘦。**

### 1.5 低膜资产定稿（产品口径 · 必读）

**不是「一个狗品种 = 一套独立低膜文件」。** 定稿如下：

| 问题 | 定稿 |
|------|------|
| 一个狗种类是不是一个低膜？ | **否。** 所有狗 **共用 1 套物种低膜**；每个品种只有 **1 份预存几何偏移**，不是 N 套独立低膜资产。 |
| 猫是不是一样？ | **是。** 猫 **共用 1 套物种低膜** + 每猫品种 1 份预存偏移 + 客户配准。猫暂无狗级 `template_structure` 耳控制点换形，差主要在 `template_scales` 乘数。 |
| 人怎么算？ | **1 套 human 物种低膜 + 客户配准**；**无品种偏移层**（九人格只走 S5 曲线，不改低膜）。 |
| 预设资产里放什么？ | **物种默认** → `预设资产/底膜包/{human,cat,dog}/species_default.json`（只读） |
| 品种偏移放哪？ | **编辑真源** → `预设资产/底膜包/{cat,dog}/breeds/{breed_id}.json`；**运行时** → `gaze_engine/{cat,dog}/breed_matrix.json` 的 `template_scales`（狗另有 `template_structure`）。由 `sync_membrane_pack.py` 同步。 |
| 客户层放哪？ | 标定后 → `客户资产库/客户_{id}/物种底膜模板.json`（只含配准，禁止美颜手调） |

**合成公式（运行时一次算清）：**

```text
最终低膜几何 =
    物种默认（底膜包）
  × 品种偏移（breed_matrix · 工程预存、已算好）
  × 客户配准（参考照/锚点 · 个体微调）
```

**与 S5 风格包的区别（勿混）：**

| 资产 | 管什么 | 是否低膜 |
|------|--------|----------|
| `底膜包/` + `breed_matrix.template_*` | 静态线条骨架（眼距、耳形） | ✅ 是 |
| `风格包/{breed}/style.json` | 150 帧通道曲线（半阖、扫视幅度） | ❌ 不是低膜 |

品种偏移 **在编译/标定/渲染前由代码合成**（`adjust_template_for_breed` → `apply_customer_adjustments` → `template_to_renderer_constants`），**不是**门户运行时让客户填公式。

**对外一句话**：预设里存的是 **「物种 1 底 + 品种 N 偏移」**；客户只贡献 **照片配准**；换品种 = 换偏移表 + **必须重新标定**（见 [`猫狗品种底膜选择专篇.md`](猫狗品种底膜选择专篇.md)）。

## 二、理论依据（Theory）

### 2.1 动态与几何必须正交

| 维度 | 管什么 | 数据形态 | 时间轴 |
|------|--------|----------|--------|
| **动态** | 5 秒内怎么动（眨、扫视、眉抬） | 12 通道 × 150 帧 | ✅ 有 |
| **几何** | 这张脸眼距多大、耳怎么垂 | `SpeciesTemplate` 常量 | ❌ 无 |

Wan conditioning 需要 **像素骨架视频**。骨架的 **形状** 与 **运动** 若混在同一旋钮里，无法复用情绪预设，也无法做 P0 验收。

### 2.2 三层资产对应三层「脸框」

```text
① 物种底膜     → 人 / 猫 / 狗 各一套解剖默认（眉是否存在、猫竖瞳、狗垂耳…）
② 品种偏移     → 贵宾 vs 柴犬 的耳形、眼型比例（参数化，非独立 mesh 文件）
③ 客户配准     → 参考照测到的眼距/眼位/耳位，对齐到该个体
```

与 [`04_四层表演栈与style边界.md`](../03_情绪坐标/04_四层表演栈与style边界.md) 中 **并行几何层** 一致：

```text
template' = species_default × breed.template_scales × breed.template_structure × 客户配准
styled[ch,t] = base_offset + scale_factor × pulse[ch,t]   ← 另一层，不改 template
```

### 2.3 标定是配准（Registration），不是美颜（Retouch）

- **配准**：测量参考照中两眼间距、眼鼻关系、耳尖位置 → 映射为相对标准模板的 **比例因子**（1.0 = 预设标准）。  
- **美颜**：用户主观希望「眼睛大一点、脸小一点」→ **不属于本产品**。

解剖比例一旦在标定中写死，后续 150 帧只在该几何上 **做表演**；禁止在门户提供自由几何滑杆，避免与美图类软件功能混淆。

## 三、为什么这样做（Why）

### 3.1 关键决策一览

| 决策 | 备选 | 选择 | 理由 |
|------|------|------|------|
| 品种底膜 | 每品种独立 PNG mesh | **物种底 + 参数偏移** | 可维护；38 情绪自动继承 |
| 客户层 | 自由滑杆调眼大小 | **仅照片/锚点配准** | 防美颜化；可审计 |
| 人格/品种戏感 | 写进 template | **走 S5 style** | 正交；改贵宾半阖不改眼距 |
| 预设存放 | 散落代码常量 | **`预设资产/底膜包/`** | 与情绪包/风格包同级只读真源 |
| 客户存放 | 写进项目滑杆 | **`客户资产库/物种底膜模板.json`** | 客户级复用；与 02 分离 |

### 3.2 人 vs 猫狗

| 物种 | 物种底 | 品种层 | 客户配准项 |
|------|--------|--------|------------|
| **人** | 一套 human 几何 + 共用 `eyelid_raw.png` | **无**（九人格属 S5，不改几何） | 眼距、眼位、眼大小、眼睑形、瞳孔、虹膜（6 项） |
| **猫** | 一套 cat 几何（竖瞳、三角耳） | `template_scales` + 耳角度 | 同上 + 耳位；未标耳则回退品种 |
| **狗** | 一套 dog 几何 | `template_scales` + **`template_structure`**（耳/眉控制点） | 同上 + 耳下垂；未标耳则回退品种 |

猫狗 **品种 id 能否混用**、三处 breed 如何对齐 → 专篇 [`猫狗品种底膜选择专篇.md`](猫狗品种底膜选择专篇.md)。

**不是**「人类一套、猫狗各 N 套品种文件」——品种差异是 **乘数 + 控制点**，不是 N 份独立底膜资产。

### 3.3 与 S5 风格层的边界

| 你想改… | 改哪里 | 示例 |
|---------|--------|------|
| 贵宾 **更常半阖眼、扫视幅度小** | S5 `style.json` / `base_offset` | `blink` base↑ |
| 这只狗 **眼距比 AKC 标准更宽**（个体解剖） | 底膜配准 | `eye_distance` 由照片测得 |
| 客户觉得 **眼睛不够大想修大** | ❌ **禁止** | 美图秀秀范畴 |

**口诀**：`style` 改 **怎么演**；`template` 改 **骨架长什么样**；客户 **不能** 用 template 做审美修图。

### 3.4 禁止行为（产品红线）

| 禁止 | 原因 | 替代 |
|------|------|------|
| 门户提供「眼睛大小」「脸宽」等 **自由滑杆** | 等同于美图秀秀 | 仅上传照 + 锚点配准 |
| 客户手动把 `eye_size` 调到 > 标准以「变大眼」 | 破坏配准语义 | 换参考照或重标锚点 |
| 把 macro/PAD 当几何修图 | 层混乱 | 改对应层合同 |
| 用 S5 style 改 `eye_distance` | style 无几何键 | 走底膜包或配准 |
| 未标定直接渲染 MP4 却声称「像某客户脸」 | 骨架仍是物种/品种默认 | 必须先标定或声明默认 |

💥 **对外口径**：本软件做 **眼眉表演资产**，不做 **人像美颜**。

## 四、怎么实现（How）

### 4.1 资产边界（真源位置）

#### 预设资产（只读 · 工程维护）

```text
预设资产/
├── 情绪包/          ← S2  macro/hold/pad
├── 风格包/          ← S5  base_offset + scale_factor（改通道曲线）
└── 底膜包/          ← 几何预设（本专篇）
    ├── human/species_default.json
    ├── cat/species_default.json
    ├── dog/species_default.json
    ├── {cat,dog}/breeds/{breed_id}.json   ← 品种偏移编辑真源（AKC/CFA 依据）
    └── README.txt
```

| 层级 | 路径 | 内容 | 谁改 |
|------|------|------|------|
| 物种默认 | `底膜包/{species}/species_default.json` | `SpeciesTemplate` 基准 + 渲染常量摘要 | 工程 |
| 品种偏移（编辑） | `底膜包/{cat,dog}/breeds/{breed_id}.json` | `template_scales` / `template_structure` + `_reference` | 工程 |
| 品种偏移（运行） | `gaze_engine/{species}/breed_matrix.json` | 同上字段（由 `sync_membrane_pack.py` 生成） | 脚本 sync |
| 共用纹理 | `gaze_engine/_shared/assets/eyelid_raw.png` | 1024 抛物线底图 | 工程 |

> **说明**：品种 **通道风格** 在 `风格包/`；品种 **几何偏移** 在 `breed_matrix` 的 template 字段。二者 sync 自同一 catalog，但职责不同（曲线 vs 骨架）。

#### 客户资产（标定后写入）

```text
客户资产库/客户_{id}/
├── 客户信息.json              ← preferred_species, breed
├── 参考素材/                  ← 正面照（配准输入，非美颜源图）
├── 物种底膜模板.json          ← schema: species_template_v1（配准结果真源）
└── 项目_{pid}/
    ├── 参考素材/              ← 项目内副本
    ├── 手动标定.json          ← 锚点记录 + 预览路径（审计）
    └── 输出/
        ├── 底膜预览_品种默认.png
        ├── 底膜预览_标定后.png
        └── 03_工程底模.mp4
```

**规则**：

- 门户 **只存选项 id**（物种、品种、情绪、人格）；数值从 `预设资产/` 拉取。  
- 客户 **唯一** 可写入的几何真源 = `物种底膜模板.json`（由标定管线生成，**非**手填美颜参数）。  
- 项目内 `手动标定.json` = 锚点与预览审计；渲染以 `物种底膜模板.json` 为准。

### 4.2 合成公式与优先级

```text
effective_template =
    load_species_default(底膜包/{species})
    |> adjust_template_for_breed(breed_matrix.template_scales)
    |> apply_breed_structure(breed_matrix.template_structure)   # 狗/猫耳眉控制点
    |> apply_customer_adjustments(物种底膜模板.json)            # 仅配准测得项
    |> template_to_renderer_constants()
    |> AffineRenderer / CatAffineRenderer / DogAffineRenderer
```

**读取优先级**（`get_effective_template`）：

1. 客户已保存 `物种底膜模板.json`  
2. 否则：`species_default` + 客户信息中的 `breed`  
3. 渲染 MP4 时注入，**不**回写 02 JSON

### 4.3 标定流程（何时注入）

```text
┌─ 前置 ─────────────────────────────────────────┐
│  建客户 / 项目 · 选定 species + breed         │
└───────────────────────────────────────────────┘
        │
        ▼
┌─ 标定（几何 · 一次性或换照重做）──────────────┐
│  A. POST /api/portal/project/upload-photo      │
│     → auto_detect_for_customer (L0~L3)         │
│  B. POST /api/portal/calibrate-template      │
│     → anchors_to_template_adjustments          │
│  → 写入 物种底膜模板.json + 手动标定.json     │
│  → 生成 底膜预览_品种默认 / 标定后 PNG        │
└───────────────────────────────────────────────┘
        │
        ▼
┌─ 表演（动态 · 每项目/每情绪）─────────────────┐
│  Pomot / delivery_pipeline → 02 烘焙 JSON      │
│  （150 帧 · 与 template 正交）                  │
└───────────────────────────────────────────────┘
        │
        ▼
┌─ 渲染底膜 MP4 ────────────────────────────────┐
│  _membrane_renderer(customer_id)              │
│  = get_effective_template + 02 channels       │
│  → 03_工程底模.mp4                            │
└───────────────────────────────────────────────┘
        │
        ▼
   扩散引擎包（MP4 + 04 Prompt）
```

**注入点**：仅在 **`render_batch` / 底膜 MP4 导出** 时读取 `effective_template`；02 烘焙 **不含** 几何模板字段。

### 4.4 自动检测 vs 手动锚点

| 方式 | 入口 | 输入 | 输出 |
|------|------|------|------|
| 自动 | `upload-photo` | 参考照 | MediaPipe（人）/ OpenCV+YOLO（猫狗）→ `detection_to_template_adjustments` |
| 手动 | `calibrate-template` | 眼/鼻/（可选）耳 **锚点像素** | `anchors_to_template_adjustments` |

**共同约束**：

- 参数经 `_clamp_template` 限制在配准合理区间（默认 0.5～1.5），防止极端值。  
- 客户 **不能** 绕过锚点/检测直接提交任意 `eye_size`。  
- 检测失败 → 提示重拍或改用手动锚点；**不能** 用滑杆凑。

## 五、检查点（Checkpoints）

| 检查项 | 方法 | 合格标准 | 优先级 |
|--------|------|----------|--------|
| 预设只读 | 门户无写 `预设资产/底膜包` 接口 | 客户 API 写不入底膜包 | **P0** |
| 禁止美颜滑杆 | UI / API 审查 | **无** 客户可调 `eye_size` 等自由几何项 | **P0** |
| 配准来源 | 查 `物种底膜模板.json` | 含 `schema: species_template_v1`；有标定则 `updated_at` 非空 | **P0** |
| 层正交 | 改 style 不改 template | `apply_persona_style` / `apply_breed_style` 不触几何常量 | **P0** |
| 渲染注入 | channels=0 帧对比 | 无标定=品种默认；有标定=预览 PNG 一致 | **P0** |
| 02 不含 template | 查 02 JSON keys | 无 `SpeciesTemplate` / 几何滑杆字段 | **P1** |
| 猫狗耳回退 | 未标耳尖 | 耳参数来自 `breed_template_ear_params` | **P1** |
| MP4 帧数 | 输出目录 | 150 帧 · 690×361 · 见 [`工程底膜合同.md`](工程底膜合同.md) §5 | **P0** |

## 六、增量修改原则

1. **新增品种几何** → 改 `breed_matrix.template_scales/structure` + `05_风格化` 合同 + sync 脚本；**不** 新建独立底膜 PNG。  
2. **改物种默认** → 改 `预设资产/底膜包/{species}/species_default.json` + `species_template.py` 对齐。  
3. **客户配准逻辑变更** → 同步 `_clamp_template` 区间与本专篇 §4.4。  
4. **禁止** 为「客户想要大眼」开 API 或 UI — 产品需求一律拒绝，引用 §3.4。  
5. 修改前见 [`合同规范.md`](../合同规范.md) §5 思维检查清单。
