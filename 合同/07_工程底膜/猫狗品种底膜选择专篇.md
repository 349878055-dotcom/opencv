## 一、概述（What）

### 1.1 一句话结论

| 问题 | 答案 |
|------|------|
| 一个狗种类是不是一个低膜？ | **否。** 狗 **1 套物种低膜** + 每品种 **1 份预存偏移**（见上级专篇 §1.5） |
| 猫是不是一样？ | **是。** 结构相同；猫品种差主要在 `template_scales` |
| 猫和狗能共用一套底膜吗？ | **不能**。物种各一套渲染器 + `底膜包/{cat,dog}/` |
| 标定用的品种和第②步选的品种不一致会怎样？ | **禁止交付**。S5 曲线可能已是柴犬，底膜几何仍是贵宾 → 扩散 conditioning 与 Prompt 分裂。 |
| 客户配准能否跨品种复用？ | **仅当品种 id 相同**时可复用 `物种底膜模板.json`；换品种必须重标。 |

### 1.2 本文件管什么

✅ 猫 / 狗 品种底膜在预设资产与客户资料中的分工  
✅ 品种 id 在标定 → S5 style → 渲染 MP4 三处的 **绑定规则**  
✅ 代码入口地图（忘记实现时可查表）  
✅ **禁止混用** 的验收口径  

### 1.3 边界

❌ RGB 格式、抛物线驱动 → [`工程底膜合同.md`](工程底膜合同.md)

## 二、理论依据（Theory）

### 2.1 三层几何，两个 id

猫狗交付同时涉及 **两个不同 id**（不要混为一个「品种」）：

| 线 | id 存在哪 | 管什么 | 典型文件 |
|----|-----------|--------|----------|
| **几何底膜** | `breed`（客户信息 + 标定 JSON） | 眼型比例、耳控制点 | `breed_matrix.template_scales` / `template_structure` |
| **表演风格 S5** | `style` / `breed`（滑杆包、02） | 半阖、扫视幅度等 **通道曲线** | `风格包/{species}/{breed}/style.json` |

**同一品种 id**（如 `poodle_giant`）在两处各有一份资产，**公式层正交、id 层必须一致**。

### 2.2 狗 vs 猫 品种几何差异

| 项 | 狗 | 猫 |
|----|-----|-----|
| 物种底 | `_RENDERER_CONSTANTS["dog"]` | `_RENDERER_CONSTANTS["cat"]` |
| 品种乘数 | `adjust_template_for_breed` ← `template_scales` | 同左 |
| 耳/眉 **控制点换形** | `apply_breed_structure` ← `template_structure` | **暂无**（仅 scales + 耳角度映射） |
| 渲染器 | `DogAffineRenderer` | `CatAffineRenderer` |

因此：**狗品种差异常比猫更大**（垂耳控制点整组替换），混用后果更严重。

### 2.3 合成公式（工程师版）

```text
# 预设（只读）
breed_baseline = species_default
               |> adjust_template_for_breed(breed_id)    # template_scales

# 客户（标定后）
effective = breed_baseline
          |> apply_customer_adjustments(配准项)           # 仅眼/鼻/可选耳锚点

# 渲染常量
constants = _RENDERER_CONSTANTS[species]
          |> apply_breed_structure(breed_id)              # 仅狗；耳/眉控制点
          |> template_to_renderer_constants(effective)
```

**配准项**（来自照片/锚点，非美颜）：

- 共有：`eye_distance`, `eye_vertical`, `eye_size`（均为 **相对品种基准的比例**，不是「修大眼」）
- 狗：`ear_droop` 等（仅当标了耳尖；否则 `breed_template_ear_params(breed_id)`）
- 猫：`ear_angle`, `pupil_slit_ratio` 等

## 三、为什么禁止混用（Why）

### 3.1 混用场景与后果

| 混用方式 | 后果 | 是否允许 |
|----------|------|----------|
| 柴犬 S5 style + 贵宾 `template_structure` 垂耳 | Prompt 写柴犬，线条是贵宾耳 | ❌ |
| 标定 breed=A，渲染 breed=B | 眼距按 A 比例，耳形按 B | ❌ |
| 同一客户、同一 breed，换情绪 preset | 仅 02 曲线变，几何不变 | ✅ |
| 未标定，只用品种默认 | 中性骨架 + 品种默认耳形 | ✅（须声明非个体配准） |

### 3.2 与「美图秀秀」的边界（再强调）

标定产生的 `eye_size ≠ 1.0` 表示 **该个体相对品种标准解剖更宽/更窄**，不是客户主观「想要更大眼」。  
门户 **不得** 提供几何滑杆；对比表文案用 **「相对品种基准」**，不用「变大/变美」。

### 3.3 门户步骤与品种 id（现状 + 规则）

**规则（目标态）**：

```text
① 选物种 + 选品种（猫/狗）→ 上传照 → 锚点标定 → 写入 物种底膜模板.json（含 breed）
② 选情绪 + 品种（须与①相同 id）
③ Pomot 生成 02（style_id = breed）
④ 渲染 MP4（breed_id = ① 中 breed，与 ② 校验一致）
```

**代码真源（查表用）**：

| 步骤 | 行为 | 代码位置 |
|------|------|----------|
| 标定 | `breed` ← 请求体；写入 `_save_template_params` | `serve_workbench.py` · `portal_calibrate_template` |
| 读模板 | 优先 `物种底膜模板.json` | `customer_db.get_effective_template` |
| 渲染 MP4 | `breed_id` ← 请求体，与标定 breed 校验 | `_render_opencv_video` · `portal_render_preview` |
| S5 曲线 | `style_id=breed_id` | `run_species_delivery` · `apply_breed_style` |
| 品种几何表 | `template_scales` / `template_structure` | `gaze_engine/{dog,cat}/breed_matrix.json` |
| 合成 | 三层叠加 | `species_template.py` |

## 四、怎么实现（How）

### 4.1 资产谁放哪

| 内容 | 位置 | 可写 |
|------|------|------|
| 物种默认 | `预设资产/底膜包/{cat,dog}/species_default.json` | 工程 |
| 品种几何 | `breed_matrix.json`（与风格包 sync） | 工程 |
| 品种 S5 | `预设资产/风格包/{cat,dog}/{breed}/style.json` | 工程 |
| 客户配准结果 | `客户资产库/客户_{id}/物种底膜模板.json` | 门户标定 API |
| 标定审计 | `项目_{pid}/手动标定.json` | 门户 |

`物种底膜模板.json` 字段：

```json
{
  "schema": "species_template_v1",
  "species": "dog",
  "breed": "poodle_giant",
  "params": { "eye_distance": 1.02, "..." : "..." },
  "updated_at": "..."
}
```

**`breed` 与 `params` 绑定保存**；换 `breed` 必须重写该文件（重标定）。

### 4.2 门户操作顺序（猫/狗）

1. **先选品种**（第①步品种下拉，来源 `GET /api/portal/presets` 的 styles 列表）  
2. 上传正面照，标眼/鼻/（可选）耳  
3. 确认标定 → 服务端用 **当前 breed** 合成并保存  
4. 第②步选情绪；品种按钮 **须与第①步相同**（变更时提示重标）  
5. 第③步生成 → 第④步渲染（服务端校验 breed 一致）

### 4.3 API 与 breed 参数

| API | breed 来源 |
|-----|------------|
| `POST .../calibrate-template` | body.`breed`（必填 cat/dog） |
| `POST .../render-preview` | body.`breed`；须等于 `物种底膜模板.json` 内 breed |
| `POST .../pomot/round1` | body.`breed` → S5 |

## 五、检查点（Checkpoints）

| 检查项 | 方法 | 合格 | 优先级 |
|--------|------|------|--------|
| 无品种混用 | 标定 breed ≠ 渲染 breed | API **400** + 门户提示重标 | **P0** |
| 无跨物种 | cat 项目渲染 dog renderer | 拒绝 | **P0** |
| 无几何滑杆 | 门户 DOM / API | 无客户可调 template 字段 | **P0** |
| 02 与 breed | baked.style / breed 与模板 breed 一致 | 一致 | **P1** |
| 预览对照 | 左=breed_baseline(breed)，右=effective | 与 MP4 首帧几何一致 | **P1** |
| 换品种 | 用户改第②步品种 | 必须出现「请重新标定」 | **P0** |

## 六、FAQ

**Q：能不能先标定，后随便换品种省时间？**  
A：不能。换品种会换 `template_scales` 和（狗）耳控制点；旧配准比例对新品种无意义。

**Q：同一只狗多个项目能否共用标定？**  
A：可以，**同一 customer_id + 同一 breed** 下共用 `物种底膜模板.json`。

**Q：人类项目要选品种吗？**  
A：不选。人类无品种几何层；九人格仅 S5。

**Q：第①步标定和第②步品种不一致，历史上为什么会发生？**  
A：早期狗标定硬编码 `poodle_giant` 而第②步才选品种 → 已改为第①步选 breed + 渲染校验；见门户与 `calibrate-template` 实现。
