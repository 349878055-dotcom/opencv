# 三层分工与编译链专篇

> **一句话**：表情最终效果 = macro（何时多大力）× PAD（什么味）× style（什么脸框），三者正交串联不可替代。

---

## 一、三层总览

```
┌─────────────────────────────────────────────────────────────────┐
```

## 二、为什么拆三层

### 2.1 核心矛盾

单一"表演力"旋钮无法同时满足：

```
客户说"我想让这个表情更委屈" → 
  是更用力（调 macro）？ 
  还是更委屈的味（调 PAD）？
  还是换个贵宾品种的眉形（调 style）？
```

拆三层后，每个需求对应唯一的一层：

| 客户说 | 改哪层 | 改什么参数 |
|--------|--------|-----------|
| "力度再大一点" | macro | power/push |
| "看着更委屈" | PAD | (P, A, D) 值 |
| "这是贵宾不是金毛" | style | breed 模板 |
| "节奏再快一点" | macro | speed/outro |
| "出场曲线柔和些" | style | scale_factor |

### 2.2 三层为什么不能合并

| 假设 | 为什么错 |
|------|----------|
| "PAD 不就是表演力吗？" | PAD 会影响所有通道的幅度比例，但 E(t)=0 时 PAD=0。如果把 PAD 混入 macro，会导致「委屈的人不能有力度大的时候」 |
| "style 不就是 PAD 吗？" | style 是**脸框级常数偏移**（贵宾眉形），与情绪无关。贵宾的委屈和德牧的委屈，PAD 值是一样的，但最终脸不一样。 |
| "macro 强 = 所有通道都大" | 不对。macro 对所有通道同步缩放，PAD 对每个通道独立缩放。两者相乘才是最终幅度。 |

## 三、三层如何组合

### 3.1 完整公式

```
对于通道 ch，第 t 帧：

  pad_scale[ch] = max(0, BASE[ch] + P×Wp[ch] + A×Wa[ch] + D×Wd[ch])
        raw[ch,t] = E[t - lag[ch]] × pad_scale[ch] × GAIN[ch]
          pulse[ch,t] = clamp(raw[ch,t], 0, 1)

  风格化后：
    final[ch,t] = style_base[ch] + style_scale[ch] × pulse[ch,t]
```

### 3.2 公式解读

| 分量 | 来源层 | 含义 |
|------|--------|------|
| `E[t - lag[ch]]` | macro | 表演时间结构（带通道滞后） |
| `pad_scale[ch]` | PAD | 情绪气质系数 |
| `GAIN[ch]` | 系统常数 | 渲染器安全系数（不让数值溢出的保险） |
| `lag[ch]` | 先验 | 通道生理滞后（例如 eyebrow 滞后 pupil 8-15 帧） |
| `style_base[ch]` | style | 品种/个体通道零位偏移 |
| `style_scale[ch]` | style | 品种/个体通道灵敏度缩放 |

### 3.3 算例：贵宾 × 委屈

| 通道 | E(t)峰值 | pad_scale | GAIN | raw | style_base | style_scale | final |
|------|----------|-----------|------|-----|------------|-------------|-------|
| eyebrow | 0.85 | 0.655 | 1.0 | 0.557 | +0.05 | 1.0 | 0.607 |
| pupil_x | 0.85 | 0.50 | 0.35 | 0.149 | 0.0 | 1.0 | 0.149 |
| blink | 0.85 | 0.48 | 0.40 | 0.163 | 0.0 | 1.0 | 0.163 |

> 说明：eyebrow 由于 PAD 的 D 负贡献（-0.5×-0.35=+0.175），pad_scale 达到 0.655，是所有通道中最高的 — 这就是"委屈"在眉眼上的核心表现。

## 四、S4 编译链详解

### 4.1 输入输出

```
输入:
  - E(t): list[float] length=150  (from build_energy_envelope)
  - pad_scale: dict[str, float]   (from compute_pad_scale)
  - channels_config: 包含 lag, gain 等参数

输出:
  - pulse[ch]: list[float] length=150  for each of 12 channels
```

### 4.2 12 通道编译步骤

1. **滞后对齐**：`E_lag[t] = E[t - lag[ch]]`（对于 t < lag，E_lag = 0）
2. **PAD 缩放**：`raw[t] = E_lag[t] × pad_scale[ch]`
3. **增益限制**：`raw[t] × GAIN[ch]`（GAIN 保证最大不超过 1.0）
4. **钳位**：`clamp(raw[t], 0, 1)`
5. **重复** 12 通道 × 150 帧

### 4.3 人类特有的编译规则

详见 [`00_PAD情绪坐标.md`](合同/03_情绪坐标/00_PAD情绪坐标.md) §二 和 [`合同/04_通道编译/00_通道编译.md`](合同/04_通道编译/00_通道编译.md)。

关键人类规则：
- **eyebrow 滞后**：eyebrow 通道滞后 pupil 通道 8-15 帧（先验规则，非 PAD 属性）
- **blink 独立序列**：blink 由独立 spike 序列驱动，不直接跟随 E(t)
- **micro_jitter**：S6 先验层附加 1/f 粉红噪声微颤
