## 一、概述（What）

### 本文件用途

澄清 **PAD (Pleasure–Arousal–Dominance)** 在本项目中的**真实角色**：

- 它**是不是**「风格」？
- 它**是不是**「气质」？
- 它**是不是**提升表演的「关键」？

并给出 **对外推荐口径** 与 **禁止口径**。

### 一句话结论（先读这个）

> **PAD = 这种情绪的「脸性格坐标」（情绪气质），不是品种/人格那种「风格包」。**  
> **PAD 是表演成败的关键之一，但管的是「演成什么气质的脸」，不管「第几秒多用力」——后者是 macro/E(t)。**  
> 完整表演 = **节拍（E(t)）× 情绪气质（PAD）× 脸怎么吃戏（品种 style）× 物种补丁**。

### 管线位置

```text
SliderPacket
  │
  ├─ macro + hold_seg ──→ E(t)           ← 时间轴：多用力、何时峰、怎么收
  │
  ├─ emotion ──→ resolve_pad() → (P,A,D) ← 气质轴：各通道静态性格权重
  │                    ↓
  │              compute_pad_scale(ch) → pad_scale[12]
  │
  └─ breed/persona ──→ style.json        ← 风格轴：base_offset + scale_factor（S5）
         │
         ▼
    channels_from_envelope(E, pad_scale) → pulse
         │
         ▼
    apply_style_offset(pulse) → styled → 02 烘焙
```

### 管辖 / 边界

| ✅ 本文件管 | ❌ 本文件不管 |
|------------|--------------|
| PAD 三轴含义、与「气质」的关系 | macro/hold 如何算 E(t)（见专篇） |
| PAD 与「风格/品种/人格」的严格区分 | 12 通道名单与烘焙格式 |
| pad_scale 公式与权重表性质 | 工程底膜几何、扩散 Prompt |
| 「PAD 关键吗」的准确说法 | 客户门户是否展示 PAD 滑杆（产品缺口） |

### 对你那个说法的判定表

| 说法 | 判定 | 准确改法 |
|------|------|----------|
| PAD 是 **气质** | ✅ **基本对** | 说 **「情绪气质」** 或 **「脸性格坐标」**，比单说「气质」更准 |
| PAD 是 **风格** | ⚠️ **易错** | 本项目 **风格 = 品种/人格 style.json（S5）**；PAD 是 **情绪层**，不是贵宾/祭司那种风格包 |
| PAD **提升表演** | ✅ **对，但要限定** | PAD 决定「委屈 vs 凶狠」的 **读感差异**；不决定「5 秒节拍」 |
| PAD 是表演的 **唯一关键** | ❌ **错** | 缺 E(t) → 没节奏；缺 PAD → 节奏对但脸读错；缺 style → 同情绪不同品种脸吃不进去 |
| PAD 有 **心理学依据** | ✅ **对（三维）** | P/A/D 空间有文献；**落到 squint 的 Wp=0.35 是工程审定** |
| 客户日常 **拖 PAD 三根杆** | ❌ **当前不对** | PAD 随 **情绪预设** 定稿；C 端改 macro/选预设，不直接改 P/A/D |

## 二、理论依据（Theory）

### 2.1 PAD 从哪来（学术侧）

**依据链**：

```text
① Russell 环形情绪模型（1980）
   → 情绪可在「愉悦度 × 激活度」平面上定位

② Mehrabian & Russell 的 PAD 量表
   → 增加第三维 Dominance（支配/控制感）
   → 形成 (P, A, D) 三维空间，广泛用于情感计算、环境心理学、HCI

③ 本项目借用方式
   → 每种 **情绪预设** 占 PAD 空间中的一个 **点**（非常数曲面）
   → 该点不描述「时间」，只描述「这种脸整体偏压抑还是偏激活、偏压人还是偏退缩」
```

| 轴 | 符号 | 心理学含义（简化） | 本项目读感示例 |
|----|------|-------------------|----------------|
| **P** Pleasure | 愉悦度 | 正=偏愉快；负=偏不悦/压抑 | 委屈 P↓ → 偏湿、偏沉 |
| **A** Arousal | 激活度 | 正=高唤醒；负=低唤醒/软塌 | 威慑 A↑ → 眼动更急、睑更绷 |
| **D** Dominance | 支配度 | 正=压人/掌控；负=顺从/退缩 | 委屈 D↓ → 眯眼、上睑垂、不压人 |

**不是**：已发表的「PAD → 眼部 AU 标准系数表」；**Wp/Wa/Wd 矩阵是 🧠 项目标定**（读感验收 + 合同 CHECK）。

### 2.2 为什么需要 PAD 这一轴（和 E(t) 分开）

想象 **同一条 E(t) 曲线**（同样的起—盯—收节拍）：

| 若只有 E(t) | 观众仍会困惑 |
|-------------|-------------|
| 峰值时刻相同 | 「这是在委屈还是在生气？」 |
| 幅度相同 | 「为什么一个湿软、一个冷硬？」 |

**PAD 回答的是**：在 **相同时间强弱** 下，**十二路通道谁更亮、谁更压、谁更湿** —— 即 **静态性格配比**。

```text
pulse[ch, t] ≈ E(t) × pad_scale[ch] × 物种规则 × 情绪补丁
                    ↑
              PAD 只进这里（pad_scale），不进 E(t)
```

这与 [`08_架构与验收/人格品种与Et正交审计.md`](../../08_架构与验收/人格品种与Et正交审计.md) 一致：**换品种不改 E(t)**；**换情绪必换 PAD**（通常也换 macro）。

### 2.3 PAD vs 风格 vs 气质 — 三词在本项目的精确定义

| 术语 | 在本项目指什么 | 数据从哪来 | 改谁会变 |
|------|---------------|-----------|----------|
| **气质（情绪气质）** | 这种 **情绪** 的脸性格 | PAD (P,A,D) + 情绪特例补丁 | 换情绪预设 |
| **PAD** | 气质的 **可计算坐标** | `emotion_pad.EMOTION_PAD` / 预设 JSON `pad` 块 | 审定预设或代码表 |
| **风格（品种/人格）** | 这张 **脸** 怎么吃同一种戏 | `style.json` base_offset / scale_factor | 换 poodle_giant / 天选者 |
| **表演节奏** | 五秒 **多用力、何时峰** | macro + hold → E(t) | 拖宏观滑杆 / NL |

**记忆口诀**：

```text
E(t)  = 戏怎么动（时间）
PAD   = 戏像什么情绪（性格）
style = 谁的脸在演（脸框）
```

### 2.4 「气质」在成片里体现在哪

PAD **不直接画曲线**，而是给每条通道一个 **音量旋钮** `pad_scale[ch]`：

```python
pad_scale[ch] = base[ch] + P×Wp[ch] + A×Wa[ch] + D×Wd[ch]
```

例：委屈·幼犬眼 `(P,A,D)=(-0.35, 0.25, -0.55)` →

- P↓ → `eye_gloss` 权重路径偏「湿」方向（Wp 为正通道）
- D↓ → `squint`/`lid_upper` 偏「垂、缩、不压人」
- 再乘 **同一 E(t)** → 整段 5 秒都带「委屈脸」的配比，而非只在某一帧

**因此**：PAD 提升的是 **气质一致性** —— 全段读感像同一种情绪，而不是只有峰值那一帧像。

## 三、为什么这样做（Why）

### 3.1 「PAD 作为气质」——为什么说对

| 理由 | 说明 |
|------|------|
| 三维空间可解释 | 合同可写「偏不悦·略激活·偏退缩」，比 12 个 float 好审定 |
| 与节拍解耦 | 可独立验收「委屈的 PAD」而不动「盯 90 帧还是 110 帧」 |
| 跨通道联动 | 一改 P 可同时推高 gloss、压低「压人眉」——符合「脸是一个整体」的读感 |
| 学术背书 | 对外可说「基于 PAD 情绪坐标」；对内知映射系数要审定 |

**推荐对外句**：

> PAD 为每种情绪设定 **眼眉通道的气质权重**，让同一套表演节拍呈现不同的 **情绪读感**。

### 3.2 「PAD 作为风格」——为什么说错或不全

本仓库 **风格** 有 **专名**：

```text
styled = base_offset + scale_factor × pulse    # S5，style.json
```

| 若把 PAD 叫成「风格」 | 后果 |
|----------------------|------|
| 与 `05_风格化/` 品种 style 混淆 | 产品以为改 PAD = 改贵宾脸，实际改的是 **情绪** |
| 与「人格风格」混淆 | 人类「天选者_大祭司」是 style，不是 PAD |
| 合同无法分工 | 改一处牵动两处验收 |

**准确说法**：

- PAD → **情绪气质 / 脸性格**（emotion-level）
- style.json → **品种或人格风格**（face-level）

若口语非说「风格」，必须加定语：**「情绪风格」** 或 **「气质风格」**，并明示 **不是品种风格包**。

### 3.3 「PAD 是提升表演的关键」——对在哪里、错在哪里

**对的部分**：

| 没有 PAD 会怎样 | 有 PAD 会怎样 |
|----------------|--------------|
| 只有 E(t) 时，多情绪可能 **峰值时刻一样、幅度一样** | squint/gloss/lid 配比不同 → **一眼分出委屈/凶狠** |
| 扩散 Prompt 写「委屈」但通道像「怒视」 | 02 烘焙与 Prompt **气质对齐**，Wan 更稳 |
| 合同无法写「这种脸偏湿偏垂」 | `pad.position` 可人类可读验收 |

**错的部分（过度声称）**：

| 过度说法 | 纠正 |
|----------|------|
| 「PAD 决定表演节奏」 | ❌ 节奏是 **E(t) / macro** |
| 「PAD 决定品种差异」 | ❌ 品种是 **S5 style** |
| 「PAD 比 E(t) 更重要」 | ❌ **正交、缺一不可**；E(t) 没起势，PAD 再好也像「死脸」 |
| 「PAD 有医学验证的面部公式」 | ❌ 三维有依据；**权重表是工程标定** |

**准确说法**：

> PAD 是 **情绪气质层** 的关键；与 **表演节拍（E(t)）**、**脸框风格（style）** 并列，三者合成完整表演，不可互相替代。

### 3.4 历史教训

| ⚠️ 坑 | 规则 |
|-------|------|
| 「用 PAD 调节能量曲线」 | PAD **不进** `build_energy_envelope()` |
| 「PAD 就是风格包」 | 风格包 = `style.json`；PAD = 情绪表 |
| 「客户拖 PAD」 | 当前产品 **未暴露**；走预设审定 |
| 预设 JSON 有 `pad` 但运行时未加载 | `dog_packet_from_file` 等路径应以 **代码表 + JSON 一致** 为审定真源 |
| 只改 PAD 不改 macro | 可能「脸像委屈、节奏像施压」→ 读感冲突，需联合验收 |

## 四、怎么实现（How）

### 4.1 PAD 从哪来 — `resolve_pad()`

优先级（[`emotion_pad.py`](../../../gaze_engine/_shared/emotion_pad.py)）：

```text
1. SliderPacket.pad（若包内显式带 pad 且加载器写入）
2. EMOTION_PAD[emotion]（代码表）
3. (0, 0, 0) 中性
```

狗示例 — 委屈·幼犬眼：

```json
"pad": {
  "P": -0.35,
  "A": 0.25,
  "D": -0.55,
  "position": "偏不悦/压抑 · 激活中性 · 偏顺从/退缩"
}
```

### 4.2 PAD 如何变成 12 个系数

狗权重表 [`dog/pad_weights.py`](../../../gaze_engine/dog/pad_weights.py)：

| 通道 | 典型气质含义 | PAD 主要吃哪轴（启发） |
|------|-------------|------------------------|
| `eye_gloss` | 湿/干 | **P**（Wp=0.30） |
| `pupil_x/y`, `lid_upper` | 急/绷 | **A** |
| `squint`, `lid_upper` | 压人/退缩 | **D** |
| `eyebrow`（狗=耳位） | 顺/竖 | **D** + ear 并行 |

**整段合成（概念）**：

```text
S1  (P,A,D) = resolve_pad(packet)
S2  E(t)    = build_energy_envelope(macro, hold)     # PAD 不参与
S4  pulse   = channels_from_envelope(E, P, A, D)     # pad_scale 在此
S5  styled  = apply_style_offset(pulse, breed_style) # 品种，非 PAD
```

### 4.3 三层对同一帧的作用（数值故事）

固定 `t=50`（保持段），比较 **委屈** vs **凶狠**（宏观类似、PAD 不同）：

| 层 | 委屈·幼犬眼 | 凶狠·威吓 | 谁造成的差异 |
|----|------------|-----------|-------------|
| E(t) | ~0.10（低峰） | 可类似或更高 | macro |
| pad_scale[squint] | 较高（D↓ 路径） | 较低 | **PAD** |
| pad_scale[eye_gloss] | 较高（P↓ 但基线+补丁） | 较低 | **PAD** + 特例 |
| styled[blink] | 贵宾基线+scale | 同公式不同 style | **style** |

→ 观众说「这狗在委屈」：主要靠 **PAD 配比 + 湿润基线**；说「这是贵宾」：靠 **S5**。

### 4.4 与 macro 的分工（客户改什么）

| 想达到 | 改 | 不改 |
|--------|-----|------|
| 更可怜、更湿、更垂 | 审定 **PAD P↓、D↓** 或加深 `_apply_moist_sad_baseline` | 不要指望只改 macro.outro |
| 更久、更颤 | **steady/grip/hold_seg** | PAD |
| 贵宾 vs 田园同情绪 | **品种 style** | PAD、E(t) |
| 从委屈改凶狠 | **换情绪预设**（macro+PAD 一起换） | 只改一个通道帧 |

### 4.5 产品现状缺口

| 项 | 状态 |
|----|------|
| 预设 JSON / 情绪合同 | ✅ 有 `pad` 块 |
| 门户展示 PAD 三轴 | ❌ 未展示 |
| `01_滑杆包` 持久化 pad | ❌ 通常无 |
| 运行时加载 JSON pad | ⚠️ 部分路径只用代码表 |

**审定流程**：改 PAD → 同时改 **`03_情绪坐标/{物种}/{情绪}.md`** + **预设 JSON `pad` 块** + **`emotion_pad.py` 表**（保持一致）。

## 六、FAQ

**Q1：PAD 到底算不算「气质」？**  
**算**，但请说 **「情绪气质」** 或 **「脸性格坐标」**——指 **这种情绪** 在全段的通道配比，不是品种长相。

**Q2：PAD 能不能叫「风格」？**  
在本项目 **不推荐**。**风格** 已专指 `05_风格化` 的 breed/persona。若口语要用，说 **「情绪风格」** 并和品种 style 划界。

**Q3：没有 PAD，表演会不会「能看但不对味」？**  
**会。** E(t) 可能对，但 squint/gloss/lid 配比像错戏；扩散 Prompt 与 02 也会 **气质打架**。

**Q4：只有 PAD，没有 macro，行不行？**  
**不行。** PAD 是 **乘性权重**，E(t)≈0 时全通道接近无表演；且 **blink 等** 还依赖时间锚点（来自 E(t) 时轴）。

**Q5：PAD 和「5秒气质精品成片」是什么关系？**  
[`5秒气质精品成片合同`](../../08_架构与验收/5秒气质精品成片合同.md) 里的 **气质** = **styled 全链读感**，含 **E(t)+PAD+style+prior**；PAD 是其中 **情绪性格** 子层，不是全部。

**Q6：我想让委屈「更压抑一点」，改 PAD 还是 macro？**  
- **更压抑气质** → 审定 **PAD P↓**（合同/预设）  
- **更轻、更慢、更颤** → **macro/hold**  
- **贵宾脸更吃委屈** → **品种 style**
