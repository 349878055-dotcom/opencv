## 一、概述（What）— 先分清三套「数」

很多人把 **「6 根滑杆」「PAD 三维」「12 通道」** 说成一件事。在本项目里它们是**三层不同对象**：

| 名称 | 数量 | 存哪里 | 客户/门户能否直接改 |
|------|------|--------|---------------------|
| **宏观滑杆 `macro`** | 6 | `SliderPacket.macro` | ✅ 能（选情绪预设或以后做微调） |
| **盯住段 `hold_seg`** | 4 项 | `SliderPacket.hold_seg` | ✅ 能 |
| **PAD (P,A,D)** | 3 维 | 预设 JSON / `emotion_pad.py` | ⚠️ 合同定稿；门户**未展示、未编辑** |
| **能量曲线 E(t)** | 150 点 ×1 条 | **不存文件**，运行时算 | ❌ 只看（由 macro+hold 决定） |
| **12 通道 pulse** | 12 × 150 | `02_烘焙_*.json` | ❌ 出厂物，禁止手改 |

**12 通道**（狗/人/猫接口一致，语义因物种略异）：

`pupil_x`, `pupil_y`, `blink`, `eyebrow`, `pupil_scale`, `iris_scale`, `cornea_bulge`, `squint`, `brow_raise`, `lid_upper`, `lid_lower`, `eye_gloss`

> **重要**：文档里说的「12 维度」= **12 条动画通道**，不是 6+3=9 根滑杆，也不是 PAD 三维的扩展。

### 客户到底改哪一个？

```text
客户可编辑（唯一入口）          系统自动推导（不要让客户直接改）
─────────────────────          ─────────────────────────────
① 选情绪预设  → macro+hold      → E(t) 能量曲线
② 选品种/人格 → style.json       → PAD 常参与 resolve_pad(emotion)
③ 自然语言    → Pomot 微调 macro  → 12 通道 pulse → styled → 02 烘焙
④ 标定底膜    → 几何模板          → 与 E(t)/PAD 正交
```

**准确说法**（推荐对外）：

- 客户改的是 **「表演强度与节奏」**（6 macro + hold 花纹）和 **「选哪种情绪/品种」**。
- 客户**不是**在改 12 根通道滑杆；12 通道是 **编译结果**。
- PAD 是 **「这种脸的气质坐标」**，由情绪（+ 可选 JSON）定稿，**不是**客户每次拖的三根杆。

若旧文档写「用 PAD 调节 12 通道」——应改为：

> **「PAD 为每种情绪设定 12 通道的静态性格权重；时间上的强弱由能量曲线 E(t) 驱动。」**

## 二、理论依据（Theory）

### 2.1 两条正交轴（本架构的核心）

本项目的数学分工（全物种统一，见正交审计）：

| 轴 | 符号 | 管什么 | 不管什么 |
|----|------|--------|----------|
| **时间轴** | **E(t)** | 5 秒内 **多用力、何时起峰、盯住多久、如何收场** | 不区分「委屈」还是「凶狠」的静态脸型 |
| **气质轴** | **PAD** | 整段 5 秒内 **各通道相对强弱**（谁更眯、谁更亮） | **不**决定第几秒到峰 |

合成（概念式）：

```text
pulse[ch, t] ≈ f( E(t), pad_scale[ch], 物种规则[ch], 情绪特例[ch, t] )
```

其中 `pad_scale[ch] = base[ch] + P·Wp[ch] + A·Wa[ch] + D·Wd[ch]`（见 `compute_pad_scale`）。

**品种/人格**在 **S5** 再乘一次（不改 E(t)）：

```text
styled[ch, t] = clamp01( base_offset[ch] + scale_factor[ch] × pulse[ch, t] )
```

### 2.2 E(t) — 表演时间模型（有依据，非神经生理）

**依据类型**：戏剧 **节拍（beat）**、动画 **timing curve**、广告分镜 **起—持—收**。

- 四段：`蓄力 → 启动 → 保持 → 缓和`（约 150 帧 @ 30fps）
- `macro.push/power/speed` → 峰高与到峰时刻
- `macro.steady/grip` → 盯住段多「飘」还是多「钉死」
- `hold_seg.shape`（flat / tremble / pulse / …）→ 在平顶段上乘纹理（如委屈的 **tremble**）

**不是**：EEG/EMG 实测曲线、FACS 时间码的直接复刻。

**代码**：`build_energy_envelope()` — 分段 smoothstep + 保持段 `_hold_texture()`。

### 2.3 PAD — 心理学三维（有依据，映射系数是工程）

**依据类型**：

- **Russell** 环形情绪模型（愉悦度 × 激活度）
- **Mehrabian & Russell** 的 **PAD** 量表（加 **Dominance** 支配度）
- 在情感计算、人机交互文献中，用 P/A/D 描述刺激—情绪反应是常见做法

**本项目用法**：

- 每种情绪在 `emotion_pad.EMOTION_PAD` 或预设 JSON `pad` 块里有一对 **(P,A,D)**
- 通过 **线性权重表** `pad_weights` 变成 12 个 **标量** `pad_scale[ch]`

**不是**：已发表的「PAD → 眼部 AU47 系数」标准表；`Wp/Wa/Wd` 为 **🧠 项目标定**（合同审定 + 读感验收）。

### 2.4 12 通道 — 动画/面部动作语义（与 FACS 同向，未逐 AU 认证）

| 通道 | 近似语义 | 与 FACS / 行业概念 |
|------|----------|-------------------|
| pupil_x / pupil_y | 视线方向 |  gaze / eye look |
| blink | 眨眼 | AU45 家族（眨眼） |
| squint, lid_upper, lid_lower | 眯眼、睑裂 | AU7, AU1+2 等（仅启发） |
| brow_raise | 眉/眉脊 | AU1/2；狗上常映射耳位相关 |
| eye_gloss | 湿润高光 | 渲染层，非 FACS |
| eyebrow（狗） | **耳位** | 犬类耳向情绪信号（行为学） |

**行业对照**（见 §五）：游戏/影视多用 **blendshape 权重** 或 **ARKit/FACS AU**，本项目的 12 通道是 **「眼眉扩散控制专用抽象」**，比通用面部 rig **窄**，比纯 PAD **细**。

## 三、为什么这样做（Why）

### 3.1 不让客户直接改 12 通道

| 理由 | 说明 |
|------|------|
| 维度灾难 | 12×150=1800 个数无法人工调 |
| 可解释 | 客户懂「更委屈、更慢、盯久一点」，不懂 `squint[47]=0.31` |
| 可验收 | 滑杆有 L1 禁区；通道有平庸三检 |
| 与扩散分工 | 02 烘焙给 Wan 当 **控制视频**；语义在 Prompt |

### 3.2 为什么 PAD 不写进 E(t) 公式

若 PAD 进入 `build_energy_envelope()`：

- 换品种会改变 **时间节奏**（违反「贵宾 vs 田园同情绪同节拍」）
- 无法独立审定「这一情绪盯 90 帧还是 110 帧」

因此 **PAD 只调 `pad_scale[ch]`**，**E(t) 只由 macro/hold 决定**（审计结论 ✅）。

### 3.3 旧说法纠偏

| 旧/模糊说法 | 问题 | 推荐说法 |
|-------------|------|----------|
| 「用 PAD 调节能量曲线」 | ❌ PAD 不进 E(t) | PAD 调节 **通道静态权重** |
| 「PAD 调节 12 滑杆」 | ❌ 客户不拖 12 通道 | PAD 参与 **12 通道编译系数** |
| 「6 滑杆映射到 12 滑杆」 | ❌ 不是 1:1 映射 | **6 滑杆 → E(t) → 乘到 12 通道** |
| 「预设里有能量图」 | ❌ JSON 无 E(t) 数组 | 预设只有 macro/hold；**E(t) 现场计算** |

## 四、怎么实现（How）— 与当前代码逐步对齐

### 4.1 狗管线 S0～S7（门户委屈路径）

```text
S0  SliderPacket（情绪 JSON → macro/hold/ear；PAD 多由 emotion 解析）
      ↓ finalize_packet（L1）
S1  resolve_pad(pkt) → (P, A, D)
S2  build_energy_envelope(pkt) → E(t) 长度 150
S4  channels_from_envelope(pkt, E, P,A,D) → pulse 12×150
      + inject_ear（ear → eyebrow/brow_raise）
      + _dog_blink_series / _apply_moist_sad_baseline（委屈特例）
S5  apply_breed_style（poodle_giant 等；不改 E(t)）
S6  apply_dog_prior（叙事扫视等）
S7  fix_dog_pulse_quality
      ↓
    02_烘焙_狗律.json（1800 关键帧）
```

### 4.2 E(t) 怎么由 6 macro 算出（摘要）

实现：`envelope_compile._timing()` + `_peak_level()` + 分段填充。

| macro | 主要影响 |
|-------|----------|
| `speed` | `t_peak` 早晚（14～20 帧附近） |
| `power`, `push` | 峰高 `peak_level`（整体幅度） |
| `steady`, `grip` | 盯住平顶高度、是否易「泄」 |
| `outro` | 90 帧后快收 vs 慢收 |
| `hold_seg.shape` | 平顶段是否 tremble/pulse/swell |

**委屈·幼犬眼** 典型：`power=26` → 低峰；`steady=62,grip=68` → 较长盯住；`shape=tremble` → 保持段波纹。

### 4.3 PAD 怎么变成 12 个数（摘要）

```python
# gaze_engine/_shared/envelope_compile.py
pad_scale[ch] = base[ch] + P*Wp[ch] + A*Wa[ch] + D*Wd[ch]
```

狗表：`gaze_engine/dog/pad_weights.py` — `DOG_PAD_WEIGHTS`, `DOG_BASE_SCALE`。

**解析顺序**（`resolve_pad`）：

1. `packet.pad`（SliderPacket 从预设 JSON / Pomot 合成加载）
2. `EMOTION_PAD[emotion]`（代码表）
3. `(0,0,0)`

预设 JSON 里的 `pad` 块与代码表应一致；`dog_packet_from_file()` / `packet_from_acting_preset()` 经 `SliderPacket.from_dict()` 加载 pad。

### 4.4 E(t) × PAD → 12 通道（狗，`channels_from_envelope`）

对每一帧 `t`、每一通道 `ch`（简化，特例见代码）：

| 通道 | 合成方式（概念） |
|------|------------------|
| `pupil_x` | `sign * E(t) * pad_scale[pupil_x]`（sign 由 push 内收/外放） |
| `pupil_y` | `E(t) * pad_scale[pupil_y]` + 偏置 |
| `blink` | **独立事件序列**（锚在 t_peak、保持段），非纯 E(t) 乘积 |
| 多数其他 | `E(t-lag) * pad_scale[ch] * channel_gain[ch]` |
| 委屈情绪 | 保持段 **叠加** squint/lid/gloss 基线（`_apply_moist_sad_baseline`） |
| `eyebrow` 等 | **耳位** `ear` 注入，与 PAD 并行 |

因此：**不是** `channel[t] = E(t) * PAD` 一个公式打完；**E(t) 是主时钟，PAD 是每通道音量旋钮，还有情绪/物种补丁。**

### 4.5 门户客户路径（当前产品）

| 步骤 | 客户操作 | 触达的层 |
|------|----------|----------|
| ② 选情绪 | 点「委屈·幼犬眼」 | macro/hold（来自预设 API） |
| ② 能量图 | 看 SVG 脉冲（macro/hold 近似 E(t)） | PAD 在 `预设资产/情绪包/` JSON，门户/API 调取，**不在网页展示** |
| ③ Pomot | 写 NL | 可能改 macro；走全管线 |
| 保存 | 客户资料 | `01_滑杆包.json` **含 pad 块**（来自情绪包或 Pomot 合成） |

**现状（2026-05-28）**：PAD 真源 = `预设资产/情绪包/{species}/*.json` 的 `pad` 块；`/api/portal/presets` 返回 pad 供管线调取；C 端 UI 不展示三轴。

## 五、科学依据 vs 工程标定 vs 同行做法

### 5.1 一张总表（诚实分级）

| 设计元素 | 科学/学术依据 | 本项目性质 |
|----------|---------------|------------|
| 情绪用 P/A/D 描述 | ✅ PAD、VAD、环形模型 | 采用 |
| 5s 起—盯—收 包络 | ⚠️ 表演/动画时间设计 | 工程 + 戏剧 |
| macro 0–100 线性映射 | ⚠️ 可标定、可解释 | 工程 |
| pad_weights 矩阵 | ⚠️ 受 FACS/读感启发 | **工程审定（🧠）** |
| 委屈 tremble + 湿润基线 | ⚠️ 犬类表情常识 | 情绪特例 |
| 12 通道命名 | ⚠️ 对接渲染器/扩散 | 接口合同 |

**结论**：可以对外说 **「基于 PAD 气质模型 + 表演节拍能量包络」**；不宜说 **「经医学验证的 PAD→眼部肌肉公式」**。

### 5.2 同行 / 工业界常见做法

| 领域 | 做法 | 与本项目关系 |
|------|------|--------------|
| **游戏引擎** | Animation Blueprint：曲线驱动 blendshape；情绪常作 **参数化状态机** | 类似 **E(t) 主时钟**；少见让策划改 50×blendshape 逐帧 |
| **Apple ARKit** | 52 blendshapes + 可选 ARFaceAnchor | 通道更细；我们是 **眼眉子集** |
| **FACS / OpenFace** | Action Units 强度 0～1 | 我们是 **语义近似**，未做 AU 级回归 |
| **影视绑定** | 动画师打 **pose + 曲线** | E(t)≈master 曲线；PAD≈各属性 bias |
| **情感计算论文** | PAD/VAD 驱动 **全局脸部生成**（深度学习） | 我们用 **显式公式** 保可控、可合同验收 |
| **MetaHuman / 数字人 SaaS** | 情绪 preset + 强度 slider | 类似 **选情绪 preset = 选 macro 包** |

**差异点（本项目的坚持）**：

- **正交**：品种/人格 **不改** 节拍（E(t)），只改通道偏移（S5）。
- **可出厂**：输出 **02 烘焙** 给扩散引擎，不是仅预览 mesh。
- **双真源**：合同 md + 预设 JSON，而非纯黑盒模型。

### 5.3 若要对齐更「科学」的可行方向（未来，非现状）

| 方向 | 说明 |
|------|------|
| FACS 对照表 | 为每个通道写「主要 AU」对照，标注置信度 |
| 行为学引用 | 犬耳位、眯眼与恐惧/顺从文献（Lorenz、犬类沟通研究） |
| 用户研究 | 委屈 preset 的 AB 读感评分 ≥ 阈值 |
| 数据拟合 | 从参考视频反推 E(t) 与 pad_scale（`参考片反推规范` 旁路） |

## 六、案例：委屈·幼犬眼（狗）

### 6.1 输入（客户可见）

```json
"macro": { "push": 15, "power": 26, "speed": 22, "steady": 62, "grip": 68, "outro": 22 },
"hold_seg": { "shape": "tremble", "pulse_rate": 18, "pulse_depth": 22, "swell": 8 },
"pad": { "P": -0.35, "A": 0.25, "D": -0.55 }
```

### 6.2 分工

| 层 | 委屈上的效果 |
|----|--------------|
| **E(t)** | 低峰、较晚起、长保持、tremble 微颤、较快 outro |
| **PAD** | 偏压抑(P↓)、略激活(A+)、退缩(D↓) → squint/lid/gloss 权重组合偏「湿、垂、弱」 |
| **特例** | `_apply_moist_sad_baseline`：保持段额外眯眼与高光 |
| **ear** | 低垂耳角，不进 E(t) |
| **品种 S5** | 贵宾 `style.json` 叠加 base/scale，**同一 E(t)** |

### 6.3 客户改委屈「更重一点」应改什么

| 想达到的效果 | 应动 | 不应动 |
|--------------|------|--------|
| 更久、更颤 | `steady`↑、`hold_seg.pulse_depth`↑ | 不要手改 `squint[帧]` |
| 更可怜、更湿 | 审定 **PAD P↓** 或加深湿润基线（工程） | 不要改品种改变 E(t) 长度 |
| 更快抬头看 | `speed`↑ 或 NL「猛地回头」 | 不要只改 `eye_gloss` 一轨 |

## 八、FAQ

**Q1：6 根滑杆和 12 通道有没有一张对照表？**  
没有 1:1 表。6 根 → **一条 E(t)**；PAD + 物种规则 → **12 个缩放与补丁**；再逐帧合成。

**Q2：客户改 PAD 吗？**  
当前产品 **不改**。PAD 随 **情绪预设** 定稿；若要做「更压抑一点」，应走 **审定预设** 或 **macro/NL 微调**，而不是三个 PAD 滑杆（除非产品新增）。

**Q3：能量曲线存盘吗？**  
可选导出 `export_envelope_series()`；预设资产 **不存** E(t) 数组。门户图是 **实时画** 的。

**Q4：为什么说 PAD 有心理学依据但仍要「审定」？**  
三维空间有依据；**落到 squint 的 Wp=0.35** 是本项目标定，需读感与合同 CHECK。

**Q5：人和狗一样吗？**  
**分层相同**（E(t) + PAD + S5 + prior）；**权重表、特例、eyebrow 语义** 不同（狗 eyebrow=耳位）。
