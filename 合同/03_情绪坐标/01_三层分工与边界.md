## 一、概述（What）

### 本文件管什么

只讲 **三个旋钮** 的分工 —— 整个项目里最容易混的三件事：

| 旋钮 | 一句话 | 不是什么 |
|------|--------|----------|
| **macro**（+ hold_seg） | **这一类戏演多重、何时用力** | ❌ 不是 PAD；❌ 不是贵宾/人格 |
| **PAD** | **是哪一类戏**（委屈 / 愤怒 / 悲伤…） | ❌ 不是表演力微调；❌ 不是 style |
| **style** | **这张脸怎么吃戏**（贵宾 / 祭司 / 田园…） | ❌ 不是情绪大类；❌ 不是 PAD |

### 定稿口诀（推荐背这个）

```text
macro  →  这一类戏「演多重」（表演力 · 微调）
PAD    →  「是哪一类戏」（情绪大类 · 非微调）
style  →  「谁的脸在吃戏」（脸框 · 品种/人格）
```

再补半句（防二次误解）：

```text
编译时：macro → PAD 展开 → style 叠加（有先后顺序）
播放时：每一帧三层同时在（没有「前几秒只 macro」）
```

## 二、理论依据（Theory）

### 2.1 为什么要拆成三层（而不是一个大「表演力」）

```text
① 人话里「更用力」和「更委屈」是两句不同的话
   → 更用力 = 幅度/节奏（macro）
   → 更委屈 = 换情绪大类（PAD + 通常也换 macro 默认值）

② 同一句「委屈」，贵宾和田园应是同戏不同脸
   → 情绪 JSON 全品种共用；品种用 style 偏移

③ 扩散 02 要同时表达「节奏 + 读感 + 脸框」
   → 一层旋钮调不动全部，硬合并必糊涂
```

### 2.2 用「力」的比喻（入门用，非物理公式）

| 概念 | 对应层 | 比喻 |
|------|--------|------|
| **多大力、何时推** | macro → E(t) | 推杆的 **幅度与时间** |
| **推出去像推人还是像撒娇** | PAD | 力的 **方向 / 通道分配** → 愤怒 vs 委屈 vs 悲伤 |
| **同样的推，大脸小脸、半阖全睁** | style | **脸框** 怎么吃这份 pulse |

**PAD 不是把 power 从 26 调到 30** —— 那是 macro 微调。  
**PAD 是**：同样 E(t) 下，squint、gloss、lid **谁多谁少**，观众才读出 **大类**。

### 2.3 「大分类」和「微调」在产品里各是什么

| 类型 | 是什么 | 客户怎么操作 |
|------|--------|--------------|
| **大分类** | 委屈 / 凶狠 / 满足 …（10～16 种预设） | 点左侧 **情绪预设** → macro + PAD **打包切换** |
| **微调** | 同类戏里更重、更慢、更颤 | 拖 **power / speed / grip** 或 Pomot NL |
| **脸框** | 贵宾 / 人格 / 猫种 | 选 **品种或人格** → 只动 style |

⚠️ **当前产品**：客户 **不拖 PAD 三根轴**；PAD 随预设定稿，走合同审定。

### 2.4 三个最容易混的词

| 词 | 在本项目指 | 常见误用 |
|----|-----------|----------|
| **情绪** | 预设包 = macro + PAD + ear… | 误当成 style |
| **气质** |  mostly PAD 那一层 | 误当成 macro 表演力 |
| **风格 / 人格化** | style.json（S5） | 误当成 PAD 或情绪 |

## 三、为什么这样做（Why）

### 3.1 为什么总把 PAD 当成表演力（历史心魔）

| 混淆来源 | 真相 |
|----------|------|
| PAD 也叫「三维」「scale」 | 那是 **通道权重**，不是 macro 的 0～100 滑杆 |
| 选情绪后曲线全变 | 因为 **macro 和 PAD 一起换**，不只 PAD |
| 文档写「PAD 调节通道」 | 调节的是 **像哪种情绪**，不是 **何时峰值** |
| 早期口语「气质=表演」 | 合同已拆层：气质≈PAD，表演力≈macro |

### 3.2 关键决策（入门版）

| 决策 | 为什么 |
|------|--------|
| PAD 不进 E(t) | 换大类不应意外改掉「第几秒到峰」 |
| style 在 pulse 之后 | 同一份委屈 pulse，贵宾/田园 **各吃各的** |
| 一种情绪一份 JSON | 改委屈一处，N 个品种 **自动跟上** |
| PAD 不给 C 端微调 | 大类靠 **选预设 + 审定**；微调靠 macro |

### 3.3 反例：若 PAD = 表演力会怎样

| 做法 | 后果 |
|------|------|
| 用 PAD 拉「更用力」 | 通道配比乱 → **像错戏**，峰值时刻却不变 |
| 用 style 换「委屈→愤怒」 | 只有脸基线变，**大类读感不变** |
| 删掉 PAD 只留 macro | 节奏对，**分不清委屈和怒** |

## 四、怎么实现（How）

### 4.1 公式一行版（对照口诀）

```text
E(t)           = f(macro, hold_seg)                    # ① 表演力
pad_scale[ch]  = base + P·Wp + A·Wa + D·Wd             # ② 大类
pulse[ch,t]    ≈ E(t) × pad_scale[ch] × …              # ①+②
styled[ch,t]   = base_style[ch] + scale_style[ch]×pulse  # ③
```

### 4.2 门户操作 → 动哪一层

| 客户操作 | 动到的层 | 大分类还是微调 |
|----------|----------|----------------|
| 点「委屈·幼犬眼」 | macro + PAD（+ ear） | **大分类** |
| 点「凶狠·威吓」 | macro + PAD | **大分类** |
| 拖 power / speed | macro → E(t) | **微调** |
| 写「更颤一点」 | macro / hold（经 Pomot） | **微调** |
| 选「巨型贵宾」 | style（S5） | **脸框**（大类仍是委屈） |

### 4.3 改需求时找对人、找对文件

| 需求 | 改 | 不要改 |
|------|-----|--------|
| 委屈和愤怒要更好区分 | 各情绪 **PAD** + 读感合同 | 只改 style |
| 委屈整体更轻、更慢 | **macro** | PAD（除非审定换大类气质） |
| 贵宾所有情绪都更半阖 | **poodle style** | 委屈 JSON |
| 参考照与骨架解剖配准（眼距/眼位） | [`底膜模板选择与标定专篇.md`](../07_工程底膜/底膜模板选择与标定专篇.md) · 门户 upload/calibrate | macro/PAD/style |
| 客户想「眼睛大一点」美颜 | ❌ **禁止** | 一切层 |

### 4.4 算例：贵宾 × 委屈（串三层）

| 步骤 | 值 | 层 |
|------|-----|-----|
| power=26, tremble… | → E(t) 低峰、长保持 | ① macro |
| P=-0.35, D=-0.55 | → squint/gloss 偏湿垂 | ② PAD 大类=委屈 |
| pulse[blink]≈0.12 | ①+② 合成 | pulse |
| base=0.55, scale=0.25 | → styled[blink]≈0.58 | ③ 贵宾脸 |

换 **凶狠** preset：② 变（大类变），① 往往也变 → pulse 整条变；③ 不变则贵宾仍比田园更半阖。

### 4.5 编译顺序 vs 播放顺序（再强调）

```text
【编译顺序 · 有先后】
  S2 E(t)  →  S4 pulse(含PAD)  →  S5 styled(含style)

【5 秒里每一帧 · 无先后】
  第 50 帧同时呈现：此刻多大力 + 像委屈 + 贵宾半阖
```

### 4.6 客户输入 · 一句版 · 依据分级

**客户只选两样**（PAD 不单独选）：

```text
① 情绪 preset  →  内含 macro + hold + 固定 PAD
② 品种/人格 style（可选）
```

**编译一句版（工程）**：

```text
E(t)=f(macro) → pulse=f(E, PAD_preset) → styled=f(pulse, style) → 12×150 → 02_烘焙
```

**产品一句版**：

> 客户选哪种 **戏（情绪）** 和哪张 **脸（style）**；戏里自带 **节拍 + PAD 大类**；系统合成 **5 秒 150 帧 × 12 通道** 控制曲线。

| 设计 | 有依据吗 | 性质 |
|------|----------|------|
| 情绪用 P/A/D | ✅ PAD 心理学文献 | 采用 |
| 每种情绪固定 PAD | ✅ 离散情绪坐标常见 | 数值 🧠 审定 |
| macro / PAD / style 分层 | ✅ 节拍 vs 大类 vs 脸框 | 工程 + 正交审计 |
| 150 帧 @ 30fps | ✅ Wan / 全链路合同 | 工程约束 |
| pad_weights、通道→AU 对照 | ⚠️ 读感/FACS **启发** | **非 AU 回归、非医学公式** |

## 五、150 帧之后 · AU 用不用？

### 5.0 边界（和 macro/PAD/style **无关**）

文档里偶现 **AU / FACS**（如 blink≈AU45、squint≈AU7）——那是 **命名对照、读感启发**，**不是** 编译链的下一步。

```text
【本栈终点 · 眼眉控制抽象】
  macro + PAD + style  →  styled 12×150  →  02_烘焙_*.json

【150 帧之后的下游 · 无 AU 环节】
  02_烘焙
      ├─→ 07_工程底膜.mp4     （OpenCV 线条图 · 像素控制）
      ├─→ 04_Prompt.txt       （语义 · 情绪/节拍文案）
      ├─→ 05_扩散节拍表（可选）
      └─→ Wan 扩散 I2V        （02 + 03 + 04 一起送）
              ↓
          成片 MP4（5s）
```

| 问题 | 答案 |
|------|------|
| AU 是 150 帧后的下一步吗？ | **❌ 不是**；当前 **没有** AU 检测/转换/驱动代码 |
| AU 和 macro/PAD/style 有关吗？ | **❌ 无编译关系**；仅合同里「通道语义≈某 AU」作 **对照表** |
| 02 里是 AU 吗？ | **❌**；是 **12 条项目自定义通道**（pupil_x, squint…），不是 OpenFace 的 AU1～AU46 |
| 以后会用 AU 吗？ | **可选方向**（见 [`03_12通道映射与编译链.md`](03_12通道映射与编译链.md) §5.3「FACS 对照表」），**非现状** |

**一句边界**：

> **macro/PAD/style 编的是「12 通道 150 帧」；AU 只是帮助理解通道含义的注释，不参与这一步，也不参与 Wan 出厂链。**

详见：[`00_从门户到扩散_管线总览.md`](../00_管线导读/00_从门户到扩散_管线总览.md) · [`扩散输出流程专篇.md`](../08_输出与扩散/扩散输出流程专篇.md)

## 七、FAQ

**Q1：我总算明白了 PAD，还要读四层栈吗？**  
本文够 **日常产品和审定**；要改代码、写验收、抠品种合成时再读 [`04_四层表演栈与style边界.md`](04_四层表演栈与style边界.md)。

**Q2：emotion、气质、风格三个词怎么记？**  
**情绪 preset** = 大包（macro+PAD）；**气质** ≈ PAD 层；**风格** = style 脸框。

**Q3：PAD 能微调「稍微更压抑一点」吗？**  
**工程上可以** 审定 P↓；**产品默认不行** —— 客户用 preset 或 macro，不拖 PAD 轴。

**Q4：为什么选情绪 macro 也会变？**  
大类不是只有 PAD：「委屈」默认就是 **轻、慢、颤**，macro 和 PAD **打包设计**，不是矛盾。

**Q5：每种情绪的 PAD 是固定值吗？**  
**是。** 随 preset 定稿；客户换 preset = 换 macro+PAD 大包，不单独改 PAD。

**Q6：150 帧出来之后还要过 AU 吗？**  
**不用。** 下一步是 **02→03 底膜 + 04 Prompt→Wan**；AU 仅文档对照，见本文 §五。

**Q7：整个流程理论上有依据吗？**  
**架构有**（PAD 文献 + 表演节拍 + 正交合成）；**具体数字要审定**，不是整表来自论文或 AU 仪器。
