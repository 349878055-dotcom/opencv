## 一、概述（What）

### 本文件管什么

**风格化偏向** = 给 **12 条通道** 各配一组 **脸框参数**，把已经编好的 **情绪 pulse**「装进某张脸 / 某个人格」里。

| 物种 | 合同叫法 | 资产 id 示例 | 客户感知 |
|------|----------|--------------|----------|
| 人 | **人格** / 人格化 | `魅惑者_温碧霞` | 像不像这个演员的脸感 |
| 狗 | **品种** | `poodle_giant` | 贵宾 vs 田园 |
| 猫 | **品种** | `british_cat` | 英短 vs 暹罗 |

**三物种同一公式、同一层（S5）**，下文以 **人·魅惑** 举例，狗贵宾同理。

### ⚠️ 先答最糊涂的点：一套还是多套？

**结论：每个人格 / 每个品种 = 全局一套偏移，不是每种情绪单独一套。**

```text
                    不是 144 份 style（16情绪×9人格）
                    而是  16 份情绪  +  9 份人格

  魅惑·勾人.json ──┐
  委屈·…    .json ──┼──→ pulse（各不同）──┐
  …共 16 个         │                      │
                    │                      ├──× 同一套 温碧霞 base/scale ──→ styled
  温碧霞 style.json ┘（12 通道各 1 个 base + 1 个 scale，与情绪无关）
```

| 问题 | 答案 |
|------|------|
| 温碧霞有没有「魅惑专用偏移」和「委屈专用偏移」？ | **❌ 没有**；只有 **一份** `魅惑者_温碧霞/style.json` |
| 换情绪、不换人格，base/scale 变吗？ | **❌ 不变** |
| 换人格、不换情绪，base/scale 变吗？ | **✅ 变**（换成另一份 style.json） |
| 「最后各自调整」指什么？ | **编译时** 对 150 帧 **逐帧** 算 `base+scale×pulse`，**没有**第三份「组合微调 JSON」 |
| 16×9=144 种组合怎么来的？ | **数学组合**：同一人格参数 × **不同** pulse → **144 条不同** styled 曲线，**不是** 144 套参数文件 |

**记忆**：人格 style = **脸的全局滤镜**；情绪 = **片源内容**。滤镜不随片源换档，片源换、滤镜不变。

### 资产数量表（人 · 现状）

| 类型 | 几份 | 举例 |
|------|------|------|
| 情绪 preset | **16** | `魅惑·勾人.json` … |
| 人格 style | **9** | `魅惑者_温碧霞/style.json` … |
| 情绪×人格 组合参数文件 | **0** | 💥 **禁止** `温碧霞_魅惑.json` 这种 |
| 出厂 styled 曲线 | **16×9=144 种可能** | 运行时算出来，一般不逐个存盘 |

狗同理：**10 情绪 × N 品种**，品种 each **1 份** style，**不是** 10×N 份。

### 一句话

> **情绪写「这场媚戏怎么演」（一份 JSON 全员共用）；风格化偏向写「林青霞的脸和温碧霞的脸怎么吃同一场媚戏」（各一份 style.json）。**

### 「耦合」到底是什么意思（先读这个）

**不是** 把两个 JSON 合并成一个文件。  
**不是** 改情绪 macro 来区分演员。  
**是** 对 **每一帧、每一通道** 做一次 **固定数学叠加**：

```text
styled[ch, t] = clamp01( base_offset[ch] + scale_factor[ch] × pulse[ch, t] )
```

| 符号 | 从哪来 | 会不会随帧变 |
|------|--------|--------------|
| `pulse[ch,t]` | 情绪 preset（macro+PAD→编译） | ✅ 150 帧曲线 |
| `base_offset[ch]` | 人格 style.json | ❌ 常数（这张脸的「默认妆」） |
| `scale_factor[ch]` | 人格 style.json | ❌ 常数（这张脸「吃动多大」） |
| `styled[ch,t]` | 耦合结果 | ✅ 150 帧 · **02 出厂值** |

**耦合** = **pulse 已知后，用 base+scale 逐帧算出 styled**。

### 边界

| ✅ 本文件管 | ❌ 不管 |
|------------|--------|
| base / scale 含义、怎么定 | macro / hold / PAD（见 01 专篇） |
| 情绪 × 人格 **组合** 规则 | LLM Prompt 全文 |
| 林青霞 vs 温碧霞 **工程拆法** | 换脸 Deepfake / LoRA 训练 |
| 怎么写一份新 style.json | 单通道 AU 回归 |

## 二、理论依据（Theory）

### 2.1 为什么要有「风格化偏向」这一层

```text
① 同一套「魅惑·勾人」戏眼语法，不应为每个演员复制 16 份情绪 JSON
   → 改媚戏节奏只改 1 处，所有人格自动继承

② 演员差异主要是「脸默认状态 + 动幅习惯」，不是另一种 E(t) 时间轴
   → 林青霞冷媚 vs 温碧霞流转：同 pulse 相位，不同 base/scale

③ 合成必须可叠加、可验收
   → 线性 base + scale×pulse；改情绪不动 style；改人格不动情绪 JSON
```

### 2.2 base_offset vs scale_factor（工程必懂）

用 **眨眼 blink** 举例：

| 参数 | 含义 | 观众读感 |
|------|------|----------|
| **base_offset[blink]** | 即使 **pulse≈0**（不动）时，这条通道的 **默认水平** | 「平时眼睛开多大 / 多半阖」 |
| **scale_factor[blink]** | 情绪 pulse **动 1 单位**，这张脸 **放大多少** | 「媚起来眨得猛不猛」 |

```text
styled[blink, t] = base + scale × pulse[blink, t]

温碧霞式：base=0.5, scale=0.75  → pulse 一动，眨幅大（眼波流转）
冷媚式：  base=0.45, scale=0.35  → 同样 pulse，眨幅小、更「钉」
```

**12 通道各有一对 (base, scale)**，不是全局一个数。

### 2.3 三层别混（再对照）

| 层 | 林青霞 vs 温碧霞 **谁负责** |
|----|---------------------------|
| **情绪** `魅惑·勾人` | **同一套** macro/hold/PAD → **同一条 pulse**（若客户不另拖滑杆） |
| **PAD** | **相同**（都跟情绪 preset） |
| **风格化偏向** | **不同** style.json → **不同 styled** |
| **E(t) 节拍** | **相同**（正交审计） |

若两人「媚感」差异主要在 **节奏**（一个慢勾、一个猛一眼）→ 那是 **不同情绪**（如 `魅惑·勾人` vs `媚杀·一眼`），**不是** style  alone。

### 2.4 项目内「林青霞」说明（避免选错层）

[`滑杆规范.md`](../01_输入与收口/滑杆规范.md) 里 **「林青霞那种瞪人」** 映射的是 **`施压·凝视` + 高 power/speed**，**不是** `魅惑·勾人`。

| 用户口语 | 工程上更可能 |
|----------|--------------|
| 林青霞 **瞪人 / 压人** | 情绪=`施压·凝视` + 人格=`天选者_大祭司` 等冷硬人格 |
| 林青霞 **东方不败式冷媚** | 情绪=`媚杀·一眼` 或 `魅惑·勾人` + 人格=`魅惑者_林青霞`（**🧠 待建**） |
| 温碧霞 **流转勾人** | 情绪=`魅惑·勾人` + 人格=`魅惑者_温碧霞`（**已有资产**） |

本文 **「同媚不同脸」** 案例默认：**同一情绪 `魅惑·勾人`**，只换人格 style。

### 2.5 风格化结构的科学依据（比项目文档更准）

> 本节回答：**「1 人格 1 套 base/scale、全局通吃 16 情绪」有没有学术/工业依据？更严谨的结构长什么样？**

#### 2.5.1 诚实分级总表

| 设计元素 | 学术/工业依据强度 | 说明 |
|----------|-------------------|------|
| **表演 vs 身份/脸 分离** | ✅ **强** | 3D 人脸、FACS、动画工业共识 |
| **表情 = 可迁移的 performance；脸 = identity/style** | ✅ **强** | FLAME / 3DMM / 表情迁移论文 |
| **静息脸偏置 + 动态增益** | ✅ **中强** | blendshape 中性态 + 权重；个体 expressivity 差异 |
| **仿射式** `base + scale×signal` | ✅ **中** | 线性 blendshape 假设的一阶近似 |
| **全局 1 套 style、不随情绪换档** | ⚠️ **工程近似** |  retargeting 文献常用；真人跨情绪 expressivity 略变，本项目 **故意忽略** 以换可维护 |
| **12 通道抽象 ≠ 全 AU 基** | ⚠️ **工程接口** | 比 FACS/ARKit **窄**；AU 仅启发命名 |
| **温碧霞 base/scale 具体数字** | 🧠 **读感审定** | **非** EMG/OpenFace 回归真值 |

**对外可以说**：「基于 **身份–表情解耦** 的线性 retargeting」  
**不宜说**：「经 FACS 仪器标定的个人 AU 矩阵」

#### 2.5.2 学术依据链（与本文结构对齐）

```text
① 3D Morphable Model / FLAME（计算机视觉 · 图形学）
   脸 ≈ 均值形状 + 身份系数 z_id + 表情系数 z_exp
   → 表情流形与身份流形 **分开参数化**
   → 本项目：pulse ≈ z_exp 时间序列；style ≈ 眼眉子空间上的 identity 偏置

② Identity–Expression Disentanglement（近年 3D/4D 人脸论文）
   目标：同一套 expression/performance 可迁到不同 identity
   → 支持「16 情绪共用、9 人格各一套」**不是拍脑袋**，是 retargeting 范式

③ FACS / Action Units（Ekman 系 · 行为面部编码）
   AU 强度 = **表情**；脸型、静息态 = **非 AU 层**
   → 12 通道是 AU 的 **粗粒度投影**，不是 46 AU 完备基

④ 个体表达力差异（心理学 · expressivity）
   同刺激下，有人动幅大、有人动幅小；静息脸亦不同
   → base ≈ 静息/默认脸偏置；scale ≈ **per-channel expressivity gain**
   （参见 facial expressivity individual differences 一类研究）

⑤ 戏剧/表演：「同一剧本、不同演员脸」
   戏眼语法（情绪 preset）可共享；演员气质 = 脸怎么吃戏
   → 与 product 层「16 情绪 + 9 人格」一致（表演学支撑，非生理公式）
```

**参考文献方向（检索用，非本项目真源）**：

| 领域 | 关键词 |
|------|--------|
| 3D 脸 | FLAME, 3DMM, `S = S̄ + B_id·α + B_exp·β` |
| 解耦 | identity-expression disentanglement, expression transfer |
|  stylized AU | AU-Blendshape, AUBlendSet（**每 identity 一套 stylized AU 基** — 与「1 人格 1 套」同向） |
| 工业 | ARKit blendshapes, MetaHuman DNA, rig neutral + animation curves |

#### 2.5.3 本项目公式在学术坐标系里是什么

**本项目（眼眉 12 通道）**：

```text
styled[ch, t] = base_offset[ch] + scale_factor[ch] × pulse[ch, t]
```

**FLAME / blendshape（全脸，概念对照）**：

```text
vertex(t) = neutral_mesh + Σ_k  w_k(t) · blendshape_delta_k
            ↑ identity/neutral     ↑ performance / expression
```

| 本项目符号 | 近似学术含义 |
|------------|--------------|
| `pulse[ch,t]` | 表情/performance 在 **通道 ch** 上的强度（已含 E(t)+PAD） |
| `base_offset[ch]` | 该 identity 在 **静息/低表情** 时通道 ch 的偏置（neutral bias） |
| `scale_factor[ch]` | 该 identity 对通道 ch 的 **表达增益**（expressivity / rig gain） |
| **对角 scale**（逐通道独立） | 完整 retarget 应是矩阵 **M×pulse**；对角是 **可维护的一阶近似** |

**「1 人格 1 套、16 情绪共用」在文献里对应**：

- **Identity-agnostic performance**：performance 码与 identity 码分开（如 ETH 2022 面部 performance 编码思路）
- **Expression retargeting**：同一 performance 曲线，乘/加到不同 rig 上
- **不是** 每个 (identity, emotion) 一对独立参数 — 那是 **过拟合表格**，无法「改情绪一处全人格跟上」

#### 2.5.4 更严谨的结构长什么样（对照 · 未来可选）

若要对齐 **更学术/更细** 的结构，优先级如下（**均非现状**）：

| 层级 | 更严谨结构 | 本项目现状 | 何时值得做 |
|------|------------|------------|------------|
| **L0 几何** | FLAME/身份 mesh + 身份 blendshape 基 | `template_scales` + 底膜标定 | 全脸而不仅是眼眉 |
| **L1 风格** | 每 identity：**向量 base** + **矩阵 M**（12×12 弱耦合） | **对角** base+scale | 某两人格 crosstalk 严重 |
| **L1b 风格** | 每 identity：**32 stylized AU 基**（AUBlendSet 思路） | 12 通道抽象 | 要对齐 FACS 级 stylization |
| **L2 情绪×身份** | 少量 **交互项** `γ_emotion·pulse` | ❌ **禁止** | 仅当全局 style 不够且愿牺牲正交 |
| **L3 标定** | 参考片 → OpenFace AU → 回归 base/scale | 🧠 旁路 [`参考片反推规范.md`](../07_输出与扩散/参考片反推规范.md) | 有实拍标定需求 |

**推荐结构（审定用 · 当前代际）**：

```text
style.json（每人格 1 份，全局）
├── base_offset[12]     ← 静息脸 / 默认妆（identity bias）
├── scale_factor[12]    ← 各通道 expressivity（diagonal gain）
├── template_scales?    ← 几何（并行，非 styled 公式内）
└── 禁止 emotion_overrides{...}   ← 会破坏 16 情绪共用
```

这与 **AUBlendSet「每主题一套 stylized AU 基」**、**FLAME「identity + expression 分开」** 同 **分层哲学**；差别在维度（12 vs 46+）和标定方式（读感 vs 扫描）。

#### 2.5.5 和 PAD、macro 的边界（避免重复造「科学层」）

| 层 | 学术近似 | 管什么 |
|----|----------|--------|
| macro / E(t) | performance **timing** / effort | 何时、多大力 |
| PAD | emotion category in **PAD/VAD 空间** | 哪类情绪、通道配比 |
| **style** | **identity / rig personalization** | 谁的脸、静息态、动幅习惯 |
| 几何 template | **identity shape** | 眼型大小、耳位结构 |

**PAD 不是 style**：PAD 随 **情绪 preset**；style 随 **人格/品种 id** — 这在学术上对应 **expression 语义** vs **identity/rig**，不应合并。

#### 2.5.6 非 3D 路线：OpenCV 底膜 + Wan 扩散（本项目选型 · 必读）

> **背景**：曾评估完整 3D（mesh / FLAME / 3D 渲染 + 扩散）→ **3D 渲染与扩散均耗时过长**，故 **否定全 3D**，采用 **OpenCV 线条底膜 + 02 控制 + Prompt + Wan**。  
> **兄弟**：[`工程底膜合同.md`](../06_工程底膜/工程底膜合同.md) · [`扩散Prompt全链路方案_导读.md`](../08_架构与验收/扩散Prompt全链路方案_导读.md)

**Wan 实际吃什么（与 3D 无关）**：

```text
① 06_工程底膜.mp4   OpenCV 三色线条（R眼 G眉/耳 B瞳孔）← 02 驱动，非 mesh 渲染
② 04_Prompt.txt     情绪词 + 从 02 编译的节拍说明书 + 叙事
③ start_image       客户参考图（身份长相主要靠此 + 扩散，非 FLAME）
```

**分工（谁做「大部分工作」）**：

| 环节 | 谁做 | 和 3D 方案对比 |
|------|------|----------------|
| 真实毛发、皮肤、光影、像不像客户脸 | **Wan 扩散** | 3D 里本由渲染器+材质做 |
| 眼眉 **几何往哪动、何时动** | **02 十二通道 + 03 线条** | 3D 里本由 rig 骨骼/blendshape |
| 演什么 **情绪、节奏** | **macro/PAD → pulse** | 概念相同，实现不同 |
| 品种/人格 **怎么吃同一份 pulse** | **style base/scale → styled** | 概念相同，**不是** mesh 换肤 |
| 眼型、耳位粗调 | **template_scales + 客户标定** | 轻量几何，**不是** 全脸 3D |

**因此：不用 3D，可以 **整类不考虑** 的东西**：

| ❌ 本项目不做 | 说明 |
|-------------|------|
| FLAME / 3DMM **mesh 与顶点** | 无 3D 网格管线 |
| 3D **渲染器**出控制图 | 用 **OpenCV** 画 03 MP4 |
| AUBlendSet 式 **32 stylized AU 三维基** | 3D 动画工业向；你是 **12 通道 2D 抽象** |
| mix_matrix 作为 **3D retarget 必备** | **非必备**；仅 02 联动修不好时再议 |
| OpenFace AU **驱动主链** | Wan 不读 AU；AU 最多当 **文档/Hints** |

**不用 3D，仍然 **必须保留** 的东西**（和扩散分工有关）**：

| ✅ 仍要做 | 原因 |
|----------|------|
| **style.json：base + scale（12 行表）** | 决定 **02 数值** → 03 线条动法 + 05 节拍表；扩散 **跟 02 走**，不替你算节奏 |
| **情绪 preset（macro/PAD）** | 02 的「片源」；扩散 **不猜** 第几秒该起峰 |
| **04 Prompt + DIFFUSION_HINTS** | 告诉 Wan **语义**（委屈/湿润）；MP4 只有线没有词 |
| **客户参考图** | **身份脸**主要靠 I2V + 参考，不是 style  alone |

**§2.5 里 FLAME/矩阵/AU 文献**：指 **分层思想**（脸 vs 戏）可借鉴；**不是** 让你上 3D。  
**当前代际定稿**：**v1 base/scale 表 + 02 + OpenCV 03 + 04 → Wan**；矩阵/AU 表 **P2 可选**，**不等于** 做 3D。

```text
【否定】全 3D 渲染链
【采用】pulse/style → 02 → OpenCV MP4 ──┐
         Prompt 说明书 ─────────────────┼→ Wan（外观与质感主战场）
         客户参考图 ────────────────────┘
```

## 三、为什么这样做（Why）

### 3.1 「耦合」不是混文件，而是 **乘法+偏置**

| 误解 | 正解 |
|------|------|
| 温碧霞 = 魅惑 JSON 里多加几个字段 | ❌ 情绪 JSON **不含** 人格 |
| 选温碧霞 = PAD 变了 | ❌ PAD **只看情绪名** |
| 林青霞版魅惑 = 复制一份 `魅惑·勾人_林青霞.json` | ❌ **禁止**；破坏「改情绪一处全员跟上」 |
| 耦合 = styled 公式 | ✅ **唯一合法合成** |

### 3.2 为何温碧霞 / 部落巫医现在数值一样

当前 [`魅惑者_温碧霞/style.json`](../../预设资产/风格包/human/魅惑者_温碧霞/style.json) 与 `魅惑者_部落巫医` **完全相同**（🧠 生成器占位）。

**结论**：工程链路 **已通**，但 **读感尚未分化** —— 审定时应改 **base/scale 差异**，而不是复制情绪 JSON。

### 3.3 定人格 style 时在想什么

| 问题 | 落到参数 |
|------|----------|
| 这张脸 **平时** 眼更湿吗？ | `eye_gloss` **base** ↑ |
| 这张脸 **媚起来** 眨得大吗？ | `blink` **scale** ↑ |
| 这张脸 **扫视** 幅度大吗？ | `pupil_x/y` **scale** |
| 这张脸 **冷**、眉压多吗？ | `eyebrow` base/scale、`squint` base ↑ |
| 动一下会不会 **clip 饱和**？ | base 与 scale **不能同时拉满** |

⚠️ **历史教训**：`base=0.9` 且 `scale=0.9` 且 pulse 高 → styled 顶满 1.0 → 02 平庸/clipping。

### 4.4 案例：同 `魅惑·勾人` · 温碧霞 vs 拟定「林青霞式冷媚」

固定：同一 `魅惑·勾人.json`，同一帧 `t=60`（保持段），设 `pulse[blink,t]=0.20`，`pulse[eye_gloss,t]=0.15`。

#### A. 温碧霞（现有 style.json）

| 通道 | base | scale | styled（公式） |
|------|------|-------|----------------|
| blink | 0.50 | **0.75** | 0.50+0.75×0.20 = **0.65** |
| eye_gloss | **0.90** | 0.55 | 0.90+0.55×0.15 = **0.98** |
| squint | 0.50 | 0.40 | 0.50+0.40×p |
| lid_upper | **0.58** | 0.55 | 上睑偏高 → 柔媚 |

读感方向（🧠 合同）：**湿、眨幅大、上睑抬、眼波跟 pulse 放大的多**。

#### B. 林青霞式冷媚（🧠 拟定值 · **尚未入库** · 仅供审定方向）

| 通道 | 拟定 base | 拟定 scale | 意图 |
|------|-----------|------------|------|
| blink | 0.48 | **0.35** | 少眨、更钉 |
| eye_gloss | **0.55** | 0.25 | 不那么「水光泛滥」 |
| squint | **0.58** | 0.50 | 冷媚靠眯/眉压，不靠纯 gloss |
| eyebrow | **0.55** | 0.65 | 眉压略抬但 controlled |
| pupil_x | 0.50 | **0.30** | 扫视幅度收小 → 更「钉你」 |

同一 pulse 下 blink：0.48+0.35×0.20=**0.55**（低于温碧霞 0.65）→ **同样媚戏相位，脸更冷更稳**。

**要点**：差异来自 **12 对 base/scale**，不是改 `魅惑·勾人` 的 macro。

#### C. 若用户要的是「林青霞瞪人」而非「同情绪冷媚」

应换 **情绪** → `施压·凝视`（macro 高 power/speed/steady + PAD 不同），人格可选 `天选者_大祭司`（ eyebrow scale 高、blink scale 低）。  
这是 **换戏**，不是 style  alone。

### 4.5 与 `天选者_大祭司` 对比（现网已有分化）

[`persona_matrix.json`](../../gaze_engine/human/persona_matrix.json) 里大祭司：

- `blink` scale **0.25**（动幅小）
- `eyebrow` scale **0.90**（眉压动态大）
- `eye_gloss` base **0.46**（偏干）

叠 **同一 pulse** → **冷、压、少眨**，适合施压/祭司，不适合温碧霞式流转。

### 4.6 改什么文件（工作流）

**只改媚戏节奏（16 人格一起变）**

1. `02_情绪与能量/人/魅惑·勾人.md` + `魅惑·勾人.json`  
2. **不要**动 `魅惑者_温碧霞/style.json`

**只改温碧霞脸感（16 情绪一起变）**

1. `05_风格化/人/魅惑者_温碧霞.md` + `style.json` + `persona_matrix.json`

1. 复制 style 模板 → 改 base/scale → 写 md 合同

## 六、FAQ

**Q1：耦合会不会改变媚戏的 pulse 形状？**  
**不会。** 只改 **幅度与基线**（styled）；pulse **波形形状** 由情绪决定。

**Q2：为什么不用 LLM 直接写 style？**  
style 是 **12×2 个审定常数**，要跨 16 情绪验收；LLM 适合改 **macro** 或 **选 preset+人格**。

**Q3：狗贵宾和温碧霞是一回事吗？**  
**同一层公式**；狗是 **品种 style**，人是 **人格 style**。

**Q4：几何底膜和 style 什么关系？**  
**并行**：style 管 **12 通道动态**；`template_scales` 管 **眼型/耳位渲染**；一起送 Wan，互不替代。

**Q5：林青霞魅惑还没入库怎么办？**  
按 §4.4B **拟定 base/scale** 新建 `魅惑者_林青霞`；若产品其实是「瞪人」，用 **施压情绪 + 冷人格**，勿硬挂魅惑。

**Q6：每种情绪要不要单独写「温碧霞 × 该情绪」的偏移？**  
**不要。** 全项目规则：**1 人格 = 1 份 style.json = 12 通道各 1 组 base/scale，通吃 16 情绪**。若某组合读感不对，优先查 **该情绪 pulse** 或 **该人格 base/scale 是否太激进**；**禁止** 为单个组合另建 style 文件（否则改情绪无法全人格同步）。

## 七、附录：「更科学」三步路线图（详解）

> **读者**：想从 🧠 读感手调 → **有测量、有公式、有对照** 的审定流程。  
> **原则**：三步都 **不破坏**「1 人格 1 套 style、16 情绪共用」；只是 **把数字怎么来定** 变科学。

### 7.0 为什么是这个顺序

```text
现状：base/scale  largely 凭感觉填 → 温碧霞/部落巫医甚至完全相同

Step 1  参考片反推     →  数字从「猜」变成「拟合」     （投入小、收益大）
Step 2  矩阵 M         →  模型从「通道各玩各的」变「有耦合」 （Step1 残差大时才上）
Step 3  FACS/AU 对照表 →  通道语义可审计、可和 OpenFace 对齐 （文档+验收，不改主链）

❌ 不要走：16×9=144 份 style  →  科学假象、工程灾难
```

| 步骤 | 解决什么痛点 | 不解决什么 |
|------|--------------|------------|
| ① 参考片反推 | 「温碧霞 gloss base 该 0.9 还是 0.6？」 | 不替代情绪 preset、不改 E(t) |
| ② 矩阵 M | 「眯眼时上睑该一起动，对角 scale 做不到」 | 不增加每情绪一套参数 |
| ③ AU 对照表 | 「squint 到底对应 AU7 还是瞎起名？」 | **不** 把管线改成 AU 驱动 |
| ❌ 144 份 style | — | 维护爆炸、失去解耦 |

---

### 7.1 第一步：参考片反推 base / scale（优先做）

#### 7.1.1 在干什么（人话）

给你一段 **温碧霞真实视频**（或客户参考 mp4），用工具量出 **她脸上实际怎么动**，再反推：**我们的通用 pulse 要乘多少、加多少，才像她**。

#### 7.1.2 具体流程（工程步骤）

```text
输入：
  · 参考 mp4（建议 5s 左右，单一读感，如「勾人」）
  · 同场景下选定的情绪 preset（如 魅惑·勾人）→ 得到 pulse_ref[t]（我们系统编的）
  · 可选：客户标定后的底膜

Step A — 从视频提取「观测曲线」obs[ch,t]
  工具候选：OpenFace（AU 强度）· MediaPipe Face · 自研眼眉跟踪
  映射：AU45→blink, AU7→squint, …（见 Step 3 对照表）
  输出：obs[12×150]  归一化到 0～1

Step B — 固定 pulse，拟合 style
  模型（与现网一致）：
    styled[ch,t] = base[ch] + scale[ch] × pulse[ch,t]
  求 base, scale 使 styled 接近 obs：
    最小化 Σ_ch,t  ( styled[ch,t] - obs[ch,t] )²
  约束：base, scale ∈ [0,1] 合理区间，防 clip

Step C — 写入资产
  · 拟合结果 → 魅惑者_温碧霞/style.json（仍 **1 份**，全局）
  · 合同 md 注明：标定源 = ref_xxx.mp4，日期，RMSE
  · 人工只看：拟合残差大的通道 + 整体读感是否像

Step D — 交叉验证（科学性的关键）
  · 用 **另外 15 种情绪** pulse（不重新拟合！）叠同一 base/scale
  · 看 styled 是否「都像温碧霞在演」—— 不像则回到 Step A 换参考片或加 Step 2
```

#### 7.1.3 小例子（blink 单通道）

| 帧 t | pulse[blink,t]（系统·魅惑） | obs[blink,t]（OpenFace 测） | 拟合目标 |
|------|------------------------------|----------------------------|----------|
| 60 | 0.20 | 0.58 | 找 base, scale 使 0.58 ≈ base + scale×0.20 |
| 80 | 0.35 | 0.71 | 同上，多帧联合最小二乘 |

若整段拟合得 **base≈0.48, scale≈0.72** → 写入 style.json，**有视频证据**，不是 🧠 拍 0.5/0.75。

#### 7.1.4 为什么先做这步

- **仍用现公式**，只改 **参数来源** → 代码几乎不动  
- **每人格仍 1 份 style** → 架构不变  
- 立刻能区分温碧霞 vs 林青霞（各用各的参考片拟合）

#### 7.1.5 局限（诚实）

- OpenFace AU ≠ 你们的 12 通道 → 靠 **对照表映射**，有误差  
- 一条参考片往往是一种 **读感**（如媚），拟合的 scale 对「施压」是否仍准 → 靠 **Step D 交叉验证**  
- 测的是 **片里的脸**，不是医学真值；但比纯读感 **可重复**

---

### 7.2 第二步：矩阵 M 代替纯对角 scale（残差大时再做）

#### 7.2.1 对角 scale 缺什么

**现状（对角）**：`styled[squint,t]` **只** 看 `pulse[squint,t]`，不看 `pulse[lid_upper,t]`。

**真人**：眯眼时 **上睑、 squint、 brow 常联动** —— 一个通道的观测值依赖 **多个** pulse 分量。

#### 7.2.2 矩阵模型长什么样

```text
styled[t] = base + M × pulse[t]

其中（每一帧 t）：
  styled  = 12×1 向量
  pulse   = 12×1 向量
  base    = 12×1 向量（与现网相同）
  M       = 12×12 矩阵（每人格一份，仍全局 1 套）
```

展开一行：

```text
styled[squint,t] = base[squint]
                 + M[squint,squint]   × pulse[squint,t]
                 + M[squint,lid_upper]× pulse[lid_upper,t]
                 + M[squint,eyebrow]  × pulse[eyebrow,t]
                 + …
```

**对角 scale** = M 只有对角线非零：`M[i,i]=scale[i]`，其余为 0。

#### 7.2.3 怎么拟合 M（接 Step 1）

```text
已有：参考片 obs[t]，系统 pulse[t]

升级优化：
  min  Σ_t || obs[t] - base - M·pulse[t] ||²
  s.t. M 稀疏或近对角（L1 正则）→ 避免 144 参数全乱飞

输出：
  style.json 增加 "mix_matrix": { "squint": {"squint":0.5, "lid_upper":0.15, ...}, ... }
  或平铺 12×12 数组
```

#### 7.2.4 数值直觉

同一段 pulse，**仅改 M 的非对角元**：

| 设置 | 效果 |
|------|------|
| M[squint,lid_upper]=0 | 与现网对角相同 |
| M[squint,lid_upper]=+0.2 | pulse 里上睑一起抬时，styled 的 squint **额外** 抬高 → 「眯眼带上睑」 |
| M[eye_gloss,blink]=+0.1 | 眨时 gloss 略跟 → 「一眨一湿润」 |

#### 7.2.5 为什么第二步、不是第一步

| | 对角 base+scale | 矩阵 M |
|---|----------------|--------|
| 参数数/人格 | 12+12=**24** | 12+144=**156** |
| 审定难度 | 低 | 高 |
| 需不需要 | **总是需要**（identity 基本量） | 仅当对角 **拟合残差大** 或 **联动读感不对** |

**建议**：先用 Step 1 拟合对角；若 RMSE 某通道长期 > 阈值，再对该人格 **放开 M 的非对角块**（例如 squint–lid_upper–eyebrow 3×3 子矩阵），不要一次 12×12 全放开。

---

### 7.3 第三步：FACS / AU 对照表（带置信度）

#### 7.3.1 在干什么（不是改管线）

**不做**：150 帧 → AU → 再转回 12 通道当主链。  
**要做**：一张 **合同表**，写清每个通道 **主要对应哪些 AU、置信度多高**。

用途：

1. **Step 1** 里 OpenFace 的 AU45 该乘多少权重进 `blink`  
2. **审定** 时争论「squint 是不是 AU7」有据可查  
3. **对外** 说「与 FACS 同向」时 **诚实分级**

#### 7.3.2 表示例（🧠 待实测填置信度）

| 通道 | 主要 AU | 次要 AU | 置信度 | 说明 |
|------|---------|---------|--------|------|
| blink | AU45 眨眼 | AU43 闭眼皮 | **高** | 工业通用 |
| squint | AU7 睑紧缩 | AU6 颊上抬 | **中** | 狗/抽象眼眉更粗 |
| eye_gloss | — | — | **低** | **渲染量**，非 FACS 肌肉 |
| pupil_x/y | — | gaze | **低** | 视线，非经典 AU |
| eyebrow（狗） | — | 耳位行为学 | **低** | 物种特例 |

置信度定义：

| 等级 | 含义 |
|------|------|
| **高** | 多数据集 AU–blendshape 共识；OpenFace 可直接映射 |
| **中** | 语义近似；需项目内读感验收 |
| **低** | 仅启发命名；**不能** 声称 FACS 认证 |

#### 7.3.3 和 Step 1、2 的关系

```text
OpenFace 输出 AU 向量 a[t]
        ↓  对照表 T（12 × n_AU，带置信度权重）
观测 obs[ch,t] ≈ Σ_k T[ch,k] · a[k,t]
        ↓
与 pulse 一起拟合 base, scale（或 M）
```

**对照表是桥梁**，不是新一层客户选项。

#### 7.3.4 为什么放第三步

- **不增加** 运行时复杂度（表 mainly 文档 + 反推脚本）  
- Step 1 没有表也能用 OpenFace **硬映射**；有表 **更一致、可审计**  
- 避免未标置信度就对外说「FACS 驱动」

---

### 7.4 为什么 **不要** 16×9 份 style

| 做法 | 表面 | 实际问题 |
|------|------|----------|
| `温碧霞_魅惑.json` + `温碧霞_委屈.json` + … | 「每组合最准」 | 改 **魅惑情绪** 要改 **9 文件**；改 **委屈** 要改 **9 文件** |
| 144 份 | 像「大数据」 | 参数 **144×24=3456** 个，无法交叉验证，**过拟合** 某一格 |
| 科学上 | — | 把 **identity×emotion 交互** 硬编码，违反 **identity/expression 解耦**（FLAME 系明确分开 z_id 与 z_exp） |

**正确做法**：emotion 变 → 只变 **pulse**；identity 变 → 只变 **base/M**；组合 **运行时乘**，不 **存表**。

若某格「温碧霞×委屈」特别怪：

1. 先查 **委屈 pulse** 是否审定错  
2. 再查 **温碧霞 style** 是否在 Step D 对委屈类情绪失效  
3. 最后才考虑 **L2 少量交互项**（专篇 §2.5.4，牺牲正交，慎用）

---

### 7.5 三步落地清单（给工程）

| 阶段 | 交付物 | 验收 |
|------|--------|------|
| **P0** | 反推脚本：mp4 + emotion → 候选 base/scale | 温碧霞 vs 大祭司 **数值可区分** |
| **P0** | AU 对照表 md（12 行 + 置信度） | 每通道有 primary AU 或标「非 FACS」 |
| **P1** | 每人格 **2+ 参考片** 交叉验证 16 情绪 | 读感一致、无 clip |
| **P2** | style.json v2 可选 `mix_matrix` | 对角 RMSE 降 ≥20% |
| **禁止** | `style/{人格}_{情绪}.json` | 目录检查为 0 |
