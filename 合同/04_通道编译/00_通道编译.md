## 一、概述（What）

**通道编译（S4）** 做一件事：把

- **1 条能量曲线 E(t)**（150 个数，管「5 秒内多用力、何时起峰、盯住多久」）
- **3 个 PAD 数 (P, A, D)**（管「这种脸的气质：偏压抑还是偏兴奋、谁更眯、谁更亮」）

合成 **12 条通道动画 pulse[12×150]**（共 1800 个数），供后续风格化、先验、写入 `02_烘焙_*.json`。

### 管线位置

```
01 SliderPacket
  → 02 E(t)              # 合同/02_情绪与能量
  → 03 pad_scale[12]     # 合同/03_情绪坐标
  → 04 pulse[12×150]     # 本文件 ⭐
  → 05 styled            # 合同/05_风格化
  → 06 prior + QC        # 合同/06_先验与质检
  → 02_烘焙_*.json
  → 07 MP4 / 08 扩散包
```

### 30 秒版（先读这段）

可以把它想成 **调音台**：

| 对象 | 类比 | 数量 |
|------|------|------|
| **E(t)** | 总音量推子：随时间起伏 | 1 条 × 150 帧 |
| **PAD** | 12 个通道各自的「性格旋钮」 | 3 个数 → 展开成 12 个系数 |
| **pulse** | 最终 12 路输出波形 | 12 条 × 150 帧 |

**不是**「3 + 1 = 12」，也 **不是**「PAD 有 12 维」。  
是：**E(t) 决定每一帧有多强；PAD 决定 12 个通道各自强多少；再按人类规则打补丁。**

## 四、核心公式：E(t) × PAD → pulse

### 4.1 总流程

```
情绪 JSON（macro / hold_seg / pad）
        │
        ├─► build_energy_envelope()     →  E[0..149]        （1 条）
        │
        └─► resolve_pad()               →  P, A, D          （3 个数）
                    │
                    ▼
            compute_pad_scale() ×12     →  scale[ch]       （12 个系数）
                    │
                    ▼
            channels_from_envelope()      →  pulse[ch][t]    （12×150）
                    │
                    ├─► blink 独立锚点
                    ├─► pupil_x/y 方向偏置
                    ├─► eyebrow 滞后
                    ├─► 盯住段耦合
                    └─► micro_jitter 微颤
                    │
                    ▼
            02_烘焙_*.json 的 channel_tracks
```

### 4.2 第一步：macro → E(t)

**输入**：`SliderPacket.macro`（6 根）+ `hold_seg`（盯住段花纹）  
**输出**：`E[t]`，`t = 0..149`，每个值在 0～1 附近  
**代码**：[`envelope_compile.build_energy_envelope()`](../../gaze_engine/envelope/envelope_compile.py)

6 根滑杆决定「5 秒表演的主旋律」——什么时候蓄力、什么时候到顶、盯住段是平的还是颤的、最后怎么收。  
这条旋律 **只有 1 根线**，不是 12 根。

四段标签：**蓄力 → 启动 → 保持 → 缓和**。

### 4.3 第二步：(P,A,D) → 12 个 scale

**输入**：`(P, A, D)`，每个 ∈ [-1, 1]  
**输出**：`scale[ch]`，12 个通道各一个数  
**代码**：[`envelope_compile.compute_pad_scale()`](../../gaze_engine/envelope/envelope_compile.py) + [`pad/pad_weights.py`](../../gaze_engine/pad/pad_weights.py)

#### 核心公式（每个通道 ch 各算一次）

```
scale[ch] = base[ch] + P×Wp[ch] + A×Wa[ch] + D×Wd[ch]
scale[ch] = max(0, scale[ch])    // 不允许负权重
```

#### 人类 PAD 权重表

| 通道 | Wp | Wa | Wd | base | 语义 |
|------|----|----|----|------|------|
| `pupil_x` | 0.00 | 0.50 | 0.40 | 0.30 | 高 A/D → 眼神向前聚焦（"迎"） |
| `pupil_y` | 0.00 | 0.50 | 0.40 | 0.30 | 同上 |
| `blink` | 0.00 | 0.30 | 0.10 | 0.30 | |
| `eyebrow` | 0.00 | 0.30 | **-0.35** | 0.30 | D 负 → 负负得正 → 眉压下（"拒"） |
| `pupil_scale` | 0.10 | 0.30 | 0.20 | 0.30 | |
| `iris_scale` | 0.10 | 0.20 | 0.10 | 0.30 | |
| `cornea_bulge` | 0.00 | 0.40 | 0.30 | 0.30 | |
| `squint` | 0.10 | 0.35 | 0.20 | 0.30 | |
| `brow_raise` | 0.10 | 0.20 | **-0.20** | 0.30 | 低 D → 挑眉抬起 |
| `lid_upper` | 0.00 | 0.50 | 0.40 | 0.30 | 高 A/D → 上眼睑紧张 |
| `lid_lower` | 0.00 | 0.30 | 0.20 | 0.30 | |
| `eye_gloss` | 0.30 | 0.10 | 0.00 | 0.30 | 高 P → 湿润光泽 |

> **注意**：`eyebrow.Wd = -0.35` 和 `brow_raise.Wd = -0.20` 是负值。这意味着「越退缩（D 越负），眉压越重/挑眉越高」—— 人类委屈时眉毛上抬是合理的生理反应。

#### 计算示例（委屈）

委屈 PAD 示例：`P=-0.40, A=-0.15, D=-0.70`

```
scale[eyebrow] = 0.30 + (0) + (-0.15×0.30) + (-0.70×-0.35)
               = 0.30 - 0.045 + 0.245
               = 0.50
```

```
scale[squint] = 0.30 + (-0.40×0.10) + (-0.15×0.35) + (-0.70×0.20)
              = 0.30 - 0.04 - 0.0525 - 0.14
              = 0.0675
```

### 4.4 第三步：E(t) × scale → pulse[12×150]

**代码**：[`envelope_compile.channels_from_envelope()`](../../gaze_engine/envelope/envelope_compile.py)

#### 默认公式（大多数通道）

```
pulse[ch, t] = clamp( E[t - lag[ch]] × scale[ch] × gain[ch] , 0, 1 )
```

| 符号 | 含义 | 人类默认 |
|------|------|---------|
| `lag[ch]` | 该通道比 E(t) 晚几帧启动 | iris_scale lag=3 |
| `gain[ch]` | 该通道额外倍率 | squint gain=1.10 |

**白话**：每一帧，用 **当前能量 E(t)** 去乘 **该通道的 PAD 系数**，得到这一帧这一通道的值。

## 五、人类特异规则

人类（相对其他物种）的 S4 有以下特性：

| 点 | 实现位置 |
|----|---------|
| `eyebrow` | **D 轴驱动滞后**跟随 pupil，非纯 E×scale |
| 盯住段 | `pulse` 耦合 eyebrow / squint / pupil_scale |
| 通道表 | `HUMAN_CHANNELS`（12 轨，与 `CANONICAL_KEYS` 一致） |
| 微颤 | `_HUMAN_JITTER_BIAS = 0`（生理基线） |

这些规则实现在 [`envelope_compile.channels_from_envelope()`](../../gaze_engine/envelope/envelope_compile.py) 内部。

## 六、例外通道详解

以下通道 **不能只用 E×scale 一行公式**：

### 6.1 blink — 眨眼

眨眼是 **离散事件**，不是随 E 平滑升降。在 `t_peak`、保持段等时刻插入快闭快开 spike。

```
blink[t] = 独立锚点序列（非 E[t] × scale）
scale 只用于计算 blink 峰值高度
```

### 6.2 pupil_x / pupil_y — 视线方向

```
pulse[t] = sign × E[t] × scale + 方向偏置
```

有左右/上下方向，不只是强度。受 `push` 滑杆方向影响：`push<50 → sign=-1`。

### 6.3 eyebrow — 眉压

D 轴驱动滞后跟随 pupil，非纯 E×scale。人类 eyebrow 表示真实的眉压（不同于其他物种将此槽位复用为耳位）。

### 6.4 委屈类湿眼补丁

委屈类情绪在保持段叠加额外眯眼 + 湿润高光基线（`_apply_moist_sad_baseline`），覆盖 `squint`、`lid_upper`、`lid_lower`、`eye_gloss`。

### 6.5 hold=tremble

保持段各通道不同幅度 ripple（`_apply_tremble_hold_coupling`）。

### 6.6 micro_jitter

全段微颤，最后叠一层生物感底噪。

## 七、02 烘焙格式

### 7.1 文件结构

**示例路径**：`…/指令/02_烘焙_*.json`

```json
{
  "schema_version": "0.2-baked-human-prior",
  "_baked_dense": true,
  "revision": "delivery:情绪名",
  "slider_packet": { "schema": "slider-packet-v1", "macro": {}, "hold_seg": {} },
  "human_prior_report": {},
  "pulse_quality_report": {},
  "channel_tracks": {}
}
```

### 7.2 `channel_tracks`

- 每通道 **150** 个 `{ "t", "v", "phase", "easing": "linear" }`
- `t` 与下标一致 `0..149`

### 7.3 结构合格线（P0）

| 检查 | 合格 |
|------|------|
| 每通道 150 采样 | ✅ |
| 12 轨齐全 | ✅ |
| schema | `_baked_dense: true` 或 `schema_version` 含 `baked` |
| 无 NaN | `validate_baked_delivery` |
| 滑杆回写 | 烘焙内 `slider_packet` 与操作台一致 |

### 7.4 校验命令

```bash
python3 -c "
from pathlib import Path
import json
from gaze_engine.input.channel_contract import validate_baked_delivery
d = json.loads(Path('…/02_烘焙_*.json').read_text())

```
