## 零、补丁的定义（先读这一节）

### 0.1 补丁是什么

**补丁** = 在 S4 函数 `channels_from_envelope()` 里，**默认公式已经算完之后**，用 **代码里写死的系数 + 固定规则**，对 12 通道做 **替换** 或 **叠加** 的那一段逻辑。

```text
S4 内部顺序：

  ① 默认形   pulse ≈ E(t) × scale(PAD) × gain     ← 大多数通道的主公式
  ② 补丁     在 ① 之上替换或加一层                  ← 本文只讲这块
  ③ 输出     pulse 12×150
```

**狗 · 当前代码里的 4 条补丁**：

| 补丁 | 对通道干什么 |
|------|--------------|
| **blink** | **整轨替换** blink 通道（不用 E×scale） |
| **委屈湿眼** | 保持段 **加** squint / lid / eye_gloss |
| **tremble ripple** | 保持段 **加** 各通道颤抖 ripple |
| **micro_jitter** | 全段 **加** 微颤 |

> ⚠️ **4 条 ≠ 4 个通道**：是 4 套改表规则，一起作用在同一张 **12 通道 × 150 帧** 的 pulse 表上。逐通道对照见 **§0.4**。

### 0.4 四条补丁 × 12 通道对照（狗）

**怎么读这张表**：

```text
  ① 默认形先填满 12 通道 × 150 帧
  ② 4 条补丁按条件往不同通道、不同帧段 替换 或 叠加
  ③ 合起来 = 最终 pulse（再进 S5 巨贵）
```

**不是** 1 条补丁 = 1 个通道；**是** 4 个概念 **按条件** 改表中的部分格子。

|------|--------------|--------------|
| ① blink | ✅ 跑 | `blink` |


### 0.2 补丁不是什么

| 不是补丁 | 阶段 | 说明 |
|----------|------|------|
| E(t) | 02 | macro+hold 来的 150 帧能量线 |
| scale[12] | 03 | PAD 投影的 12 个常数 |
| 默认形 E×scale×gain | S4 前半 | 补丁 **之前** 的主公式 |
| 巨贵 style | **S5** | `base + scale×pulse`，在补丁 **之后** |
| prior / QC | **S6** | 先验、平庸质检 |

### 0.3 一句话定义

> **补丁 = 默认形算不完时，编译器里另写的一套「固定系数 + 固定公式」；按条件触发，改 pulse，不改 E(t)。**

## 一、两层结构（最易混淆 · 必读）

补丁环节里 **同时存在两样东西**，不要混成一个「全是上游定的」：

```text
┌─────────────────────────────────────────────────────────────┐
│  第 1 层 · 上游触发（情绪 JSON 里已有，不用多配 patch 块）      │
│  ─────────────────────────────────────────────────────────  │
│  macro+hold  →  E(t)、t_peak、t_hold0、t_hold1（时间轴）     │
│  PAD         →  scale[12]（如 scale[blink]）                │
│  情绪名字符串  →  含不含「委屈/可怜/渴望」                      │
│  hold_seg    →  flat / tremble …                             │
│                                                              │
│  作用：走哪条补丁 · 在第几帧 · 个别项乘 scale 或 E(t)          │
└─────────────────────────────────────────────────────────────┘
                              +
┌─────────────────────────────────────────────────────────────┐
│  第 2 层 · 补丁系数（写在 envelope_compile.py 里 · 🧠 脑补）   │
│  ─────────────────────────────────────────────────────────  │
│  0.07、0.17、28%、0.72、0.09…                                │
│                                                              │
│  作用：触发之后 **加多少、什么形状**                            │
│  不在 JSON 里 · 改数要改代码 · 目前无权威定稿                  │
└─────────────────────────────────────────────────────────────┘
                              ↓
                         pulse 12×150
```

| 你的说法 | 对应哪一层 |
|----------|------------|
| **上游定植**（JSON 不多一套字段） | 第 1 层 · 触发 |
| **参数带入 / 人为定**（脑补常数） | 第 2 层 · **补丁系数** |

**关键纠正**：

- ❌ 误解：「补丁 = 上游全定死，没有补丁系数」  
- ✅ 正解：「JSON 里没有补丁系数字段，但 **代码里一定有** 写死的补丁系数」

## 二、「三类」= 三种触发方式（每条补丁里都有系数）

以前说「补丁分三类」指的是 **什么时候执行**，**不是** 「有没有系数」。

**每一类补丁执行时，都会用到第 二 层里的写死系数。**

| 类 | 什么时候跑 | 补丁 | 写死系数举例 |
|----|------------|------|--------------|
| **① 狗通用·恒跑** | 只要是狗 S4 | blink 基础、micro_jitter | 峰 0.13、锚 28%/52%、波形 0.72/1.0/0.58 |
| **② hold 开关** | `hold_seg.shape == "tremble"` | tremble ripple；blink×1.12 | 0.09、0.14、0.07… |
| **③ 情绪名开关** | 名含「委屈/可怜/渴望」 | 湿眼；blink 改 0.17 | 0.07、0.05、0.85、0.35… |

```text
                    ③ 情绪名开关
                    「委屈」? ──是──→ 湿眼系数 0.07…
                         │
                    ② hold 开关
                    tremble? ──是──→ ripple 系数 0.09…
                         │
                    ① 狗通用（恒跑）
                    ──→ blink 系数 0.13/0.17…
                    ──→ jitter 系数
```

**委屈·变体3（hold=flat）实际走的路径**：

```text
① blink（恒跑）        → 用 0.17（③ 情绪名打开）
③ 湿眼（情绪名打开）   → 用 0.07…
② tremble              → 不跑（hold=flat）
① jitter               → 跑（次要）
```

### 3.1 blink — `_dog_blink_series`

| 系数 | 值 | 影响面 | 上游怎么用 |
|------|-----|--------|------------|

### 3.3 tremble — `_apply_tremble_hold_coupling`（变体3 不跑）

| 通道 | 系数 × ripple × E(t) |

| squint | 0.14 |

| eye_gloss | 0.03 |

### 3.4 micro_jitter — 狗偏置 + profile

| 项 | 值 | profile 由谁选 |

## 四、委屈·变体3：你要审哪几个数

| 优先级 | 审什么 | 为什么 |
|--------|--------|--------|
| **P0** | 湿眼 0.07 / 0.05 / 0.85 / 0.35 / 0.04 / 0.05 | 委屈脸读感主战场 |
| **P1** | blink 0.17 + 锚点 28%/52% + spike 波形 | 眨眼次数与力度 |
| **P2** | micro_jitter 偏置 | 全狗微颤，不如湿眼显眼 |
| **可忽略** | tremble 0.09… 全套 | hold=flat **不触发** |

## 五、巨贵 / E(t) / PAD 管不管补丁

```text
┌─────────────┬──────────────────────────────────────────┐
│  输入        │  补丁环节管什么                            │
├─────────────┼──────────────────────────────────────────┤
│  E(t)       │  默认形；tremble 里 ripple×E(t)            │
│  PAD        │  scale[ch]；blink 峰 × scale[blink]        │
│  macro      │  blink 锚点帧号；jitter profile            │
│  hold_seg   │  tremble 开/关                             │
│  情绪名      │  湿眼开/关；0.13 vs 0.17                   │
│  巨贵        │  ❌ 不参与补丁（S5 才进来）                 │
└─────────────┴──────────────────────────────────────────┘
```

巨贵只在 S5：`styled = base + scale × pulse`（`style.json`，与补丁系数是 **另一套人为定参数**）。

## 六、补丁 vs 非补丁（边界表）

| 名字 | 是不是补丁 | 有没有写死系数 |

| prior / QC | ❌ S6 | 另一套规则 |

## 七、巨贵 × 委屈 × 变体3 — 逐步

```text
macro+hold → E(t)
PAD        → scale[12]
                ↓
S4  默认形 + 补丁（系数在 .py 里）
      · blink 0.17×scale[blink]，锚点来自 macro
      · 湿眼 +0.07…（情绪名「委屈」触发）
      · tremble 跳过
                ↓
         pulse 12×150
                ↓
S5  巨贵 style.json → styled
                ↓
S6  prior + QC → 02_烘焙.json
```

**t=80 心算（保持段）**：

```text
默认形 squint  ≈ E(80) × scale[squint] × gain  ≈ 0.021
+ 湿眼补丁     ≈ +0.09
= pulse[squint] ≈ 0.11
→ styled       = 巨贵_base + 巨贵_scale × 0.11
```

## 八、定植 vs 人为定（审参数时用）

| 层级 | 叫什么 | 配置在哪 | 补丁环节 |
|------|--------|----------|----------|
| 上游触发 | 定植输入 | 情绪 JSON：macro/hold/PAD/情绪名 | 决定 **走不走** |
| 补丁系数 | **人为定** | `envelope_compile.py` 常数 | 决定 **走之后加多少** |
| 品种 | **人为定** | `style.json` | **不是补丁**，S5 |

**JSON 里不需要 `patch` 块** ≠ **补丁没有系数**。  
系数在代码里，**目前全是脑补，需要你逐类审定。**

## 九、改效果往哪改

```text
更用力/更慢到顶        → macro → E(t)           （不是补丁）
通道气质配比           → PAD → scale             （不是补丁）
更湿的眼               → 湿眼补丁系数 0.07…       （改 .py）
眨眼多少/多用力        → blink 0.17、锚点比例     （改 .py）
保持段发抖             → hold=tremble + tremble 系数
巨贵眼更大             → poodle_giant/style.json  （S5，不是补丁）
```
