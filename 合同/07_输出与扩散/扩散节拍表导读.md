# 扩散节拍表导读 — 「导演指令」是什么、怎么编译

> **你问的那个东西，官方叫：`扩散节拍表` / `节奏说明书`**  
> 口语可叫：**导演节拍指令**、**12 通道语义说明书**  
> **状态：2026-05-28** · 对齐 `rhythm_compiler.py`

**一句话**：Wan 除了 MP4 和 Prompt，还需要一份 **把 02 里每通道、每关键帧的数值翻译成人话** 的文本 — 告诉扩散模型「第 49 帧 pupil_x 变大 = 扫视回头」，否则 MP4 只有形状、没有情绪方向。

**详细规范**：[`节奏说明书.md`](../04_通道与先验/节奏说明书.md) · [`节奏说明书编译器.md`](../04_通道与先验/节奏说明书编译器.md)  
**组装进 Wan 包**：[`扩散引擎包组装专篇.md`](扩散引擎包组装专篇.md)

## 一、先分清：Wan 实际吃几路

送 Wan **不是两路，是四路**（其中两路在文本里）：

```text
┌─────────────────────────────────────────────────────────────┐
│  ① 参考图 start_image.jpg     →  画的是谁（身份）            │
│  ② 控制视频 03_工程底模.mp4   →  眼眉在哪、怎么动（像素）    │
│  ③ 扩散节拍表（本文件讲的）   →  每个脉冲在演什么（语义）    │
│  ④ 正向/负向 Prompt + 叙事   →  总导演要求 + 客户故事       │
└─────────────────────────────────────────────────────────────┘
```

| 路 | 文件/段落 | 管什么 | 缺了会怎样 |
|----|-----------|--------|-----------|
| 像素控制 | `03_工程底模.mp4` | 150 帧 RGB 线条：**几何在哪** | 形状可能对，表情空洞 |
| **语义节拍（导演指令）** | `04` 的 **`## 扩散节拍表`** | 12 通道关键帧 + 中文语义 | 几何在动，**不知道在演委屈还是怒** |
| 总导演句 | `04` 的 `## 正向 Prompt` | 品种、情绪、质感、「跟随控制序列」 | 缺硬约束，CLIP 漂移 |
| 客户故事 | `04` 的 `## 叙事` | 「跑回笼子再回头看」 | 缺场景意图 |
| 禁区 | `wan_negative.txt` | 不要过曝/换脸/不同步 | 质量崩 |

**③ 就是你不确定怎么称呼的那一环。**

## 三、它是不是「每一帧一条导演令」？

**不完全是。** 要分两层理解：

### 3.1 机器真源：确实是 12 × 150

`02_烘焙.json` 的 `channel_tracks` 里，每个通道有 **150 帧** float（0～1）：

```text
pupil_x:  [0.0, 0.0, …, 0.737, …, 0.0]   ← 150 个数
blink:    [0.0, 0.0, …, 0.42, …, 0.0]
… 共 12 通道
```

这 150×12 个数：
- **一路** → `affine_renderer` → **MP4 每一帧的像素**
- **另一路** → `rhythm_compiler` → **扩散节拍表文本**

### 3.2 送给 Wan 的文本：关键帧 + 语义（降采样）

Wan 的 CLIP **读不下 1800 个 float**，所以编译器只导出 **变帧关键帧** + **每通道一句语义**：

```text
- **pupil_x**（视线左右）: t0=0.0, t17=0.34, t49=0.737, t83=0.22, …
  → 节拍：扫视方向；牵动注视与头部微转暗示
- **blink**（眼睑开合）: t0=0.0, t52=0.38, t86=0.15, …
  → 节拍：眼睑脉冲；唇颊放松/微收节奏
… 12 通道 …

## 时间轴汇合（变帧时刻）
0, 17, 49, 52, 83, 86, …
```

所以：
- **MP4** = 每一帧都有像素（150 帧全量）
- **扩散节拍表** = 每一通道的 **关键节拍点** + **导演语义句**（不是 150 行 prose）

## 四、怎么编译出来（完整链）

```text
客户 NL + 滑杆
    │
    ▼  delivery_pipeline（S0～S7）
02_烘焙.json
    │  channel_tracks[12][150]
    │
    ├──────────────────────────────┐
    │                              │
    ▼                              ▼
affine_renderer              rhythm_compiler.build_metronome_text()
（像素编译器）                 （语义编译器 · 本环节）
    │                              │
    ▼                              ▼
03_工程底模.mp4              05_扩散节拍表.txt
150 帧 RGB 视频              （或嵌入 04 的 ## 扩散节拍表）
    │                              │
    └──────────┬───────────────────┘
               ▼
    DiffusionPromptAssembler.assemble()
               │
               ▼
    04_Prompt.txt  →  split_for_wan()  →  wan_positive / wan_negative
               │
               ▼
    build_diffusion_bundle()  →  扩散引擎包/
```

### 4.1 语义编译器是谁

| 项目 | 内容 |
|------|------|
| **模块** | `gaze_engine/_shared/rhythm_compiler.py` |
| **入口函数** | `build_metronome_text(baked_json, species=...)` |
| **谁调用** | `DiffusionPromptAssembler._build_beat_text()`（Pomot/export 时自动） |
| **文案真源** | `gaze_engine/{human,cat,dog}/rhythm_data.py` → `DIFFUSION_HINTS`、`CHANNEL_LABELS`、`DOG_CONSTRAINT` 等 |

### 4.2 编译器做四件事

```text
① 读 02.channel_tracks → 每通道提取 keyframes (t, v)
② 查 DIFFUSION_HINTS   → 每通道配一句「→ 节拍：…」
③ 汇总变帧时刻         → ## 时间轴汇合
④ 生成硬约束摘要       → ## 给扩散的硬约束（摘要）
```

### 4.3 代码一行验证

```python
from gaze_engine._shared.rhythm_compiler import build_metronome_text

beat_text = build_metronome_text(baked_json, species="dog")
# beat_text 就是「导演节拍指令」全文
# 通常嵌入 04 的 ## 扩散节拍表，不单独送 Wan 节点
```

### 4.4 和 04 / wan_positive 的关系

```text
04_Prompt.txt
├── ## 正向 Prompt          ← 总导演要求（短）
├── ## 扩散节拍表           ← ★ 本导读讲的「导演指令」（长）
├── ## 叙事                 ← 客户故事（短）
└── ## 负向 Prompt

split_for_wan() 后：
wan_positive = 正向 + 空行 + 扩散节拍表 + 空行 + 叙事
wan_negative = 负向
```

**Wan 节点只接 `wan_positive.txt`，但 positive 里已经包含整份扩散节拍表。**

## 五、和 MP4 的分工（最易混）

| 问题 | MP4 回答 | 扩散节拍表回答 |
|------|----------|----------------|
| 第 49 帧瞳孔往哪偏？ | ✅ 蓝圈像素位置 | （可选）t49=0.737 |
| 这个偏移在演什么？ | ❌ 像素说不清 | ✅ 「扫视方向；牵动头部微转」 |
| 第 52 帧为什么闭眼？ | ✅ 红环闭合 | ✅ 「眼睑脉冲；全局微释放」 |
| 整体是委屈还是怒？ | ❌ | ✅ 情绪名 + 硬约束 + 正向 L2 词 |

**口诀**：**MP4 = 几何真值 · 节拍表 = 语义真值 · 二者必须同一份 02.revision**

## 六、门户里什么时候生成

| 步骤 | API | 是否出节拍表 |
|------|-----|-------------|
| Pomot 第一轮/第二轮 | `POST /api/portal/pomot/round1` | ✅ 嵌入 `prompt_04` 的 `## 扩散节拍表` |
| 保存 | `POST /api/portal/save` | ✅ 若带 `prompt_04` |
| 导出 | `POST /api/portal/export` | ✅ 写 `04` + `wan_positive`（含节拍表） |
| 单独 CLI | `python3 -m gaze_engine._shared.rhythm_compiler --input 02.json` | ✅ 可单独出 `05_扩散节拍表.txt` |

Pomot **不会**单独给你一个「导演指令.pdf」— 它在 `04` / `wan_positive` 中间那一段。

## 七、示例片段（狗 · 委屈）

**02 里（机器，不送 Wan）**：

```json
"channel_tracks": {
  "pupil_x": { "keyframes": [{"t": 0, "v": 0.0}, {"t": 49, "v": 0.737}, …] }
}
```

**编译后（人话，送 Wan positive）**：

```text
- **pupil_x**（视线左右）: t0=0.0, t49=0.737, t83=0.22
  → 节拍：扫视方向；牵动注视与头部微转暗示

## 给扩散的硬约束（摘要）
扫视过冲帧(约49)为全脸张力高峰；轻眨帧(约86)为全局微释放。
狗版本：150帧线性插值；blink 在保持段须有可见脉冲；…
```

## 八、改这里会动什么

| 你想改… | 改哪里 | 不要改 |
|---------|--------|--------|
| 某帧瞳孔数值 | 滑杆 / 02 编译链 | 手写节拍表 |
| 节拍表里的 t,v | 必须重跑 02 → rhythm_compiler | 直接改 wan_positive 数字 |
| 「扫视」改成别的说法 | `{species}/rhythm_data.py` 的 `DIFFUSION_HINTS` | MP4 渲染器 |
| 客户故事 | NL / `## 叙事` | 节拍表数值 |
