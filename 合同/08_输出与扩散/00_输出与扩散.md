## 二、理论依据（Theory）

### 2.1 为什么 08 需要四件套

Wan 2.1 视频扩散模型接受**多路 conditioning 输入**，每路解决一个维度的问题：

| Wan 输入 | 解决什么 | 缺了会怎样 |
|----------|---------|-----------|
| `control_video`（MP4） | 眼眉**在哪、怎么动**（像素几何） | 形状对但表情空洞 |
| `wan_positive` 中的节拍表 | 眼眉在**演什么情绪**（语义节奏） | 有动作但不知道在演什么 |
| `wan_positive` 中的叙事 | **发生什么故事**（场景氛围） | 方向对但不知道在拍什么 |
| `start_image`（参考图） | **画的是谁**（身份锚点） | 不知道画的是林青霞还是狗 |

**四路缺一不可**。少任何一路，Wan 都会在对应维度自由发挥，大概率偏离意图。

### 2.2 为什么节拍表 ≠ JSON

| 送 Wan 的方式 | 问题 |
|--------------|------|
| 直接送 02_烘焙.json（1800 个数字） | Wan 看不懂数字在「演什么」 |
| 送节拍表文本（每通道一句语义说明） | Wan 读懂了：「哦，这是扫视」 |

```text
02.json 中的 channel_tracks.pupil_x:
  t0=0.0 → t17=0.34 → t23=0.3 → t86=0.22 → t149=0.0
  └────────────────────────────────────────────────┘
  Wan：这些数字是什么意思？（无法理解）

节拍表中的 pupil_x 行:
  pupil_x: t0=0.0, t17=0.34, t23=0.3, t86=0.22, t149=0.0
  → 节拍：扫视方向；牵动注视与头部微转暗示
  └────────────────────────────────────────────────┘
  Wan：哦，这是扫视！视线方向变化，头部跟着微转
```

**节拍表 = JSON 的人话翻译**，是管线上唯一一份同时流向 Wan、客户、开发者的中间件。

### 2.3 为什么 Pomot 分两轮

| 理由 | 说明 |
|------|------|
| round1 定调 | 选情绪 → 加载预设 → 编译 02 → 出节拍表 → 出 04 |
| round2 微调 | 只调 macro（再委屈一点 / 再狠一点），**不换 preset** |
| 禁止混用 | round2 换 preset = 情绪和节奏全变，与客户预期不一致 |

### 2.4 为什么 04 五段必须分三段送 Wan

```text
04_Prompt.txt 全文（五段）
  ├── 文件头          ← 不送 Wan（仅归档用）
  ├── ## 正向 Prompt  ← 送 wan_positive 段 1
  ├── ## 扩散节拍表    ← 送 wan_positive 段 2  ← 关键！
  ├── ## 叙事         ← 送 wan_positive 段 3
  └── ## 负向 Prompt  ← 送 wan_negative 全文
```

Wan 的 positive CLIP 需要把「情绪/质感描述 + 节拍语义 + 场景故事」放在一起，让 Wan 在同一个语义空间内理解「谁 + 什么情绪 + 什么场景」。

负向单独送，防止禁区破坏正向量。

## 三、为什么这样做（Why）

### 3.1 关键决策：控制视频 + 节拍表 = 管线精确输出

| 方案 | 问题 | 结论 |
|------|------|------|
| 只送 MP4 | Wan 知道眼眉位置但不知道在演什么情绪 | ❌ 情绪方向可能错 |
| 只送文本 | Wan 有故事但眼眉节奏不可控 | ❌ 几何位置对不上 |
| **MP4 + 节拍表** | 像素精确控制 + 语义精确描述 | ✅ 正选 |

**教训**：某次仅换 MP4 没换节拍表 → Wan 生成的成片眼眉位置对，但情绪方向偏了。**此后 02/03/04 revision 必须一致**。

### 3.2 关键决策：NL 分两路（眼眉 vs 叙事）

| 路 | 字段 | 去向 |
|----|------|------|
| NL-A（眼眉） | `emotion` → preset | `SliderPacket` → 02 → 节拍表 |
| NL-B（叙事） | `action` 原文 | 04 `## 叙事` → `wan_positive` |

⚠️ **禁止**将 NL-B 叙事整句送进眼眉链（01~06）。「跑回笼子」是场景，不能当眼眉参数编译；「再委屈一点」只能调 macro，不能改叙事。

### 3.3 关键决策：0225 帧烘焙定稿 vs 稀疏草稿

| 形态 | 帧数 | 用途 |
|------|------|------|
| 稀疏草稿 | ~40 关键帧 | Pomot round1/2 预览（速度快） |
| 烘焙定稿 | 150 帧 | export 送 Wan（精度高） |

**教训**：某次用稀疏草稿送 Wan → 节拍表只有 40 个变帧点，Wan 在中间补的帧情绪不对。**export 必须用烘焙定稿**。

### 3.4 关键决策：export 才渲染 MP4

| 时机 | 问题 | 结论 |
|------|------|------|
| Pomot round1/2 就渲 MP4 | MP4 渲染费时（约 3-5 秒），每次改都要等 | ❌ 用户体验差 |
| **export 时再渲染** | 编辑时不出 MP4，最后一次性渲染 + 打包 | ✅ 正选 |

**门户流程**：
```text
① POST /api/portal/pomot/round1   → 02 + 04 + wan±（无 MP4）
② POST /api/portal/save            → 落盘 01/02/04
③ POST /api/portal/render-preview  → 可选，仅看 03 底模
④ POST /api/portal/export          → 渲 MP4 + 打包扩散引擎包/
```

### 4.2 Step 2：节拍表编译（自动）

#### 4.2.1 节拍表是什么

节拍表是 **02_烘焙.json 的人话翻译版**，负责告诉 Wan 每个通道的数值变化在「演什么」。

#### 4.2.2 节拍表六段结构

```text
① # 扩散节拍表（12 通道 · 由 02 导出）
   文件头：情绪名、来源路径、形态（烘焙/稀疏）、物种

② ## 全局阶段
   蓄力 → 启动 → 保持 → 缓和
   （来自 02 的 energy_phases）

③ ## 各通道脉冲（核心）
   - **pupil_x**（视线左右）: t0=0.0, t17=0.34, t23=0.3, ...
     → 节拍：扫视方向；牵动注视与头部微转暗示
   - **blink**（眼睑开合）: t0=0.0, t12=0.0, t17=0.12, ...
     → 节拍：眼睑脉冲；唇颊放松/微收节奏
   ... // 共 12 个通道

④ ## 时间轴汇合（变帧时刻）
   0, 12, 17, 23, 32, 55, 83, 86, 90, 120, 149

⑤ ## 给扩散的硬约束
   - 扫视过冲帧(约17)为全脸张力高峰
   - 轻眨帧(约86)为全局微释放
   - 远景镜头也需保持脉冲语义

⑥ ## 出厂质检（若有）
   （记录节拍表自身的质检结果）
```

#### 4.2.3 关键机制：变帧检测

从 12 通道 × 150 帧中自动识别「值变化超过阈值」的关键帧：

```python
# 本质逻辑
prev_v = None
for k in keyframes:
    t, v = k["t"], k["v"]
    if prev_v is None or abs(v - prev_v) > 0.002:
        frames.add(t)  # 只有值变化时才记录
    prev_v = v
```

**blink 特殊处理**：强制保留非零峰（即使变化小于阈值），防止眨眼被过滤掉。

#### 4.3.2 正向 Prompt 三层

```text
[L1] 品种/身份/质感层
  林青霞（气质参考，不换客户脸），室内暗光，电影质感

[L2] 情绪视觉词层
  情绪浓度100，委屈，眼眶微红，视线低垂，眉尖微蹙

[L3] 严格跟随控制序列
  眉毛与眼部的运动严格跟随控制序列的节奏与幅度
  整体节奏紧跟眉眼控制序列的节奏与幅度
  眉眼以外可自然发挥，情绪起伏每一拍与控制序列对齐
```

**L3 是关键**：告诉 Wan 眼眉节奏必须跟 MP4 对齐，不能自由发挥。

#### 4.3.4 负向 Prompt 禁区

```

```

⚠️ 负向 **不得包含** 节拍表、叙事、通道名。

#### 4.6.4 Wan 扩散引擎参数调优表

以下是 Wan Fun Control 节点全部可调参数及其对输出质量的影响。**参数之间耦合性强**，改一个往往需联动调其他。

| 参数 | 影响 | wan_preview 推荐 | wan_final 推荐 | 调优原则 |
|------|------|-----------------|---------------|----------|
| **Steps** | 采样步数。越多越细腻，但边际递减 | 15~20（快出方向） | **40~50**（质感足） | steps↑ → CFG 可略↓；steps<30 必有廉价感 |
| **CFG Scale** | prompt 贴合度。高=更严格跟文本，低=模型自由发挥 | 5.0~6.0 | **5.5~7.0** | 眼眉精确场景用 6.0+；叙事驱动场景可降至 5.5 |
| **Sampler** | 采样器算法 | `euler`（最快） | **`dpm++ 2m karras`**（质感最好） | preview 用 euler 省时，final 必须换 dpm++ |
| **Scheduler** | 噪声调度策略 | `normal` | **`karras`**（配合 dpm++，高光保留好） | karras 对暗光/电影质感更好 |
| **Seed** | 随机噪声种子 | **多 seed 盲选**（~10 个） | 用 preview 最佳 seed | 同一 seed 在不同 steps/CFG 下效果不同，先定其他参数再定 seed |
| **Control Strength** | control_video 控制力。1.0=严格跟底膜，0.5=半自由 | 0.8~1.0 | **0.85~1.0** | 眼眉精确场景必须 ≥0.85；太低 → 眼眉失控 |
| **Denoise Strength** | 去噪强度（i2v 首帧保留度）。1.0=完全重绘 | 0.85~0.95 | **0.90~0.95** | 保留参考图五官；<0.85 → 脸变；>0.95 → 太死板 |
| **Resolution** | 输出分辨率 | 768×432（16:9）或 **854×480**（接近 16:9） | 同 preview | 保持 16:9 比例；不用 1:1（人像纵向构图浪费像素） |
| **Width / Height** | 具体宽高像素 | W=768 H=432 或 W=854 H=480 | 同 preview | 宽高必须能被 8 整除；推荐 854×480 |
| **Model** | Wan 模型变体 | `wan2.1-i2v-v1` | 同 preview | 用 i2v（image-to-video）系列，不用 t2v |
| **CLIP Skip** | 跳过 CLIP 末几层。1=不跳，2=跳末层 | 2 | **2** | skip=2 减少过拟合文本风格，对写实人像更好 |
| **VAE** | 解码器 | 模型自带 VAE | 同 preview | 不额外指定 |

##### 参数调优决策树

```text
输出质感不够好？
  ├── Steps < 40 ? → 提到 40~50（最优先）
  ├── Sampler 不是 dpm++ ? → 换 dpm++ 2m karras
  ├── CFG < 5.5 ? → 提到 6.0
  ├── 眼眉位置对了但动得不自然？
  │     └── Control Strength 降到 0.85（给 Wan 一点自由发挥空间）
  ├── 眼眉完全失控（没跟底膜）？
  │     └── Control Strength 提到 1.0
  ├── 脸变了不像本人？
  │     └── Denoise Strength 提到 0.95 + 检查 start_image 是否有遮挡
  ├── 整体廉价感/塑料光？
  │     └── 换 karras scheduler + CLIP Skip=2 + negative 加「塑料感、过锐」
  └── 多次生成都不好？
        └── 换 seed（最廉价方案），试 5~10 个 seed 再调参数
```

##### 参数耦合矩阵

| 调整 | 需联动调整 |
|------|-----------|
| steps↑（如 20→50） | CFG ← 可微降 0.5（steps 高了 prompt 已经跟得紧） |
| CFG↑（如 5.5→7.0） | 检查负向是否需要强化（过高 CFG 易引入 artifact） |
| Control Strength↑ | Denoise ↑ 同步（控制力强了，首帧保留也要加强） |
| 换 dpm++ sampler | 必须同时换 karras scheduler（dpm++ + normal = 边缘闪烁） |
| 提分辨率 | 大幅提分辨率（如 1080p）→ 显存暴增，NVME 溢出；480p 最佳 |

##### 显存与时间预算

| 参数 | 显存占用 | 单次生成时间（RTX 3090） |
|------|---------|------------------------|
| wan_preview（49f/steps 20） | ~8 GB | ~40 秒 |
| wan_final（150f/steps 40） | ~16 GB | ~5 分钟 |
| wan_final（150f/steps 50） | ~18 GB | ~7 分钟 |
| 提分辨率到 1280×720 | 超 24 GB ❌ | 接近不可用 |

**定稿推荐配置**：steps=40 · CFG=6.0 · dpm++ 2m karras · Control Strength=0.9 · Denoise=0.93 · 854×480 · Seed 盲选最佳
