## 一、概述（What）

### 1.1 本文件管什么

本文定义 **节奏说明书（Rhythm Specification）** 的格式规范、生成方式、消费方式。

节奏说明书是整个系统中**唯一一份既是机器生成、又是人类可读的交付物**。

### 1.2 管辖范围

✅ 节奏说明书的格式模板
✅ 每个通道的节拍说明规则
✅ 节奏说明书与指令集的对应关系
✅ 节奏说明书如何被扩散引擎消费
✅ 节奏说明书与客户提示词的关系

### 1.3 边界（非管辖）

❌ 不涉及 12 通道指令集的生成（见 [`01_十二通道与全量帧格式.md`](../04_通道编译/01_十二通道与全量帧格式.md)）
❌ 不涉及工程底膜的渲染（见 [`工程底膜驱动规范.md`](../07_工程底膜/工程底膜驱动规范.md)）
❌ 不涉及客户叙事提示词的撰写（由资产库人格包自定义）
❌ 不涉及 OpenCV 渲染管线的实现（见 [`affine_renderer.py`](gaze_engine/human/affine_renderer.py)）

### 1.4 本环节的定义

在指令集与扩散引擎之间，有一段语义鸿沟：

```
指令集（数字）：   pupil_x: 0.0 → 0.34 → 0.3 → 0.22 → 0.0
                  └──────────────────────────────────────────┘
                    Wan 看不懂这些数字在"演什么"

节奏说明书（文本）： pupil_x → 节拍：扫视方向；牵动注视与头部微转暗示
                  └──────────────────────────────────────────┘
                    Wan 读懂了：哦，这是"扫视"
```

节奏说明书就是填补这段语义鸿沟的桥梁。

## 二、理论依据（Theory）

### 2.1 扩散引擎的输入限制

Wan 2.1 这类视频扩散模型接受两种输入：
1. **图像输入**：底膜帧序列（像素级控制）
2. **文本输入**：Prompt + 节拍描述（语义级控制）

底膜告诉 Wan **"眼睛长什么样"**，节奏说明书告诉 Wan **"眼睛在演什么情绪"**。

### 2.2 两路输入的分工

```
Wan 输入         控制什么        缺了会怎样
─────────────────────────────────────────────────
底膜帧序列     几何位置           眼睛形状正确但表情空洞
节奏说明书     情绪节奏           有动作但不知道在演什么
叙事 Prompt    场景故事           方向感对但不知道在拍什么
参考图         身份特征           不知道画的是林青霞还是狗
```

**四种输入缺一不可。**

### 2.3 为什么需要节奏说明书（而非纯数字）

| 对比 | 纯 JSON 数字 | 节奏说明书 |
|------|------------|-----------|
| Wan 能否直接理解 | ❌ 不能 | ✅ 能 |
| LLM 能否二次修改 | ❌ 难以理解 | ✅ 可直接编辑 |
| 客户能否看懂 | ❌ 完全看不懂 | ✅ 可以提出修改意见 |
| 不同物种切换 | 需要改代码 | 只改文本就行 |

## 三、为什么（Why）

### 3.1 解决的问题

| 问题 | 没有节奏说明书 | 有了节奏说明书 |
|------|-------------|--------------|
| Wan 不理解通道语义 | 瞳孔缩放=情绪浓度 → Wan 当成几何变化 | 文本说明"瞳孔放大=情绪上升" |
| 不同景别表达不一致 | 特写有表情，全景面无表情 | 节拍说明告诉 Wan 全景也要跟随节奏 |
| 客户要改节奏 | 需要重新编译整个指令集 | 直接改节拍表文本即可 LLM 重写 |
| 跨物种复用 | 每物种写一套新代码 | 同一套格式，改通道语义说明就行 |

### 3.2 节奏说明书的价值定位

```
在系统中的位置：
                                                 ┌──────────┐
                  ┌─────────────────────────────│ 客户叙事  │
                  │                              │ 提示词    │
                  │                              └────┬─────┘
                  │                                   │
┌──────────┐     │     ┌──────────────┐     ┌────────▼────────┐
│ 指令集   │─────┼────→│ 节奏说明书    │────→│    Wan 引擎     │
│ 12×150  │     │     │ 05_节拍表.txt │     │  + 底膜+参考图 │
└──────────┘     │     └──────────────┘     └─────────────────┘
                 │
                 └────→ 工程底膜帧序列（直接像素控制）
```

节奏说明书是唯一**同时流向三层**的中间件：给 Wan 做语义理解、给客户做修改入口、给开发者做跨物种适配。

## 四、怎么做（How）

### 4.1 节奏说明书的格式模板

每份节奏说明书包含以下部分：

```
# 扩散节拍表（12 通道 · 由 02 导出）
# 情绪: {情绪名称}
# 来源: {来源路径}
# 形态: 烘焙定稿 / 稀疏草稿
# 用途: Wan/扩散引擎节奏主钟；远景也保留脉冲语义

## 全局阶段
{蓄力} → {启动} → {保持} → {缓和}

## 各通道脉冲
- **pupil_x**（视线左右）: t0=v0, t1=v1, t2=v2, ...
  → 节拍：扫视方向；牵动注视与头部微转暗示
- **pupil_y**（视线上下）: t0=v0, t1=v1, t2=v2, ...
  → 节拍：视线沉降；下颌与颈后线条随之处置
- **blink**（眼睑开合）: t0=v0, t1=v1, ...
  → 节拍：眼睑脉冲；唇颊放松/微收节奏
- **eyebrow**（眉压 / 猫狗:耳位）: t0=v0, t1=v1, ...
  → 节拍：眉压 / 猫:耳位耷拉 / 狗:耳位下垂；对应物种自适应
- **pupil_scale**（瞳孔缩放）: t0=v0, t1=v1, ...
  → 节拍：瞳孔收缩；情绪浓度与面部收紧
- **iris_scale**（虹膜圈）: t0=v0, t1=v1, ...
  → 节拍：虹膜显露；眼神锐度
- **cornea_bulge**（角膜鼓起）: t0=v0, t1=v1, ...
  → 节拍：目光有神；额部提亮节奏
- **squint**（眯眼眶压）: t0=v0, t1=v1, ...
  → 节拍：眶挤压；鼻翼法令与面颊走向
- **brow_raise**（挑眉 / 猫:耳尖 / 狗:眉脊）: t0=v0, t1=v1, ...
  → 节拍：挑眉 / 猫:耳尖微颤 / 狗:眉脊微动
- **lid_upper**（上眼睑）: t0=v0, t1=v1, ...
  → 节拍：上睑压；额头纹与上脸紧张
- **lid_lower**（下眼睑）: t0=v0, t1=v1, ...
  → 节拍：下睑；口周与颊部微绷
- **eye_gloss**（眼湿润高光）: t0=v0, t1=v1, ...
  → 节拍：湿润高光；皮肤质感与喉颈光泽联动

## 时间轴汇合（变帧时刻）
t0, t1, t2, t3, t4, t5, ...

## 给扩散的硬约束
{尾部摘要}
```

### 4.2 每个通道的节拍说明来源

节拍说明的文本来自 [`channel_contract.py`](gaze_engine/_shared/channel_contract.py) 的 `DIFFUSION_HINTS` 字典。

对于猫/狗等物种，`DIFFUSION_HINTS` 中的标注已包含物种自适应说明（如 `"eyebrow": "猫:耳位耷拉程度"`）。

### 4.3 工程实现

节奏说明书由 [`export_diffusion_metronome.py`](gaze_engine/_shared/export_diffusion_metronome.py) 自动生成：

```python
def build_metronome_text(sparse: dict, *, source_path: str = "") -> str:
    from channel_contract import CANONICAL_KEYS, CHANNEL_LABELS_ZH, DIFFUSION_HINTS
    
    lines = [

        f"# 情绪: {sparse.get('mood', '')}",
        "",
        "## 全局阶段",
        " → ".join(sparse.get("energy_phases") or []),
        "",
        "## 各通道脉冲",
    ]
    for key in CANONICAL_KEYS:
        track = tracks.get(key, {})
        kfs = track.get("keyframes", [])
        hint = DIFFUSION_HINTS.get(key, "")
        # 输出: - **key**（label）: t0=v0, t1=v1, ...
        #         → 节拍：hint
    return "\n".join(lines)
```

### 4.4 节奏说明书如何被 Wan 消费

扩散引擎的 Prompt 结构：

```
【正向】
{物种/身份描述}，{场景描述}，{灯光/质感描述}，
情绪浓度 {N}，{情绪标签}，
眉毛与耳朵的运动严格跟随控制序列的节奏与幅度，
整体节奏紧跟眉眼控制序列的节奏与幅度，
眉眼以外可自然发挥，情绪起伏每一拍与眉眼对齐，
{景别}，单人，高清。

【扩散节拍表】
{节奏说明书的完整文本}

【叙事】
{客户提供的 5 秒故事描述}

【负向】
色调艳丽，过曝，模糊，字幕，低质量，丑陋，畸形，...
```

**关键规则**：节奏说明书中的每个 `→ 节拍：` 描述，Wan 必须遵守——它定义了每个通道的脉冲在画面中的物理/情绪意义。

### 4.5 节奏说明书 + 底膜 + 参考图 + 叙事 Prompt 的配合

```
┌─────────────────────────────────────────────────────┐
│                    Wan 输入                          │
├─────────────────────────────────────────────────────┤
│  参考图（谁）   ─→  身份特征                         │
│  底膜序列（在哪） ─→  每帧的几何位置（R/G/B 通道）   │
│  节奏说明书（什么情绪）─→  每通道脉冲的语义含义       │
│  叙事 Prompt（发生什么）─→  5 秒故事                 │
└─────────────────────────────────────────────────────┘
                          │
                          ▼
                ┌─────────────────┐
                │  Wan 2.1 引擎    │
                │  理解：           │
                │  - 画的是谁       │
                │  - 眼睛/耳朵在哪  │
                │  - 在演什么情绪   │
                │  - 场景故事线     │
                └────────┬────────┘
                         │
                         ▼
                ┌─────────────────┐
                │  5 秒视频        │
                │  - 眼睛:底膜对齐 │
                │  - 全身:节奏对齐 │
                │  - 镜头:拐点对齐 │
                └─────────────────┘
```

### 4.6 无面部景别的处理

当镜头切到无面部画面（空镜、全景、背影）时：
- 底膜不可见（不驱动）
- **节奏说明书持续生效**：Wan 根据各通道的脉冲曲线调整：
  - 剪接点对齐脉冲拐点
  - 全景中的身体语言对齐 `blink`/`eyebrow` 的节奏
  - 空镜的持续时间对齐脉冲的保持段

## 六、节奏说明书与指令集的对应关系

```
指令集（机器数字）                   节奏说明书（人类语义）
────────────────────────────────────────────────────────
pupil_x: 0.0→0.34→0.3→0.22→0.0   → 节拍：扫视方向
pupil_y: 0.0→-0.13→-0.09→0.0     → 节拍：视线沉降
blink: 0.0→0.12→0.0               → 节拍：眼睑脉冲
eyebrow: 0.3→0.1→0.0              → 节拍：耳位耷拉（猫狗）
pupil_scale: 0.0→0.8→0.2          → 节拍：瞳孔缩放
eye_gloss: 0.2→0.8→0.4            → 节拍：湿润高光
```

**数字到文本的翻译规则**：
- 通道值从 0 升到 1 → "……增强/上升/收紧"
- 通道值从 1 降到 0 → "……减弱/下降/放松"
- 通道值快速跳变 → "……冲击/抖动/脉冲"
- 通道值平缓变化 → "……缓慢过渡/渐变"
