## 一、概述（What）

### 1.1 本文件管什么

本文定义 **04_给视频生成的Prompt.txt** 的完整拼装规范，包括：

| 环节 | 范围 |
|------|------|
| ✅ 文件整体结构 | 五段式模板：文件头 → 正向 → 节拍表 → 叙事 → 负向 |
| ✅ 各段来源 | 每段的输入数据是什么、从哪里来、谁生成 |
| ✅ 动态部分 vs 固定部分 | 哪些是随 02_烘焙.json 动态生成，哪些是固定模板 |
| ✅ 拼装逻辑 | Python 伪代码 |
| ✅ 物种自适应 | 狗/猫/人的 Prompt 差异 |
| ✅ 验收标准 | 拼装后的 04_Prompt.txt 通过哪些检查才算合格 |

### 1.2 04_Prompt.txt 是什么

```
04_给视频生成的Prompt.txt 是扩散引擎 Wan 的语义控制信号。
它与 OpenCV 线条图 MP4（视觉控制信号）一起送扩散引擎。

扩散引擎同时接收：
  ① OpenCV 线条图 MP4  → 像素级控制（眼眶/眉脊/瞳孔位置）
  ② 04_Prompt.txt      → 语义级控制（演什么情绪、什么节奏）
```

### 1.3 边界（非管辖）

| ❌ 不管 | 原因 |
|---------|------|
| 05_扩散节拍表.txt 的生成 | 见 [`节奏说明书.md`](../01_总纲/节奏说明书.md)，由 [`rhythm_compiler.py`](../../gaze_engine/_shared/rhythm_compiler.py) 实现 |
| OpenCV 线条图 MP4 的渲染 | 见 [`工程底膜合同.md`](../03_工程底膜/工程底膜合同.md) |
| 客户叙事文本的提取 | 见 [`pomot合成规范.md`](../06_架构/pomot合成规范.md) 的 `nl_splitter` |
| 情绪路由 / 品种选择 | 见 [`pomot合成规范.md`](../06_架构/pomot合成规范.md) 的 `emotion_router` |

### 1.4 关键术语

| 术语 | 含义 |
|------|------|
| **正向段** | Prompt 的正面描述：物种、场景、灯光、情绪、节奏要求 |
| **节拍段** | 05_扩散节拍表.txt 的完整内容：12 通道 × 关键帧 + 节拍说明 |
| **叙事段** | 客户原始描述：如"委屈的跑回了笼子再回头看了一眼" |
| **负向段** | 负面描述：需要避免的画面问题 |
| **动态部分** | 每轮管线执行后重新生成的部分（节拍表、叙事、元信息） |
| **固定部分** | 不随管线变动而变的部分（负向模板、prompt 框架句式） |

## 二、理论依据（Theory）

### 2.1 理论依据链

```
① 扩散引擎 Wan 接受两路输入：
     - 图像：控制几何形状（线条图给出眼眶/瞳孔/眉脊位置）
     - 文本：控制语义（Prompt 说明演什么情绪、什么场景）
   → 文本输入必须包含"节拍"信息，否则线条图只是几何形状，
     扩散引擎不知道这些形状在表达什么情绪

② 同一组线条图可以被扩散引擎理解为不同情绪：
     - 如果只说"狗委屈"，扩散引擎可能把瞳孔缩小理解为"愤怒"
     - 如果加上节拍说明"瞳孔缩小 = 情绪浓度上升"，扩散引擎才知道方向
   → 节拍表必须嵌入 Prompt，让每个通道的脉冲曲线有语义

③ 扩散引擎的文本输入是"一张大白纸"——不给负向就会乱画：
     - 没有负向 Prompt，扩散引擎可能产生过曝、模糊、畸形
   → 负向段是必选的，不能省略

④ 客户叙事与节拍表必须共存于同一个 Prompt：
     - 叙事告诉扩散引擎"拍什么故事"
     - 节拍表告诉扩散引擎"故事的情绪节奏怎么走"
   → 两者缺一不可，且互不覆盖
```

### 2.2 设计依据

```
设计决策                       依据
────────────────────────────────────────────────
04_Prompt 从 02_烘焙.json       保证线条图、节拍表、Prompt
实时生成而非静态模板             三者同源同版本

五段模板结构                    覆盖扩散引擎需要的全部信息：
                               （参考图身份→场景→节奏→故事→约束）

正向段留空给 LLM 填充           LLM 更擅长根据物种/情绪/场景
                              生成具体的质感/灯光描述

节拍段复用 05_节拍表.txt        不重复造轮子，已有 rhythm_compiler 生成
```

## 三、为什么这样做（Why）

### 3.1 关键决策

#### 决策 1：五段模板结构

```
备选方案:
  方案 A（选中）: 五段模板 —— 文件头 / 正向 / 节拍表 / 叙事 / 负向
     - 每段职责清晰，可以单独修改和验收
  方案 B: 一段式，整段由 LLM 生成
     - 问题: 无法保证节拍表的准确性（LLM 会乱编数值）
     - 问题: 客户叙事可能被 LLM 改写
  方案 C: 只送线条图，不送 Prompt 文本
     - ⚠️ 扩散引擎不知道线条图在表达什么情绪
     - 结果: 画面几何形状正确，但表情空洞

选择理由:
  五段模板让每段有独立的生成/修改来源：
  - 正向段: 固定框架 + LLM 补充质感描述
  - 节拍表: 从 02_烘焙.json 自动生成（精确，不改）
  - 叙事段: 客户原文（不经过 LLM，保留原意）
  - 负向段: 固定模板
```

#### 决策 2：节拍表段直接用 05_扩散节拍表.txt 的完整内容

```
备选方案:
  方案 A（选中）: 直接插入 05_扩散节拍表.txt 全文
     - 保证节奏说明书与 Prompt 完全一致
     - 由 rhythm_compiler.py 生成，不需要额外处理
  方案 B: 从 05_节拍表中提取摘要
     - 问题: 摘要可能丢失关键通道信息
     - ⚠️ 扩散引擎需要完整的 12 通道节拍才能正确驱动

选择理由:
  05_节拍表.txt 已经是从 02_烘焙.json 精确生成的节奏说明书，
  直接复用确保零误差。不需要在 04_Prompt 中重新定义节拍格式。
```

#### 决策 3：正向段使用固定框架 + LLM 补充

```
备选方案:
  方案 A（选中）: 固定框架句子（物种/品种/情绪/节奏规则）+ LLM 填质感
     - 框架保证"情绪浓度、节奏跟随"等关键信息不被遗漏
     - LLM 负责填充"真实皮肤、柔和光线、武侠质感"等艺术描述
  方案 B: 全由 LLM 生成
     - 问题: LLM 可能遗漏"眼眉跟随控制序列"的关键约束
  方案 C: 全固定不调用 LLM
     - 问题: 太死板，缺乏针对具体场景的艺术描述

选择理由:
  框架保证了扩散引擎必须遵守的约束，
  LLM 补充分保持了画面的艺术灵活性。
```

### 3.2 历史教训

⚠️ **静态模板陷阱**：当前预设资产中的 `04_给视频生成的Prompt.txt` 是手写静态文件。管线改滑杆后 02_烘焙.json 更新了，线条图变了，但 04_还是旧的。Pomot 的 assembler 必须从 02_实时生成 04_，不保留静态模板。

⚠️ **叙事段被 LLM 改写**：之前的流程让 LLM 重写客户叙事，导致"委屈的跑回了笼子"被改成"一只悲伤的狗在移动"。客户叙事段必须**客户原文直出**，不经过任何 LLM 改写。

⚠️ **负向段被省略**：早期版本不传负向 Prompt，扩散引擎经常产生过曝、模糊、畸形画面。负向段是**必选**的。

## 四、怎么实现（How）

### 4.1 04_Prompt.txt 的五段模板

```
┌──────────────────────────────────────────────────┐
│  # 给视频生成引擎的说明                            │
│  (文件头: 来源说明，人类可读)                       │
├──────────────────────────────────────────────────┤
│  ## 正向 Prompt                                   │
│  {物种/品种}，{场景/质感 by LLM}，                 │
│  情绪浓度 100，{情绪标签}，                        │
│  眉毛与耳朵的运动严格跟随控制序列的节奏与幅度，       │
│  ...                                              │
├──────────────────────────────────────────────────┤
│  ## 扩散节拍表                                     │
│  (05_扩散节拍表.txt 的完整内容)                     │
│  - **pupil_x**（视线左右）: t0=0.0, t17=0.34...   │
│    → 节拍：扫视方向                                 │
│  ...                                              │
├──────────────────────────────────────────────────┤
│  ## 叙事                                           │
│  {客户原始叙事文本，不做任何修改}                    │
├──────────────────────────────────────────────────┤
│  ## 负向 Prompt                                    │
│  色调艳丽，过曝，模糊，字幕，...                    │
└──────────────────────────────────────────────────┘
```

### 4.2 各段的输入来源

| 段 | 内容 | 来源 | 生成方式 | 是否动态 |
|----|------|------|---------|---------|
| **文件头** | `# 给视频生成引擎的说明` + 来源说明 | 固定 + 元信息 | `f"# 情绪: {emotion}"` 等 | ✅ 动态（情绪名/物种名） |
| **正向段** | 物种/品种/场景/节奏约束 | 物种预设 + LLM 补充 | 框架填充 + LLM 可选 | ✅ 动态（物种/品种） |
| **节拍表段** | 05_扩散节拍表.txt 完整内容 | `rhythm_compiler.build_metronome_text()` | 从 02_烘焙.json 自动生成 | ✅ 动态（每轮不同） |
| **叙事段** | 客户原始叙事文本 | `nl_splitter` 输出的 action | 客户原文直出，不做修改 | ✅ 动态（客户说的） |
| **负向段** | 负面约束列表 | 固定模板 | 字符串常量 | ❌ 固定 |

### 4.3 正向段的框架规则

#### 4.3.1 框架句子（必选，生成时填入）

```
{物种描述}，{场景/灯光/质感描述 by LLM}，
情绪浓度 {emotion_intensity}，{mood_tags}，
眉毛与耳朵的运动严格跟随控制序列的节奏与幅度，
整体节奏紧跟眉眼控制序列的节奏与幅度，
眉眼以外可自然发挥，情绪起伏每一拍与眉眼对齐，
{景别}，{subject_type}，高清。
```

| 占位符 | 填充规则 | 示例 |
|--------|---------|------|
| `{物种描述}` | `species/breed` + 照片身份 | `贵宾犬` / `林青霞` |
| `{场景/灯光/质感描述}` | 留空由 LLM 补充，或使用预设默认 | `柔和光线，真实毛发` |
| `{emotion_intensity}` | 固定 `100` | `100` |
| `{mood_tags}` | 情绪情绪标签 | `委屈` |
| `{景别}` | 按客户需求 | `正面半身` |
| `{subject_type}` | `狗狗`（狗）/ `猫咪`（猫）/ `单人`（人） | `狗狗` |

#### 4.3.2 物种自适应的框架差异

| 物种 | 正向段差异 |
|------|-----------|
| `human` | `正面半身肖像，真实皮肤，{人格气质描述}（气质参考，不换客户脸）` |
| `dog` | `{品种}犬，真实毛发，{场景描述}，耳朵姿态跟随控制序列，尾巴与全身节奏联动` |
| `cat` | `{品种}猫，真实毛发，{场景描述}，耳朵姿态跟随控制序列，尾巴与全身节奏联动` |

#### 4.3.3 LLM 填充场景描述（可选增强）

当需要 LLM 生成 `{场景/灯光/质感描述}` 时，调用：

```python
def llm_fill_scene_description(species, breed, emotion, customer_action):
    prompt = f"请为以下场景生成一句画面质感描述（20字以内）：\n"
    prompt += f"物种: {species}, 品种: {breed}, 情绪: {emotion}\n"
    prompt += f"叙事: {customer_action}"
    return llm_call(prompt)  # 返回如 "柔和光线，真实毛发，室内暖光"
```

如果不使用 LLM，该段留空或使用预设默认值。

### 4.4 完整拼装逻辑

```python
def assemble_diffusion_prompt(
    baked_json: dict,               # 02_烘焙_真人律.json
    customer_action: str,           # 客户叙事（来自 nl_splitter）
    metadata: dict,                 # 元信息
    species: str = "human",         # "human" | "dog" | "cat"
    breed: str = "",                # 品种名（宠物用）
    emotion: str = "",              # 情绪名
    mood_tags: list = None,         # 情绪标签列表
    scene_desc: str = "",           # 场景描述（可选，空则 LLM 填或省略）
    use_llm_scene: bool = False,    # 是否用 LLM 生成场景描述
) -> str:
    """拼装 04_给视频生成的Prompt.txt"""

    # ── Step 1: 生成 05_扩散节拍表.txt 文本 ──
    from gaze_engine._shared.rhythm_compiler import build_metronome_text
    beat_text = build_metronome_text(baked_json, species=species)

    # ── Step 2: 填充正向段 ──
    mood_tags = mood_tags or [emotion]
    subject_map = {"dog": "狗狗", "cat": "猫咪", "human": "单人"}
    subject_type = subject_map.get(species, "单人")

    # 物种自适应的开头
    if species == "human":
        species_desc = metadata.get("persona_ref", breed or "人物")
        species_line = f"{species_desc}（气质参考，不换客户脸）"
    elif species == "dog":
        species_line = f"{breed}犬，真实毛发"
    elif species == "cat":
        species_line = f"{breed}猫，真实毛发"
    else:
        species_line = breed or "人物"

    # 场景描述（LLM 或固定）
    if not scene_desc and use_llm_scene:
        scene_desc = llm_fill_scene_description(species, breed, emotion, customer_action)

    positive_parts = [
        species_line,
        scene_desc or "",
        f"情绪浓度100，{'、'.join(mood_tags)}",
        "眉毛与耳朵的运动严格跟随控制序列的节奏与幅度",
        "整体节奏紧跟眉眼控制序列的节奏与幅度",
        "眉眼以外可自然发挥，情绪起伏每一拍与眉眼对齐",
        f"{subject_type}，高清",
    ]
    positive_text = "，".join(p for p in positive_parts if p)

    # ── Step 3: 负向段（固定模板） ──
    negative_text = (
        "色调艳丽，过曝，模糊，字幕，整体发灰，低质量，丑陋，畸形，"
        "脸变形，换脸，多余人物，眉眼与画面不同步，"
        "乱动脱节，情绪浓度不足，涣散无神，夸张鬼脸，杂乱背景"
    )

    # ── Step 4: 拼装五段 ──
    emotion_name = emotion or baked_json.get("mood", "未知")
    lines = [
        f"# 给视频生成引擎的说明",
        f"# 情绪: {emotion_name}",
        f"# 物种: {species}",
        f"# 品种: {breed or '-'}",
        f"# 来源: 04_Prompt.txt · 从 02_烘焙.json 自动拼装",
        "",
        "## 正向 Prompt",
        positive_text,
        "",
        "## 扩散节拍表",
        beat_text,
        "",
        "## 叙事",
        customer_action or "（无客户叙事）",
        "",
        "## 负向 Prompt",
        negative_text,
        "",
    ]
    return "\n".join(lines)
```


**输出**（04_给视频生成的Prompt.txt）：

```

# 品种: 贵宾犬

贵宾犬，真实毛发，情绪浓度100，委屈，眉毛与耳朵的运动严格跟随控制序列的节奏与幅度，整体节奏紧跟眉眼控制序列的节奏与幅度，眉眼以外可自然发挥，情绪起伏每一拍与眉眼对齐，狗狗，高清。

...eyebrow: t0=0.7, t30=0.3...
...）

## 叙事
委屈的跑回了笼子再回头看了一眼

## 负向 Prompt
色调艳丽，过曝，模糊，字幕，整体发灰，低质量，丑陋，畸形，脸变形，换脸，多余人物，眉眼与画面不同步，乱动脱节，情绪浓度不足，涣散无神，夸张鬼脸，杂乱背景
```

### 4.6 两轮对话的 Prompt 变化

| 轮次 | 正向段 | 节拍表段 | 叙事段 | 负向段 |
|------|--------|---------|--------|--------|
| **第一轮** | `贵宾犬，真实毛发，情绪浓度100...` | 从 `02_v1.json` 生成 | `委屈的跑回了笼子再回头看了一眼` | 固定 |
| **第二轮** | 相同（只改情绪强度标签） | 从 `02_v2.json` 生成（数值有变化） | **相同**（叙事不随微调改变） | 固定 |

⚠️ **重要规则**：第二轮微调时，叙事段**不修改**。客户说"再委屈一点"只是改情绪强度，不改叙事情节。

## 4.8 Wan / Comfy 接线规范（交付物 → 节点输入）

`04_Prompt.txt` 是**归档用五段文本**；ComfyUI 的 Wan 工作流需要拆成两个 CLIP 字符串 + 一个控制视频。

### 4.8.1 送 Wan 的完整清单

| 节点输入 | 来源文件/字段 | 格式 |
|---------|--------------|------|
| `control_video` | `03_工程底模.mp4` | H.264 MP4，150 帧，RGB 三色底膜 |
| `start_image` | 客户参考照 | PNG/JPG |
| **positive CLIP** | `04` 的 **正向 + 扩散节拍表 + 叙事** 三段拼接 | UTF-8 纯文本 |
| **negative CLIP** | `04` 的 **负向 Prompt** 段 | UTF-8 纯文本 |

**不送 Wan：** `02_烘焙.json`、`01_滑杆包.json`、单独 `05_扩散节拍表.txt`（05 已嵌入 04）。

### 4.8.2 positive CLIP 具体写什么

**段 1 · 正向 Prompt（短，导演总要求）**

```text
贵宾犬，真实毛发，情绪浓度100，委屈·幼犬眼，眼耳与控制线的运动严格跟随控制序列的节奏与幅度，整体节奏紧跟眼耳控制序列的节奏与幅度，眼耳以外可自然发挥，情绪起伏每一拍与控制序列对齐，狗狗，高清
```

**段 2 · 扩散节拍表（长，从 02 自动生成）**

```text
# 扩散节拍表（12 通道 · 由 02 导出）
# 情绪: 委屈·幼犬眼
## 全局阶段
蓄力 → 启动 → 保持 → 缓和
## 各通道脉冲
- **pupil_x**（视线左右）: t0=0.0, t7=0.02, …
  → 节拍：扫视方向；牵动注视与头部微转暗示
…（12 通道全文）…
## 给扩散的硬约束（摘要）
…
```

**段 3 · 叙事（短，客户 action）**

```text
回头看一眼
```

**拼接规则：** 三段之间用空行 `\n\n` 连接 → 得到 `wan_positive_clip`。

### 4.8.3 negative CLIP

固定质量负向串（三物种共用，见 §4.3 负向模板），**不要**把节拍表或叙事放进 negative。

### 4.8.4 同源约束（P0）

| 规则 | 说明 |
|------|------|
| 单一真源 | `02_烘焙.json` 的 `channel_tracks` |
| 同步产物 | 同一次 `revision` 必须同时生成 MP4 与 04 |
| 校验 | `03_工程底模.meta.json` 的 `baked_revision` == `02.revision` |
| 代码 | `DiffusionPromptAssembler.split_for_wan(prompt_04)` |
