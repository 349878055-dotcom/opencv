## 一、概述（What）

### 本文件管什么

定义 **门户勾选一對** 时的合成规则：

```text
通用狗情绪（10 选 1）  +  狗品种（当前 1 个，可扩展 N 个）
        ↓
「这一条组合专属的能量曲线」= styled 12 通道 × 150 帧
```

### 核心约定（产品层一句话）

> **情绪写「戏怎么演」；品种写「这张脸怎么吃戏」。**  
> 同一种情绪 JSON **全狗种共用**；改情绪 **只改一处**，各品种通过 **固定偏移公式** 自动跟上。

### 管线位置

| 环节 | 输入 | 输出 | 谁定稿 |
|------|------|------|--------|
| ① 通用情绪 | `预设情绪包/dog/{情绪}.json` | **E(t)** + **pulse** | `02_情绪/狗/{情绪}.md` |
| ② 品种偏移 | `风格包/dog/{品种}/style.json` + `breed_matrix.json` | **base_offset / scale_factor**（+ 几何） | `05_人格化/狗/{品种}.md` |
| ③ **合成** | pulse + 品种偏移 | **styled**（组合能量曲线） | **本文** |
| ④ 后处理 | styled | prior / 质检 → **02_烘焙** | `dog/dog_pipeline.py` |
| ⑤ 底膜 | styled + SpeciesTemplate | 工程底膜 MP4 | `dog/affine_renderer.py` |

### 边界（非管辖）

| ❌ 不属于本文件 | 去哪改 |
|----------------|--------|
| 某一情绪的 push/power/hold 定稿 | `02_情绪/狗/{情绪}.md` |
| 某一品种的 blink 基线、眼型乘数 | `05_人格化/狗/{品种}.md` |
| 客户照片标定覆盖 | 客户资产库 `物种底膜模板.json` |
| 04 扩散 Prompt 文案 | `04_接口/扩散引擎提示词拼装规范.md` |

## 二、理论依据（Theory）

### 2.1 为什么要「情绪通用、品种偏移」

```
① 狗 10 种情绪是跨品种共用的「戏眼语法」（委屈、警觉、满足…）
   → 不应为贵宾、柯基各复制 10 份 JSON，否则改一次要改 N 遍

② 品种差异是「脸的结构 + 默认气质」，不是另一种情绪时间轴
   → 贵宾半阖眼基线高、田园扫视幅度大 → 用 offset/scale，不用改 E(t) 四段

③ 合成必须是线性可叠加的函数
   → 改情绪只动 pulse；改品种只动 base/scale；二者可独立验收
```

### 2.2 三层曲线定义（术语统一）

| 名称 | 维度 | 含义 | 是否含品种 |
|------|------|------|-----------|
| **E(t)** | 150 | 能量主钟（蓄→起→盯→收） | ❌ 仅情绪 |
| **pulse[ch,t]** | 12×150 | 物种通道上的「纯情绪动态」 | ❌ 仅情绪+狗 PAD |
| **styled[ch,t]** | 12×150 | **门户勾中组合的定稿能量曲线** | ✅ 情绪×品种 |

对外说的 **「这条贵宾委屈眼的能量曲线」** = **styled**，不是单独的 E(t)。

### 2.3 合成公式（动态层）

对每一通道 `ch`、每一帧 `t`：

```text
E(t)           = build_energy_envelope( emotion.macro, emotion.hold_seg )
pulse[ch, t]   = DogCompile( E(t), PAD(emotion), ear, … )    // 见 dog/envelope_compile.py
styled[ch, t]  = clamp01( base_offset[ch] + scale_factor[ch] × pulse[ch, t] )
```

- `base_offset` / `scale_factor` 来自 **品种**（`style.json` ≡ `breed_matrix.json` 同 id）
- **品种不参与** `build_energy_envelope()`，**不改** t_peak / t_hold0 / t_hold1

### 2.4 几何层（与动态并行，不替代 styled）

```text
SpeciesTemplate = 狗默认模板
                  × breed.template_scales（眼大小、眼型…）
                  × 客户标定（可选）
                  → OpenCV 渲染常量 + 耳/眉控制点
```

几何 **不写入** E(t)；渲染底膜时与 styled 通道 **同时使用**。

## 三、为什么这样做（Why）

### 3.1 关键决策

| 决策 | 备选 | 选择理由 |
|------|------|----------|
| **一种情绪一份 JSON，全品种共用** | 每种狗复制 10 份情绪 | 改「委屈更软」只改 1 个 JSON + 1 个 md，N 个品种自动继承 |
| **品种用 base+scale 乘 pulse，不改 E(t)** | 品种也改 macro | 避免「贵宾版委屈」和「田园版委屈」时间轴分叉，门户无法对比 |
| **pulse 作为中间态显式保留** | 情绪直接 styled | 便于调试：先验收纯情绪，再叠品种 |
| **style.json 与 breed_matrix 双写同步** | 只留一处 | 门户读 `预设资产/风格包/`；编译读 `breed_matrix.json` |

### 3.2 「改通用情绪，各狗种都要反映」的机制

**不是**人工去改每个品种的 md。

**而是**数学上保证：

```text
styled_breed(ch,t) = base_breed[ch] + scale_breed[ch] × pulse_new(ch,t)
```

当 `pulse_new` 因情绪 JSON 变化而变时，**同一 base/scale 下所有帧自动变**。

| 你改了情绪的什么 | pulse 哪里变 | 各品种 styled 如何跟 |
|----------------|-------------|---------------------|
| push↓ 更内收 | pupil_x/y 幅度整体变小 | 各品种 **同比例缩小**，基线仍由 base 拉开品种差 |
| hold→tremble | 保持段 ripple 变大 | 各品种 tremble **同相位**，幅度由 scale 调制 |
| power↑ peak 变高 | 全轨 envelope 抬高 | styled 线性随 pulse 抬高（scale 通道更明显） |
| ear 块 | eyebrow/brow_raise pulse | 品种 base 不改耳 JSON，但 styled 眉轨仍随 pulse 变 |

⚠️ **禁止**：在 `style.json` 里写「仅委屈·幼犬眼用」的 macro —— 那会破坏通用性，改情绪时该品种不会跟其它情绪对齐。

### 3.3 反例（禁止）

| ❌ 错误做法 | 后果 |
|------------|------|
| 为 `poodle_giant` 单独复制 `委屈·幼犬眼_poodle.json` | 改通用委屈要改 N 份，合同体系失效 |
| 在品种里改 E(t) 帧轴 | 同一情绪在不同品种「起势快慢不一致」，门户分组混乱 |
| 把品种 blink 基线写进情绪 JSON | 情绪不再通用，田园/贵宾无法共用 |

## 四、怎么实现（How）

### 4.1 资产与合同对应

| 层 | 磁盘真源 | 合同 |
|----|----------|------|
| 通用情绪 | `预设资产/预设情绪包/dog/{情绪名}.json` | `contracts/02_情绪/狗/{情绪名}.md` |
| 品种偏移 | `预设资产/风格包/dog/{id}/style.json` | `contracts/05_人格化/狗/{id}.md` |
| 品种矩阵 | `gaze_engine/dog/breed_matrix.json` | 与 style.json **数值一致** |
| 合成规则 | 本文 | — |

### 4.2 门户勾选 → 数据流

```text
用户勾选：情绪 = 委屈·幼犬眼 ，品种 = poodle_giant
  │
  ├─ 读 委屈·幼犬眼.json          → SliderPacket
  ├─ 读 poodle_giant/style.json   → base_offset, scale_factor
  │
  ▼
build_energy_envelope(pkt)         → E(t)
channels_from_envelope(…)          → pulse[12×150]
apply_breed_style(pulse, style)    → styled[12×150]    ← S5 已接入
apply_dog_prior / fix_dog_quality  → styled'
  │
  ▼
02_烘焙 channel_tracks             → 组合能量包落盘
  │
  parallel: adjust_template_for_breed("dog","poodle_giant") → 底膜几何
  ▼
工程底膜 MP4
```

### 4.3 代码映射

| 步骤 | 函数 | 文件 |
|------|------|------|
| E(t) | `build_energy_envelope()` | `_shared/envelope_compile.py` |

**实现状态（2026-05-27）**：S2～S5 均已通；见 [`人格品种与Et正交审计.md`](../../06_架构/人格品种与Et正交审计.md)

### 4.4 修改工作流（保证「改情绪全品种跟上」）

**只改通用情绪（例：委屈更软）**

1. 改 `contracts/02_情绪/狗/委屈·幼犬眼.md` §4 滑杆 / 读感  
2. 改 `预设资产/预设情绪包/dog/委屈·幼犬眼.json`  
3. **不要**改 `poodle_giant/style.json`  
4. 重跑 ③→⑤ 或门户导出  
5. 验收：贵宾、未来柯基… **同一 base/scale 下** pulse 变 → styled 自动变  

**只改某一品种（例：贵宾默认更半阖）**

1. 改 `contracts/05_人格化/狗/poodle_giant.md`  
2. 改 `style.json` + `breed_matrix.json` 同 id 的 base/scale  
3. **不要**改 `委屈·幼犬眼.json`  
4. 验收：**10 种情绪** 叠贵宾时都更半阖，委屈/警觉 **时间轴不变**  

### 4.5 数值示例（委屈·幼犬眼 × 巨型贵宾 · blink 通道）

| 量 | 来源 | 示例值 |
|----|------|--------|
| pulse[blink, t_hold] | 情绪编译 | ≈ 0.12（随 tremble 微抖） |
| base_offset[blink] | poodle_giant | 0.55 |
| scale_factor[blink] | poodle_giant | 0.25 |
| **styled[blink, t]** | 合成 | clamp(0.55 + 0.25 × 0.12) ≈ **0.58** |

若把情绪 JSON 的 power 下调使 pulse[blink]→0.08，则 styled→0.57 —— **品种 md 不用动**。

| 检查项 | 测试方法 | 合格标准 | 优先级 |
