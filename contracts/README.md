# contracts 索引

> **合同规范**：所有 contracts 文件必须遵循 [`合同规范.md`](合同规范.md) 的统一五段格式 —
> **概述（What）→ 理论依据（Theory）→ 为什么这样做（Why）→ 怎么实现（How）→ 检查点（Checkpoints）**
>
> 每个合同都要求"有依据"：每个设计决策必须追溯到物理/数学/上游约束，不接受无依据的决策。

---

## 目录结构（人 / 狗 / 猫）

**原则：一种情绪 / 一种风格 = 一份独立正文 md；物种总文件只是索引，不含定稿正文。**

```text
contracts/
├── 02_情绪/
│   ├── 人/          ← 16 份独立情绪合同 + 人类情绪与能量曲线.md（仅索引）
│   ├── 猫/          ← 12 份独立 + 猫情绪与能量曲线.md（仅索引）
│   ├── 狗/          ← 10 份独立 + 狗情绪与能量曲线.md（仅索引）
│   └── …            ← 根目录 stub 重定向
├── 05_人格化/
│   ├── 人/          ← 9 份独立人格合同 + 索引
│   ├── 猫/          ← 4 份独立 + 索引
│   └── 狗/          ← 1 份独立 + 索引
```

每份独立 md 均含完整五段：**What → Theory → Why → How → Checkpoints**（含滑杆表、E(t) 指标、读感、混淆、验收脚本）。

**生成器**：`python3 tools/03_工具脚本/generate_species_contracts.py`  
从 `预设资产/` 同步数值；🧠 语义段落审定后请 **只改该 md**，勿在索引里堆正文。

## 怎么用

```text
改某一情绪（只动这一份）：
  ① contracts/02_情绪/{人|猫|狗}/{情绪名}.md
  ② 预设资产/预设情绪包/{species}/{情绪名}.json

改某一风格（只动这一份）：
  ① contracts/05_人格化/{人|猫|狗}/{id}.md
  ② 预设资产/风格包/{species}/{id}/style.json

索引文件（*_与能量曲线.md / *_风格偏向.md）仅用于跳转，不要在索引里写定稿正文。

**测试前验收（项目根目录）：**

```bash
python3 scripts/verify_diffusion_prompt_contract.py
python3 scripts/verify_dog_150_compile_contract.py
python3 scripts/export_prompt_samples.py   # → _runtime/prompt_samples/
# 定稿 Wan 前：人眼过 5秒气质精品成片合同 §5.2 P1
```

**门户测试入口：** `http://127.0.0.1:8765/portal`（双击 `一键打开能量工作台.sh`）
```
