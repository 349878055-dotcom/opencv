## 一、概述（What）

### 1.1 本文件管什么

[`affine_renderer.py`](gaze_engine/affine_renderer.py) 是**指令集 → 工程底膜**的驱动引擎。本文定义这个驱动引擎的**职责**、**核心机制**、**关键注意点**、**修改守则**。

### 1.2 管辖范围

✅ 12 通道数值 → 像素图像的翻译逻辑
✅ `EyeMesh` 三角形控制网格的变形算法
✅ 标准抛物线公式的驱动方式
✅ 已知问题和已验证的修复方案
✅ 代码修改守则

### 1.3 边界（非管辖）

❌ 不涉及工程底膜的格式协议（见 [`工程底膜合同.md`](工程底膜合同.md)）
❌ 不涉及 12 通道指令集的生成（见 [`全量帧指令集规范.md`](../01_总纲/全量帧指令集规范.md)）
❌ 不涉及艺术皮肤层（第二管道，待建）
❌ 不涉及扩散节拍表的生成

### 1.4 本环节的定义

[`affine_renderer.py`](gaze_engine/affine_renderer.py) 是整个管线的**最后一道几何工序**。它接收经过 [`human_prior`](gaze_engine/human_prior.py)（真人化）和 [`pulse_quality`](gaze_engine/pulse_quality.py)（平庸三检）修正后的 12 通道 × 150 帧指令集，将其**驱动**为像素级 RGB 三色分离图像序列。

> **概念区隔**：本模块属于**第一管道**（扩散引擎消费），操作称为"驱动"（Drive）或"生成"（Generate），与第二管道（客户预览）无关。

## 二、理论依据（Theory）

### 2.1 数值空间 → 像素空间的翻译必要性

管线上游（包络 → human_prior → pulse_quality）全部工作在**数值空间**（12 通道 float 序列）。扩散引擎的 conditioning 接口接受**像素空间**信号。

这一翻译需要满足三个约束：

| 约束 | 来源 | 本模块如何满足 |
|------|------|---------------|
| 几何精确 | 底膜必须精确反映指令意图 | 标准抛物线公式直接计算，无拟合误差 |
| 时间一致 | 帧间无跳变噪声 | LINE_8 硬边缘，像素值 ∈ {0, 255} |
| 解剖独立 | 三个系统独立编码 | RGB 三色分离，色彩通道隔离 |

### 2.2 抛物线公式的几何基础

底图 [`base_mesh_gen.py`](gaze_engine/base_mesh_gen.py) 使用抛物线公式生成眼睑环：

```
y_offset = peak × (1 − (2t−1)²)
```

其中 `t ∈ [0, 1]`，`t=0` = 左眼角，`t=1` = 右眼角。

**关键数学性质**：

```
t=0 → y_offset = peak × (1 − 1) = 0     → 眼角在水平线上
t=1 → y_offset = peak × (1 − 1) = 0     → 眼角在水平线上
t=0.5 → y_offset = peak × (1 − 0) = peak → 眼睑最高点
```

这一性质**不依赖于 peak 值** → 无论怎么变形，眼角始终闭合。

### 2.3 驱动原理：标准函数法

如果驱动引擎使用**与底图不同的公式**（如线性衰减），变形后的控制点将**不在抛物线上**。用这些不在抛物线上的点再去拟合抛物线，必然产生拟合误差。

**数学推导**：

```
底图：  y(t) = peak × (1 − (2t−1)²)          ← 抛物线
线性：  y(t) = peak × (1 − |2t−1| × 0.4)    ← 线性衰减（错误）
         ↓ 两者在 t=0 和 t=1 相等，但在中间点不同
         ↓ deform() 算出不在抛物线上的点
         ↓ 对这些点做抛物线拟合 → 永远有残差
         ↓ 残差的体现就是眼角跑偏
```

**正确做法**：驱动引擎使用**同一抛物线公式**，只改 peak 值：

```
驱动后：y(t) = (peak − Δ) × (1 − (2t−1)²)  ← 仍然是抛物线
              ↑ 只改峰值，不改形状
```

这称为**标准函数法**（Parametric Standard Function Approach）。

### 2.4 三角形网格作为顶点传递机制

`EyeMesh` 的 18 三角形拓扑仍然保留，但**用途已变**：

| 原来（错误） | 现在（正确） |
|-------------|-------------|
| 三角形网格 warp 产生像素位移 | 三角形网格仅作为顶点容器 |
| 用 warp 矩阵计算每个像素的新位置 | 用抛物线公式直接计算眼睑曲线 |
| 三角形边界 C1 不连续 → 毛刺 | 无三角形 warp，无毛刺 |

眉毛（3 个控制点，无抛物线问题）仍然通过 `deform()` 传递。

## 三、为什么这样做（Why）

### 3.1 关键决策一览

| 决策 | 备选方案 | 选择 | 理由 |
|------|---------|------|------|
| 眼睑变形方法 | 三角网格 warp / 5 点 polylines / 7 点拟合 / 标准函数法 | **标准函数法** | 唯一与底图几何同源的方案 |
| 眼睑绘制点数 | 5 点 / 7 点 / 40+1 点 | **40+1=41 点上眼睑，同数下眼睑** | 平衡平滑度与性能 |
| 眉毛驱动 | 抛物线拟合 / 折线 | **折线（3 点 deform）** | 眉毛无抛物线约束 |
| 抗锯齿 | LINE_AA / LINE_8 | **LINE_8** | 帧间稳定性 |
| 缩放策略 | 逐点缩放 / 最后统一 resize | **最后统一 resize** | 保持亚像素精度 |

### 3.2 关键决策详解

**决策 1：标准函数法 vs 其他方案（最重要的决策）**

经历了三次失败的迭代才找到正确方案：

| 方案 | 尝试时间 | 问题 | 弃用原因 |
|------|---------|------|---------|
| 18 三角网格 warp | 最早 | 三角形边界 C0 连续但 C1 不连续 | **毛刺** |
| 5 点 `polylines` | 第一次修复 | 5 点连直线 → 方块眼 | **不够平滑** |
| 7 点抛物线拟合（从 deform() 取点） | 第二次修复 | deform() 的线性衰减产生不在抛物线上的点 → 拟合残差 | **眼角跑偏** |
| 标准函数法（不走 deform()，直接用抛物线公式） | 当前 | 完美抛物线，天然闭合 | ✅ **正选** |

**结论**：不要从 `deform()` 取眼睑控制点。眼睑几何**直接走抛物线公式**。

**决策 2：眉毛走 deform() vs 走抛物线**

眉毛由额肌控制，运动模式是整体抬升/下压，没有"眼睑抛物线"这类曲线约束。3 点折线已经足够表达。因此眉毛继续走 `deform()`。

### 3.3 历史教训列表

| 时间 | 问题 | 根因 | 修复 | 形成规则 |
|------|------|------|------|---------|
| 最早 | 三角形 warp 毛刺 | 三角形边界导数不连续 | 弃用 warp | 💥 工程底膜禁止三角 warp |
| 中期 | 眼角跑偏 | deform() 线性衰减与抛物线不匹配 | 标准函数法 | 💥 驱动公式必须与底图同源 |
| 近期 | 帧间闪烁 | LINE_AA + micro_jitter 14Hz | LINE_8 | 💥 工程底膜禁止抗锯齿 |

### 3.4 踩坑的自动检测

为避免同一类问题重复出现，在代码中加入以下防护：

- `_AFFINE_DISABLED` 开关（当前 `False`）— 紧急情况可一键禁用以降级
- `_smooth_ring()` 内部的抛物线 `lstsq` 拟合 — 如果后续有人误改 deform() 为非线性，拟合残差会报警

## 四、怎么实现（How）

### 4.1 架构总览

[`affine_renderer.py`](gaze_engine/affine_renderer.py) 包含三个核心类/方法：

```
AffineRenderer (主驱动引擎)
  ├── EyeMesh (单眼三角形控制网格)
  │     ├── _build_source()      ← 底图抛物线控制点
  │     ├── _build_triangles()   ← 18 三角形拓扑（仅作为顶点容器）
  │     └── deform(channels)     ← 12 通道 → 顶点位移（眉毛走这里）
  │
  ├── render_frame(channels)     ← 单帧生成入口
  │     ├── _smooth_ring()       ← ⭐ 核心：标准抛物线公式生成 82 点眼睑环
  │     ├── polylines (R 通道)   ← 眼眶
  │     ├── polylines (G 通道)   ← 眉毛（走 deform()）
  │     └── circle (B 通道)      ← 虹膜 + 瞳孔
  │
  └── render_batch(json, out)    ← 批量 150 帧 → PNG → ffmpeg MP4
```

> 注：类名和方法名包含 `render` 是代码历史遗留命名。实际功能是**指令驱动几何生成**。

### 4.2 输入规格

| 项 | 说明 |
|----|------|
| channels dict | 12 个 float 键值对，范围 [0.0, 1.0]（部分通道可负） |
| 底图 | 从 [`gaze_engine/_shared/assets/eyelid_raw.png`](gaze_engine/_shared/assets/eyelid_raw.png) 加载 |
| 批量输入 | JSON 文件，`channels` 字段包含 12 个数组，每数组 150 个值 |

### 4.3 输出规格

| 项 | 值 |
|----|-----|
| 单帧 | `numpy.ndarray` shape (361, 690, 3), dtype uint8 |
| 批量 | PNG 序列 → ffmpeg H.264 MP4，CRF 18 |
| 色彩 | R=眼眶(0,0,255), G=眉(0,255,0), B=虹膜+瞳孔(255,0,0) |
| 线条 | `cv2.LINE_8` 硬边缘 |

### 4.4 核心算法：标准抛物线公式

```python
# 上眼睑：从左到右，steps=40
for i in range(steps + 1):
    t = i / steps
    x = cx - ew + 2 * ew * t
    y_offset = upper_peak * (1 - (2*t - 1)**2)
    y = cy - y_offset

# 下眼睑：从右到左，steps=40
for i in range(steps + 1):
    t = i / steps
    x = cx + ew - 2 * ew * t
    y_offset = lower_bot * (1 - (2*t - 1)**2)
    y = cy + y_offset

# peak 的变形公式
upper_peak = UPPER_PEAK - blink * BLINK_DROP - lid_upper * LID_UPPER_DROP
lower_bot = max(-2, LOWER_BOT - squint * SQUINT_LIFT - lid_lower * LID_LOWER_LIFT)
```

## 六、修改守则

1. **眼睑几何只改 `_smooth_ring()`，不碰 `deform()` 中的眼睑部分**
2. **保持抛物线公式结构不变** — 只改峰值常量（如 `BLINK_DROP`），不改 `1 − (2t−1)²` 形式
3. **新增通道必须同步更新**：
   - [`CANONICAL_KEYS`](gaze_engine/affine_renderer.py:44) 添加通道名
   - [`deform()`](gaze_engine/affine_renderer.py:159) 添加变形逻辑
   - 本文 §4.5 驱动表同步更新
4. **不混入艺术皮肤逻辑** — 任何渐变、Bloom、手绘质感属于第二管道
5. **测试覆盖**：每次修改必须验证 §5 中所有 P0 检查项通过
6. **修改前看合同规范** — 见 [`合同规范.md`](合同规范.md) §5 思维检查清单
