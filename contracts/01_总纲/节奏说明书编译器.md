## 二、理论依据（Theory）

### 2.1 为什么需要编译器（而非手写）

| 方式 | 问题 | 结论 |
|------|------|------|
| 手写节奏说明书 | 每段新视频都要手写 12 通道 × 150 帧的节拍点，不可能 | ❌ 行不通 |
| 编译自动生成 | JSON 数据 → 关键帧提取 → 文本模板填充 → 物种自适应 → 一次性输出 | ✅ 唯一方案 |

### 2.2 编译器的三个核心能力

```
能力 1：变帧检测
  从 150 帧的稠密数据中，找出"值发生变化"的关键帧作为节拍点。
  比如 pupil_x 在 150 帧里有 150 个值，但只在 17 帧和 23 帧附近变化超过阈值。
  编译器只需输出两个关键帧，而非 150 个。

能力 2：语义映射
  每个通道的数值变化要配一句自然语言说明。
  eyebrow: 0.7→0.1 → "耳位从竖立到耷拉"（狗）
  eyebrow: 0.4→0.8 → "眉压上升"（人）
  同一通道不同物种配不同语义。

能力 3：格式固化
  输出严格遵循节奏说明书的固定模板（6 段结构）。
  确保 Wan 每次读到的格式都完全一致。
```

## 三、为什么（Why）

### 3.1 解决的问题

| 问题 | 后果 | 编译器解决方案 |
|------|------|--------------|
| 指令集 150 帧太稠密 | Wan 无法逐帧消费 | 编译器自动降采样为关键帧 |
| 通道语义人类理解困难 | 客户/LLM 无法修改 | 编译器配上自然语言节拍说明 |
| 物种不同语义不同 | 需要多套代码 | 编译器读取 `DIFFUSION_HINTS` 自动适配 |
| 格式不一致 | Wan 解析困难 | 编译器输出固定 6 段模板 |

### 3.2 编译器的价值定位

```
指令集（机器）→ 编译器（翻译）→ 节奏说明书（人类/Wan 可读）

编译器是这个管线上唯一一个：
  输入是 JSON（机器）
  输出是 TXT（人类）
  的环节。
```

## 四、怎么做（How）

### 4.1 输入格式

输入为 `02_烘焙_真人律.json`，标准结构：

```json
{
  "schema": "slider-packet-v1",
  "emotion": "情绪名称",
  "species": "human | cat | dog",
  "energy_phases": ["蓄力", "启动", "保持", "缓和"],
  "channel_tracks": {
    "pupil_x": {
      "keyframes": [
        {"t": 0, "v": 0.0, "easing": "linear"},
        {"t": 17, "v": 0.34, "easing": "ease_out_expo"},
        ...
      ]
    },
    ...  // 其余 11 个通道
  }
}
```

**编译器只关心每个通道的 `keyframes` 数组。** 一个 `keyframes` 包含：
- `t`: 帧号 `[0, 149]`
- `v`: 通道值 `[0.0, 1.0]`
- `easing`: 缓动函数（仅供编译器参考，不进入输出）

### 4.2 输出格式

输出为 `05_扩散节拍表.txt`，严格 6 段固定模板：

```
# 扩散节拍表（12 通道 · 由 02 导出）
# 情绪: {情绪名}
# 来源: {源文件路径}
# 形态: {烘焙定稿 | 稀疏草稿}
# 用途: Wan/扩散引擎节奏主钟；远景也保留脉冲语义

## 全局阶段
{阶段1} → {阶段2} → {阶段3} → {阶段4}

## 各通道脉冲
- **{key}**（{中文名}）: t0=v0, t1=v1, t2=v2, ...
  → 节拍：{DIFFUSION_HINTS 中的物种自适应说明}
... // 共 12 个通道

## 时间轴汇合（变帧时刻）
t0, t1, t2, t3, ..., tN

## 给扩散的硬约束（摘要）
{3-5 条约束}
```

### 4.3 编译规则

#### 规则 1：关键帧提取

从每个通道的 `keyframes` 数组中提取所有 `t` 和 `v`：

```
输入 keyframes: [{"t":0,"v":0.0}, {"t":12,"v":0.0}, {"t":17,"v":0.34}, ...]
输出行: t0=0.0, t12=0.0, t17=0.34, ...
```

**仅提取 `keyframes` 内的变帧点**，不插值、不降采样、不平滑。

#### 规则 2：语义映射

每个通道的节拍说明从 [`channel_contract.py`](gaze_engine/_shared/channel_contract.py) 的 `DIFFUSION_HINTS` 字典读取：

```python
DIFFUSION_HINTS = {
    "pupil_x": "节拍：扫视方向；牵动注视与头部微转暗示",
    "eyebrow": "节拍：眉压 / 猫:耳位耷拉程度(竖耳=脉冲高值,飞机耳=低值)",
    "brow_raise": "节拍：挑眉 / 猫:耳尖微颤(受惊/好奇时高频小幅度)",
    ...
}
```

**物种自适应**：编译时检查输入 JSON 中是否有 `species` 字段：
- `species="dog"` → `DIFFUSION_HINTS` 中狗的说明优先
- `species="cat"` → `DIFFUSION_HINTS` 中猫的说明优先
- `species="human"` 或无 `species` → 使用默认说明

#### 规则 3：时间轴汇合

遍历所有 12 通道，收集所有出现过的 `t` 值，去重后排序：

```python
frames: set[int] = set()
for key in CANONICAL_KEYS:
    for kf in tracks[key]["keyframes"]:
        frames.add(int(kf["t"]))
sorted_frames = sorted(frames)
# 输出: 0, 12, 15, 17, 18, 20, 23, 25, 32, 55, 83, 85, 86, 90, 120, 149
```

#### 规则 4：全局阶段提取

从输入 JSON 的 `energy_phases` 字段读取，用 ` → ` 连接：

```python
phases = sparse.get("energy_phases", ["蓄力", "启动", "保持", "缓和"])
" → ".join(phases)
```

#### 规则 5：硬约束生成

在输出的末尾生成 3-5 条摘要约束：

```python
constraints = [
    "眉眼节奏严格跟随上表；眉压↑时口型克制、颧部微绷、额颈随节拍收紧；",
    "扫视过冲帧(约17–25)为全脸张力高峰；轻眨帧(约86)为全局微释放。",
    "远景镜头也需保持脉冲语义：pupil_x/y 仍控制注视方向，head 跟随。",
]
```

### 4.5 命令行接口

```bash

    --input 02_烘焙_真人律.json \
```

## 六、与现有代码的关系

### 6.1 与 `export_diffusion_metronome.py` 的关系

`rhythm_compiler.py` 是 `export_diffusion_metronome.py` 的**重构升级版**：

| 对比项 | `export_diffusion_metronome.py` | `rhythm_compiler.py` |
|-------|-------------------------------|---------------------|
| 核心函数 | `build_metronome_text()` | `build_metronome_text()`（同名兼容） |
| 物种自适应 | ❌ 不支持 | ✅ 支持 `species` 参数 |
| 输出模板 | 松散格式 | 严格 6 段模板 |
| 硬约束 | ❌ 无 | ✅ 自动生成摘要约束 |
| CLI 接口 | ✅ 有 | ✅ 有（更规范的参数） |

**向后兼容**：`rhythm_compiler.py.build_metronome_text()` 的签名与旧版一致，旧代码无需修改。
