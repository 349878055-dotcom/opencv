## 三、调度层的工作方式

```
用户输入: "猫咪警觉地盯着逗猫棒"
               │
               ▼
    nl_intent.py ─── 检测到 "猫咪" → species="cat"
               │
               ▼
    nl_to_packet.py ─── 路由到 cat/presets.py 的 cat_alarm_stare
               │
               ▼
    delivery_pipeline.py:
        if packet.species == "cat":
            pad = import cat/pad_weights.py
            env = _shared/envelope_compile.build(packet, pad)
            dense = _shared/micro_jitter.apply(env, "cat")
            dense = cat/prior.apply(dense)        ← 猫扫视
            dense = cat/pulse_quality.fix(dense)  ← 猫质检
            img = cat/affine_renderer.render(dense)  ← 猫底膜
```

## 四、实施步骤（按文件创建顺序）

### Step 0: 创建目录骨架
```bash
mkdir -p gaze_engine/{_shared,human,cat,dog}
touch gaze_engine/{_shared,human,cat,dog}/__init__.py
mkdir -p eye_asset/{cat, dog}
```

### Step 1: 从现有平铺文件，拆到 _shared/ 和 human/
- `_shared/`: 搬入通道、数据类、包络、微颤、IO 等共享模块 → **零改动**
- `human/`: 搬入人类预设、渲染、先验、质检、人格 → **保持现状**

### Step 2: 新建 cat/ 目录 7 个文件
```
presets.py → 12 个猫情绪预设
breeds.py  → 4 个品种配置
pad_weights.py → 猫 PAD 权重
affine_renderer.py → CatEyeMesh + 耳位渲染
prior.py → 猫扫视动力学 + 第三眼睑 + 耳位耦合
pulse_quality.py → 猫版质检规则
assets/eyelid_raw.png + ear_positions.json
```

### Step 3: 新建 dog/ 目录 7 个文件
```
同上，但狗参数
```

### Step 4: 改调度文件
- `channel_contract.py` → 加物种路由函数
- `slider_schema.py` → 加 species 字段 + EarParams
- `delivery_pipeline.py` → species 分支
- `nl_intent.py` → 物种识别
- `nl_to_packet.py` → 物种路由

## 五、这样设计的好处

| 维度 | 平铺结构（当前） | 物种目录结构（目标） |
|------|---------------|-------------------|
| 找文件 | 25 个文件翻找 | `cd cat/` 一目了然 |
| 新增物种 | 在同一个文件加 if species | 新建一个目录即可 |
| 修改风险 | 改人类代码可能影响宠物 | 各目录完全隔离 |
| 删除物种 | 要 grep 所有文件 | `rm -rf cat/` |
| 新人理解 | 一堆文件名 | 目录名说明一切 |
| 测试 | 混在一起 | `pytest cat/` 独立测试 |
| Git 历史 | 互相污染 | 人类和宠物提交分离 |
