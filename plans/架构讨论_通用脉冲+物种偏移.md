## 二、"偏移量"的物理意义

你说的"人格偏移量" 和 "性格偏置" —— 在代码里就是：

```python
final_channels[ch][t] = base_offset[ch] + emotion_pulse[t] × scale_factor[ch]
```

| 概念 | 对应系统 | 谁提供 |
|------|---------|--------|
| `emotion_pulse[t]` | 能量包络 E(t) | **通用**（_shared/envelope_compile） |
| `base_offset[ch]` | 人格/品种基线 | **物种专属**（human/persona_matrix / cat/breeds） |
| `scale_factor[ch]` | 人格/品种放大系数 | **物种专属**（同上） |
| `final_channels[ch][t]` | 最终 12/14 通道 | 编译结果 |

### 举例

**人类 · 天选者：**
```
base_offset["eyebrow"]  = 0.40   ← 天选者眉压本来就低
scale_factor["eyebrow"] = 0.90   ← 情绪变化时眉动幅度很大
```

**猫 · 布偶猫：**
```
base_offset["ear_left"]  = 0.35  ← 布偶猫耳朵本来就放松
scale_factor["ear_left"] = 0.50  ← 情绪变化时耳朵动幅中等
```

**猫 · 暹罗猫：**
```
base_offset["ear_left"]  = 0.65  ← 暹罗猫耳朵本来就竖
scale_factor["ear_left"] = 0.80  ← 情绪变化时耳朵动幅大
```

**同一个情绪脉冲** `E(t)` 灌进去，**不同的 base_offset + scale_factor** 出来完全不同的猫/狗/人表情。

## 三、当前代码结构是否符合这个逻辑

### 现在 `_shared/persona_compiler.py` 的核心函数：

```python
def compile_to_channels(emotion_pulse, persona_id, frame_count=150):
    persona = get_persona(persona_id)
    for key in CANONICAL_KEYS:
        base = persona.base_offset[key]          # ← 来自 persona_matrix.json
        scale = persona.scale_factor[key]         # ← 同上
        channel_series = clamp(base + pulse * scale)
        result[key] = channel_series
    return result
```

**这个函数本身就是通用的**——它不关心你是人是猫是狗。它只需要：
1. 一个 `emotion_pulse`（能量包络的输出）
2. 一个 `persona`（含 base_offset + scale_factor）
3. 一个 `CANONICAL_KEYS` 列表

**问题只在于**：当前 `persona_compiler.py` 硬编码了 `CANONICAL_KEYS` 为人类 12 通道。改成接收 `canonical_keys` 参数就通用了。

### 同样 `_shared/envelope_compile.py` 的核心函数：

```python
def _compute_pad_scale(key, P, A, D):
    Wp, Wa, Wd = _PAD_WEIGHTS.get(key, (0.0, 0.3, 0.2))  # ← 硬编码人类 PAD
    base = _BASE_SCALE.get(key, 0.30)                       # ← 硬编码人类 baselines
    return base + P*Wp + A*Wa + D*Wd
```

**问题**：`_PAD_WEIGHTS` 和 `_BASE_SCALE` 是硬编码的 Python dict。改成接收外部权重的参数就通用了。

## 四、所以我理解的你要的意思

```
现在的架构：
  _shared 里写着人类 12 通道的 PAD 权重、base_scale
  → 改成人/猫/狗各自提供 PAD 权重 + base_scale
  → _shared/envelope_compile 和 persona_compiler 变成纯引擎

改完后：
  _shared/envelope_compile.build( packet, pad_weights=cat/cat_pad_weights )
  _shared/persona_compiler.compile( pulse, persona, keys=cat/CANONICAL_KEYS_CAT )
```

### 具体改动一览

| 文件 | 改动 | 效果 |
|------|------|------|
| `_shared/envelope_compile.py` | `_PAD_WEIGHTS` 和 `_BASE_SCALE` 改为**函数参数** | 变成纯通用引擎 |
| `_shared/persona_compiler.py` | `CANONICAL_KEYS` 改为**函数参数** | 变成纯通用引擎 |
| `human/pad_weights.py` | **新增**：把现在硬编码在 envelope_compile 里的 PAD 权重移过来 | 人类提供自己的权重 |
| `cat/pad_weights.py` | 填充猫版 PAD 权重和 base_scale | 猫提供自己的 |
| `dog/pad_weights.py` | 填充狗版 PAD 权重和 base_scale | 狗提供自己的 |
| `_shared/persona_matrix.json` | 不动（保持人类 9 人格） | 还是人类的 |
| `cat/breeds.py` | 填充猫品种 offset 矩阵 | 猫品种人格 |
| `dog/breeds.py` | 填充狗品种 offset 矩阵 | 狗品种人格 |
| `delivery_pipeline.py` | species 分支路由时，注入物种专属的 PAD 权重和 persona 矩阵 | 调度层 |

### 最终数据流

```
NL → SliderPacket(species=cat, emotion=alarm, macro={...})
  → _shared/envelope_compile.build(packet, pad_weights=cat/weights)
      → 能量包络 E(t) + 14通道投影
  → _shared/persona_compiler.compile(pulse, persona=ragdoll, keys=cat_keys)
      → final[14][150]
  → cat/prior.apply(final)
  → cat/affine_renderer.render(final)
  → 猫底膜.png + 02_烘焙.json
```

### 人与猫/狗完全对称

```
人: SliderPacket(species=human) → _shared/envelope(human_weights) 
   → _shared/persona(天选者) → human/prior → human/affine_renderer

猫: SliderPacket(species=cat) → _shared/envelope(cat_weights) 
   → _shared/persona(布偶) → cat/prior → cat/affine_renderer
```

**区别只在 3 行参数配置，管线逻辑完全一样。**
